# Phase Console

[English](README.md) · **فارسی**

یک کنسولِ وبِ محلی برای «اجرای فازبندی‌شده»: مرور طرح‌ها، فازها و هندآف‌ها، دیدنِ وضعیتِ زنده، کپی‌کردنِ
بوت‌پرامپتِ هر فازِ آماده، و خواندنِ آمار در سراسر کتابخانه‌ی طرح‌ها.

## راه‌اندازی

<div dir="ltr">

```bash
cd viewer && npm ci && npm run build && cd ..   # once per machine, and after an update
./start                                         # from the skill directory — opens your browser
phase-console                                   # from anywhere: a plugin install or a hub copy
```

</div>

سرور، Node خالی است (نسخه‌ی ‎22.18+ یا ‎23.6+، که TypeScript را مستقیم اجرا می‌کند — آن‌جا چیزی برای ساختن
نیست). اما کلاینت **خروجیِ build است**: یک اپِ Vite/React که پوشه‌ی `client/dist` آن gitignore شده، پس
هر ماشین یک بار کپیِ خودش را می‌سازد (بستهٔ یک Release آن را از پیش ساخته‌شده
دارد). اگر build نکنید، کنسول باز هم جواب می‌دهد — با صفحه‌ای که همان دو
دستور و مسیرِ دقیقِ اجرایشان را نام می‌برد — و `npm start` هر وقت buildِ موجود از کد عقب‌تر باشد هشدار
می‌دهد. هیچ‌چیز هرگز به‌طورِ ضمنی build نمی‌شود: آنچه سرو می‌شود همیشه همان است که آخرین بار عامدانه
ساخته‌اید. بعد از ساخت، آفلاین هم کار می‌کند و روی Home Screen گوشی هم نصب می‌شود.

اولین صفحه می‌پرسد کدام پوشه را بخواند: هر مخزنی که <span dir="ltr">`docs/plans/`</span> داشته باشد. انتخاب‌های قبلی
را به یاد می‌سپارد و هر وقت خواستید می‌توانید از سوییچرِ بالای نوارِ کناری (**Open another source here**) یا از
Settings ▸ Essentials (**Change source**) عوضش کنید. برای ردشدن از این صفحه، پوشه را از همان اول نام ببرید:

<div dir="ltr">

```bash
./start ~/code/your-repo      # open this plan library straight away
./start --allow-writes        # also enable the guarded write verbs
./start --port 8080 --no-open # pin a port, don't open a browser
```

</div>

<div dir="rtl">

**هر کنسول به یک ریشهٔ مخزن تعلق دارد** و هویتش از همان مسیر ساخته می‌شود، پس یک پروژه همیشه همان
کنسول است. باقی ماجرا در [`shared/instances.mjs`](shared/instances.mjs) است: دفترچهٔ ثبت در
`~/.config/phase-console/instances.json` و زنجیرهٔ اولویت
`--port` ← `PHASE_CONSOLE_PORT` ← فایل `.phase-console.json` پروژه ← آخرین پورتی که واقعاً گرفته ← مشتق‌شده.



</div>

## زنده نگه‌داشتنش

کنسولی که در ترمینال اجرا می‌کنید تا وقتی همان ترمینال باز است زنده می‌ماند — بستنش، خروج از سیستم و
هر کرشی پروسه را تمام می‌کند، و Settings ▸ This instance ▸ **Shut down** راهِ عمدیِ همان کار است.

تلاش می‌کند اصلاً زمین نخورد. یک خطای مدیریت‌نشده، یک file watch که ارور می‌دهد، مرورگری که
وسطِ استریم ناپدید می‌شود — هرکدام به‌عنوان وضعیتِ **degraded** ثبت می‌شود و از `/api/state` سرو می‌شود،
به‌جای اینکه پروسه را بکُشد. خودِ file watch هر دقیقه خودش را بررسی می‌کند و اگر کر شده باشد دوباره ساخته
می‌شود — چون یک تابلوی یخ‌زده دقیقاً شبیهِ یک تابلوی سالم به نظر می‌رسد. هر خروجی، دلیلش را در
`~/.local/state/phase-console/console.log` می‌نویسد، و اجرایی که هیچ دلیلی ننوشته باشد، دفعه‌ی بعد که
کنسول بالا می‌آید به‌عنوان کرش گزارش می‌شود — یعنی «همین‌جوری قطع شد» سؤالی است که لاگ می‌تواند جوابش را
بدهد.

## خاموش کردنش

از Settings ▸ This instance ▸ **Shut down** کنسول و هر چیزی که در اختیار دارد خاموش می‌شود — یک خروجِ تمیز که می‌گوید
چه چیزی را با خودش می‌بَرد. وقتی هیچ ناظری روی پروسه نیست، همین خروج یعنی ایستادن.

</div>
<div dir="rtl">

دیالوگِ تأیید یک صورت‌برداری است، نه یک هشدار، و از خودِ کار محاسبه می‌شود: هر lane زنده، نزدیک‌ترین
ساعتی که خروج می‌شکند (یک ازسرگیری، تبدیلِ یک freeze، ساعتِ `require` یک سرورِ MCP) و شمارِ بقیه، اجراهای
روی دیسک که بوتِ بعدی برمی‌دارد، نشست‌های زنده‌ی Claude که دیگر زیرِ نظر نیستند، کارت‌های تأییدِ در انتظار،
رویدادهای حضور و اعلان‌هایی که هنوز خوانده نشده‌اند — و دستوری که دوباره همه را بالا می‌آورد. تأیید یعنی
پذیرفتنِ همین فهرست: <span dir="ltr">`POST /api/shutdown`</span> یک <span dir="ltr">`{"confirm":true}`</span>
خالی را روی فهرستی که خالی نیست رد می‌کند و آن را نام می‌برد، و «Stay off» همیشه
<span dir="ltr">`"acknowledge": true`</span> لازم دارد. Restart نیمه‌ی ترمینال‌ها را نشان می‌دهد — چون همیشه در
مسیرِ خروج همه‌ی ptyها را می‌کشته و هیچ‌وقت این را نمی‌گفته. Shut down عمداً پشتِ `--allow-run` نیست: تنها
کاری که هر کنسولی باید بتواند انجام دهد، ایستادن است.

<span dir="ltr">`GET /api/shutdown`</span> همان صورت‌برداری و برنامه‌ی هر شدت را پیش از هر فشاری سرو
می‌کند، هرکدام با یک واژه‌ی `durability` که دیالوگ آن را به تنها وعده‌اش بدل می‌کند — وقتی هیچ‌چیز بر
پروسه نظارت نمی‌کند این واژه `stays-off` است و دیالوگ کنارِ دستوری که کنسول را برمی‌گرداند می‌گوید
«Nothing brings it back». خودِ فشار اعلام می‌شود و کنسول منتظرِ آن اعلان می‌ماند: خاموشی تا
`SHUTDOWN_ANNOUNCE_WAIT_MS` (۵ ثانیه) برای یک گزارشِ تحویل صبر می‌کند، و رکوردی که هیچ‌چیز درباره‌اش
گزارش نداده با ردیفِ تحویلِ `skipped`ِ خودِ کنسول که دلیلش را می‌گوید بیرون می‌رود
(`shutdown.announced`)، تا صندوق هرگز خاموشی‌ای را نشان ندهد که بی‌صدا فرستاده نشده است.

## چه چیزهایی نشان می‌دهد

کنسول **هفت مقصد در سه دسته** است — کار (**Runs**، که خانه است، سپس **Plans** و **Sessions**)، سابقه
(**Repo**، **Insights** و **Logs**) و خودِ کنسول (**Settings**) — همان هفت تا در هر دو نسخه
(<span dir="ltr">`DESTINATIONS`</span>، <span dir="ltr">`shared/route-meta.js`</span>). کنارشان سرنشانی‌هایی هستند که ناوبری
فهرستشان نمی‌کند — **Your turn** (نوبتِ شما؛ <span dir="ltr">`#/turn`</span>، که Runs را روشن نگه می‌دارد؛ بخشِ *نوبتِ
شما*، پایین‌تر)، صفحه‌های خودِ یک فاز و یک هندآف زیرِ طرحشان، و یک انتخابگرِ مخزن بدونِ پوسته‌ی اپ — و سه پوشش که روی
query string سوار می‌شوند: پالت، زنگ و Help. هر نشانی‌ای که نسخه‌های قبلی ساخته‌اند هنوز کار می‌کند — یک بوکمارک،
لینکِ داخلِ یک هندآف، یا payloadِ یک push از سروری قدیمی‌تر، در یک گام به جایی می‌رسد که آن صفحه به آن منتقل شده و
آن نیمه از نشانی را که هنوز معنا دارد نگه می‌دارد (<span dir="ltr">`#/now`</span> ← <span dir="ltr">`#/runs`</span>،
<span dir="ltr">`#/now?focus=inbox`</span> ← <span dir="ltr">`#/runs?group=needs-you`</span>، <span dir="ltr">`#/ready`</span> ←
<span dir="ltr">`#/runs?group=ready`</span>، <span dir="ltr">`#/queue`</span> ← <span dir="ltr">`#/runs?group=queued`</span>،
<span dir="ltr">`#/approve?step=<id>`</span> ← <span dir="ltr">`#/turn/<id>`</span>، <span dir="ltr">`#/plan/x/route`</span> ←
<span dir="ltr">`#/plan/x/phases?view=map`</span>، <span dir="ltr">`#/plan/x/raw`</span> ←
<span dir="ltr">`#/plan/x/source?view=raw`</span>، <span dir="ltr">`#/terminal/abc`</span> ← <span dir="ltr">`#/sessions/abc`</span>،
<span dir="ltr">`#/debug/health?since=1`</span> ← <span dir="ltr">`#/logs/health?since=1`</span>). <span dir="ltr">`?bay=`</span>ِ
نسخه‌ی ۶.x هنوز به‌جای <span dir="ltr">`?group=`</span> خوانده می‌شود، و <span dir="ltr">`#/plan/<slug>/run`</span> همان نمای
**Run** طرح است.

| مقصد | به چه چیزی جواب می‌دهد |
|---|---|
| **Runs** | *آیا چیزی به من نیاز دارد؟* خانه، <span dir="ltr">`#/runs`</span> (<span dir="ltr">`DEFAULT_HEAD`</span>). عنوانش وضعیت است در یک جمله — <span dir="ltr">*2 need you, Your turn (1), checkout-rewrite is running — phase 3, 1 waiting, 4 phases ready, $41 today*</span>، و هر صفر حذف می‌شود — و بالای گروه‌ها کنسول فقط آنچه را می‌گذارد که در خودش خراب است (<span dir="ltr">*Claude Code is signed out*</span>، <span dir="ltr">*Nothing is driving this phase*</span>، مخزنی که کارهای GitHubاش شروع نمی‌شوند). بعد شش گروه، فوری‌ترین اول، هرکدام یک نشانی (<span dir="ltr">`?group=`</span>): **Your turn** (هر موردی که منتظرِ شماست، هرکدام یک خط با اولین گامش، که دقیقاً به همان شکلی فشار داده می‌شود که سرور نوشته — <span dir="ltr">`{endpoint, method, body}`</span>، پس یک نوعِ تازه روی کنسولی که کسی دوباره build نکرده هم کار می‌کند)، **Running** (در حالِ اجرا)، **Waiting** (منتظر)، **Queued** (در صف: هر اجرا منتظرِ چه کسی است، و فعل‌هایی که جابه‌جایش می‌کنند)، **Ready to start** (آماده‌ی شروع: فازهای آماده‌ی هر طرحِ باز، هرکدام با حداکثر دو دلیل و **Start**) و **Settled today** (امروز تمام‌شده)، تاشده. یک جدولِ قاعده گروهِ هر اجرا را تعیین می‌کند، پس صفحه و سرصفحه نمی‌توانند با هم اختلاف داشته باشند. هر اجرا یک خط است — وضعیتش به‌شکلِ یک نقطه و یک واژه، نامش، فازهایش به‌شکلِ یک مسیرِ کوتاه، یک ساعت، فازهای تمام‌شده (<span dir="ltr">`2/9`</span>) و آنچه تا حالا هزینه داشته — با دقیقاً یک کنش: راهِ پیشِ رویِ پیشنهادیِ کارتِ توقف، دکمه‌ی قدیمی‌ترین موردش، **Thaw**، **Pause**، **Hold** یا **Open run**. وقتی همان‌جا باز شود، کارتِ توقف، لِین‌ها و آخرین باری که از هرکدام خبر رسیده، **Phase N now** و هر فعلی را که اجرا می‌پذیرد نشان می‌دهد. **All runs** (<span dir="ltr">`?view=all`</span>) همه‌ی اجراها در یک جدول است؛ **Filter** نُه چراغ دارد که اجراهای متوقفِ هر خانواده‌ی توقف را می‌شمارند، و **⋯** **Freeze everything** و **Thaw everything** را دارد. آنچه به کسی بدهکار نیست — پاسخی از جدولِ سیاست، سلامتِ خودِ کنسول، یک قفل، یک ruling — در زنگ می‌ماند. |
| **Plans** | *هر طرح کجا ایستاده است؟* کتابخانه: هر طرحِ باز یک خط — وضعیتش، نامش، خطِ فازهایش، نشست‌های باقی‌مانده و آخرین باری که پیش رفته — به‌شکلِ **List** یا **Cards**، با طرح‌های بسته و اسناد در تاشوهایی که شمارششان را می‌دهند. **New plan** یک طرح را با AI می‌نویسد (<span dir="ltr">`--allow-agent`</span>)، از قالب داربست می‌کند (<span dir="ltr">`--allow-writes`</span>)، یا میزِ issueها را روی issueهایی باز می‌کند که طرح لازم دارند. یک طرح، <span dir="ltr">`#/plan/<slug>`</span>، روی نگاهِ اجمالی‌اش باز می‌شود — وضعیت، خط، آنچه مانده و آنچه هزینه دارد، و همان یک کاری که می‌خورد (**Start phase 1** تا وقتی اجرایی ندارد) — روی سه نما، هرکدام یک نشانی. **Phases** یک جدول از همه‌ی فازهاست، با گیت، قفل، رأیِ QA و شواهدِ هرکدام؛ <span dir="ltr">`?view=map`</span> طرح را به‌شکلِ یک مسیر می‌کشد (ایستگاه‌ها و ریل)، و <span dir="ltr">`qa`</span> و <span dir="ltr">`handoffs`</span> ستون‌های خودشان را جلو می‌آورند. **Details** یک فاز همان‌جا باز می‌شود — حرفِ رانر روی رکوردش، QAاش، ساعت‌هایش و *Why is this not done?* (چرا این تمام نشده؟) — و فاز صفحه‌ای از آنِ خودش دارد، <span dir="ltr">`#/plan/<slug>/phase/<n>`</span>، با کارتِ گیت و بازبینی‌اش. **Run** (<span dir="ltr">`#/plan/<slug>/run`</span>) اجرای همین طرح است: نگاهِ اجمالی‌اش — کارتِ توقف و همان یک حرکتِ پیشنهادی، لِین‌ها و ساعت‌هایشان — روی تاشوهایی: **Sessions and their consoles** (یک قاب برای هر لِین، <span dir="ltr">`?lane=p<N>`</span>، و فازهایی که هنوز منتظرند، <span dir="ltr">`?lane=waiting`</span>)، **Phases** با رکوردِ این اجرا از هر فاز (شواهد، زنده‌بودن، rulingها)، **Ways forward** (تنها رندرکننده‌ای که یک چاره دارد — جای دومی برای ظاهرشدنِ یک چاره وجود ندارد)، **Why it started and what it cost** (هر شروع و هر ردشدن از دفترِ اجرا، و هر نشست با اینکه چه کسی تمامش کرد، هزینه، نوبت‌ها، زمان و سقف‌هایش، تطبیق‌داده با خرجِ اجرا — و وقتی نمی‌خوانند قرمز می‌شود و شکاف را نام می‌برد)، **Where the time went** (خطِ زمانی، با یک نشانه برای هر نشست، پرسش، پاسخِ سیاست و شروع)، **What the ladder tried**، **Checkout** (کارتِ Git) و **Journal**؛ <span dir="ltr">`?view=history`</span> همه‌ی اجراهای قبلیِ طرح است. **Source** طرح است همان‌طور که نوشته شده — زمینه، بودجه‌ی نشست، مانیفستِ <span dir="ltr">`## Decisions`</span> همان‌طور که برقرار است و گرافِ فازها همان‌طور که موتور خوانده — یا بایت‌به‌بایت با <span dir="ltr">`?view=raw`</span>. |
| **Sessions** | *چه چیزی در حالِ اجراست، و می‌توانم سراغش بروم؟* یک فهرست برای لِین‌های autopilot، نشست‌های agent، شل‌ها و نشست‌های Claude که هوکِ حضور گزارش می‌کند، گروه‌بندی‌شده بر اساسِ نوع؛ **Locks**، کنارش در <span dir="ltr">`#/sessions/locks`</span>، هر ادعای فاز و نگه‌دارنده‌اش را نشان می‌دهد. یک نشست با تمامِ ارتفاع در <span dir="ltr">`#/sessions/<id>`</span> باز می‌شود — همان ترمینالِ مرورگرِ گوشی‌محور برای آن دو نوعی که این کنسول برایشان pty دارد، با یک نوارِ کلید و یک جعبه‌ی پیام روی گوشی — و نشستی که این کنسول فقط از آن خبر دارد صفحه‌ای باز می‌کند که گفت‌وگویش را می‌شود از آن‌جا ازسر گرفت. نشستِ agent به <span dir="ltr">`--allow-agent`</span> و شل به <span dir="ltr">`--allow-terminal`</span> نیاز دارد؛ بدونِ هیچ‌کدام، Sessions از نوارِ کناری می‌رود و لِین‌ها همچنان روی Runs دیده می‌شوند. حضوری که پروب پایانش را دیده <span dir="ltr">`ended · inferred`</span> خوانده می‌شود، نشستِ یک اجرا دری را که از آن آمده و اینکه چه کسی با چه هزینه‌ای تمامش کرد نشان می‌دهد، و نشست‌های پروبِ MCPِ خودِ کنسول هرگز فهرست نمی‌شوند. |
| **Repo** | *کار با درخت چه کرد — و با کدام درخت؟* شش بخش روی سطح‌های فقط‌خواندنیِ git و issueها، هرکدام یک نشانی (<span dir="ltr">`#/repo/<section>`</span>، و <span dir="ltr">`?repo=<key>`</span> که مخزن را نام می‌برد): **History** (<span dir="ltr">`#/repo`</span>: گرافِ کامیت‌ها، با شاخه‌های ران و لِین برچسب‌خورده)، **Branches** (واگرایی، اینکه چه چیزی هر شاخه را ادعا می‌کند، و کدام درخت‌های کاری نگهش داشته‌اند)، **Working trees** (کارِ موازی کجاست — و کدام درخت را دیگر هیچ رکوردِ زنده‌ای ادعا نمی‌کند: سطحِ بازپس‌گیری)، **Changes** (هر بازه، هر بار یک فایل)، **Settles** (کارِ هر ران چطور به تنه رسید، یا چرا نرسید) و **Issues** (میزِ issueها: فهرستِ **کاملِ** issueهای گیت‌هابِ هر مخزن — تا ۲٬۰۰۰، و فراتر از آن <span dir="ltr">`truncated`</span> گفته می‌شود — در یک جدول، با دسته، شدت و وضعیتِ طرحِ هر issue که از برچسب‌هایش و خط‌های <span dir="ltr">`Fixes:`</span> طرح‌های محلی به دست می‌آید، هر ستون قابلِ مرتب‌سازی، هفت فیلتر و ترتیب در نشانی، هر <span dir="ltr">`owner/name`</span> که با **Add a repository** افزوده شود با نشانِ «بیرون از این کنسول»، و انتخابی که **Author a plan from N issues** آن را به ویزاردِ طرح می‌سپارد — تازگیِ هر مخزن <span dir="ltr">`fresh`</span> · <span dir="ltr">`stale`</span> با سنش · <span dir="ltr">`unknown`</span> با دلیلش است، و کاوشی که نتواند پاسخ بگیرد آخرین سطرهای درست را نگه می‌دارد، نه اینکه فهرست را خالی کند). بالای همه، همان نگاهِ اجمالی‌ای که <span dir="ltr">`/api/state`</span> همیشه می‌داد: شاخه، شمارنده‌های ردگیری، و آنچه **زیرِ <span dir="ltr">`docs/`</span>** کامیت‌نشده مانده — تنها گوشه‌ای که آن خواندن پوشش می‌دهد (<span dir="ltr">`repoInfo`</span> دامنه‌ی <span dir="ltr">`git status`</span> را همان‌جا محدود می‌کند)، و به همین دلیل همین را می‌گوید. هر ردیف در پنل بررسی می‌شود و رکوردِ سرور را بی‌کم‌وکاست نشان می‌دهد. |
| **Insights** | *چقدر مانده، چقدر خرج برداشته، با چه سرعتی، و روی چه؟* یازده پرسش، هرکدام یک بار جواب‌داده‌شده، از بالا به پایین: **How long is left** (چقدر مانده: برآورد با مبنایی که زیرش ایستاده — <span dir="ltr">`plan`</span>، <span dir="ltr">`portfolio`</span> یا <span dir="ltr">`heuristic`</span>؛ یک «تقریباً ۳ روز» سه معنای متفاوت دارد)، **What it costs** (خرجِ تسویه‌شده در برابرِ سقفِ روزانه، و هر اجرا در برابرِ بودجه‌اش)، **What each session cost** (به‌ازای هر طرح و هر حساب)، **What this plan cost** و **This plan's record** (روی صفحه‌ای که به یک طرح محدود شده: پولِ هر فاز و تاریخِ پایان؛ رأی‌های QA و گزارش‌هایشان)، **What a session may spend** (سقف‌هایی که از نشست‌های خودِ این کنسول سنجیده شده‌اند، کنارِ سقف‌های پیش‌فرض، <span dir="ltr">`GET /api/sizing`</span>)، **How fast** (روندِ سرعت)، **This week** (گزارشِ هفته، <span dir="ltr">`GET /api/report`</span>)، **Who was asked** (کارت‌هایی که برای یک آدم بالا آمد، آنچه auto-grant پاسخ داد، آنچه همین حالا منتظر است)، **What shape the work is in** (حالت‌ها، اندازه‌ها، قفل‌ها، سلامت، طرح‌های متوقف) و **On what** (مخازن، اسکیل‌ها و مدل‌هایی که کار رویشان می‌رود). کلِ سبد، یا یک طرح با <span dir="ltr">`?plan=`</span>. |
| **Logs** | *کنسول چه دیده است؟* تا ۷.۰ نامش Debug بود؛ هر نشانیِ <span dir="ltr">`#/debug…`</span> با queryاش روی بخشِ خودش می‌نشیند. پنج بخش، هرکدام یک نشانی (<span dir="ltr">`#/logs/<section>`</span>، <span dir="ltr">`screens/logs/`</span>): **Logs** (<span dir="ltr">`#/logs`</span>) — هر لاگی که این کنسول می‌نویسد، روی یک محورِ زمانی: journalهای اجرا، تصمیم‌های زمان‌بندِ watch، رکوردِ سلامت و هر فراخوانِ ابزارِ ردشده، با فیلترِ منبع، سطح، زمان، طرح، اجرا، فاز و trace در نشانی، که این‌جا خوانده می‌شود و نه فقط در یک ترمینال، با یک tailِ زنده (*Follow*) و کارتِ سطحِ لاگ (سطح، کانال‌های debug و اینکه تغییر تا کی می‌ماند؛ *Revert now* زودتر تمامش می‌کند)؛ **Journal** (یک اجرا همان‌طور که رخ داد، روی همان Ganttِ نمای اجرا، و اینکه چرا یک فاز تمام نشده)؛ **Delivery** (سرنوشتِ هر اعلان روی هر دستگاه)؛ **Health** (runtime، doctor با یک فشار، همین پروسه، credentialهای بازنشسته، شروع‌های خودکارِ این ساعت در برابرِ سقفِ شروع — <span dir="ltr">`GET /api/ceiling`</span> — کنسول‌های سرگردانی که کدشان رفته — <span dir="ltr">`GET /api/doctor/strays`</span> — متریک‌ها، و bundle)؛ **Access** (این کنسول به چه کسانی سرویس داده). bundle همان <span dir="ltr">`GET /api/debug/bundle`</span> است: یک عکسِ فوریِ JSONِ ویرایش‌شده به اندازه‌ی یک پنجره‌ی زمینه، پس تشخیصِ یک اجرا یعنی تحویلِ یک bundle، نه توصیفِ یک صفحه. |
| **Settings** | *این کنسول چه اجازه‌ای دارد، و به نامِ چه کسی؟* نُه بخش با نشانیِ خودشان <span dir="ltr">`#/settings/<section>`</span>، از ساده به پیشرفته: **Essentials** (منبع و **Change source**، اجازه‌هایی که کنسول دارد، دستورِ شروع، موتور، کلیدها)، **Appearance** (تم، تراکم، کلیدهای ترمینال، ترتیبِ کتابخانه‌ی طرح‌ها)، **Automation** (پیش‌فرض‌های راه‌اندازی — خودِ فرمِ راه‌اندازی، همان‌جا — checkoutها، سه کنترلِ بررسی — اینکه اثباتِ داوری نشستِ بررسی بگیرد یا نه، آن نشست با چه چیزی اجرا شود و پس از چند ردشدن مورد به مالک برسد — نردبان و سقف‌هایش، آستانه‌های توقف، **The start ceiling**، **Policy answers** با **Relay rules**اش، زمان‌بندیِ سوارشدن، صف، **Session presence**، و **Asking less**، خلاصه‌ی «کمتر پرسیدن»)، **Notifications** (هر نوع اعلان و اینکه دقیقاً به کجا می‌رسد — کنسول، این دستگاه، هر کانال — به‌همراه ساعاتِ سکوتِ هر دستگاه)، **Accounts** (هر حساب یک خط که همان‌جا باز می‌شود، و آنچه این ماشین در اختیار دارد: هر credentialی که یک طرح نام می‌برد، موجود یا نه، <span dir="ltr">`GET /api/credentials`</span>)، **MCP servers** (رجیستری و کاتالوگ)، **Permissions** (**Grants** و **Owner keys**، سپس ویرایشگرِ قاعده‌ها)، **This instance** (چه چیزی این صفحه را سرو می‌کند، ری‌استارت، چگونه در دسترس است، **Logs and retention**، پروفایلِ ماشین، خاموش‌کردن، و بنرِ کنسولی که خودکارسازی‌اش نگه داشته شده) و **Everything** — هر کلیدی که <span dir="ltr">`GET /api/prefs/schema`</span> توصیف می‌کند، با مقدارش، پیش‌فرضش، اینکه مقدار از کجا آمده، یک کنترل هر جا که صفحه اجازه‌ی نوشتنش را دارد، و **Reset** (کلیدی که به‌صورتِ <span dir="ltr">`null`</span> فرستاده شود به پیش‌فرضِ خودش برمی‌گردد). **Find a setting**، بالای هر صفحه‌ی Settings، هم با بخش‌ها جواب می‌دهد هم با تنظیم‌های تک‌تک، پس <span dir="ltr">`quiet hours`</span> کلید را پیدا می‌کند. شناسه‌های پیش از ۴٫۰ یعنی <span dir="ltr">`general`</span>، <span dir="ltr">`alerts`</span> و <span dir="ltr">`process`</span> هنوز ری‌دایرکت می‌شوند. |

**سه در روی هر صفحه.** هر مقصد ستونی از ردیف‌های تک‌خطی است، و هر ردیف همان سه در را به آنچه کنار می‌گذارد باز
می‌کند — هیچ‌چیزی از آنچه کنسول می‌داند کنار گذاشته نمی‌شود، و هر داده‌ای حداکثر دو فشار فاصله دارد. **Expand**
(باز کردن) یک ردیف را همان‌جا که ایستاده باز می‌کند (**Show details**، یا **Everything about** طرح روی خطِ یک اجرا)،
و صفحه آنچه را باز گذاشته‌اید به یاد می‌سپارد. **Inspect** (بررسی) رکورد را در پنل می‌گذارد، روی چهار تب:
**Overview**، **Actions** (هر فعلی که روی آن کاربرد دارد — فعلی که این کنسول کلیدش را ندارد می‌گوید کدام کلید)،
**History** و **Raw**. **Everything**، آخرین جای نوارِ ابزار، کلیدی است که هر صفحه در این مرورگر نگهش می‌دارد:
روشن که باشد، صفحه به‌جای موارد ضروری هر ستون، هر داده و هر بخشِ تاشده را نشان می‌دهد. نوارِ ابزار در هر صفحه‌ای
که چیزی را فهرست می‌کند یک ردیف است با یک ترتیب — جست‌وجو، **Filter**، **Group**، **Sort**، **View**، **⋯** و
**Everything**، و هر صفحه فقط جاهایی را می‌کشد که دارد — و روی گوشی جست‌وجو می‌ماند و بقیه در یک کشوییِ **View**
جمع می‌شوند.

مسیر، رویداد، تنظیم و فعلِ اپراتوریِ سرور را با دری که یک آدم از آن به آن می‌رسد نام می‌برد
(<span dir="ltr">`viewer/test/surface-parity.test.ts`</span> آن را در هر دو جهت با سرور هم‌خوان نگه می‌دارد). کنارشان
<span dir="ltr">`styles/`</span>، <span dir="ltr">`lib/`</span> و <span dir="ltr">`content/guide/`</span> هستند. قانونِ
طراحی <span dir="ltr">`viewer/docs/design.md`</span> است، و نخستین رنگ‌آمیزی (first paint) به ۱۷۰ کیلوبایتِ سروشده
محدود است (<span dir="ltr">`check-dist`</span>؛ تا پیش از ۷.۰، ۱۹۰ کیلوبایت).

صفحه خودش را به‌روز می‌کند: یک watch روی <span dir="ltr">`docs/`</span> تغییرات را با server-sent events می‌فرستد، پس
هندآفی که یک نشستِ ایجنت می‌نویسد بدون رفرش ظاهر می‌شود. ضمناً یک PWAی قابل‌نصب است: پوسته‌ی اپ — chunkِ هر مقصد —
precache می‌شود تا فوری باز شود (و آفلاین همین را صریح می‌گوید، به‌جای نشان‌دادنِ تابلویی کهنه — داده‌ی زنده هرگز
کش نمی‌شود). buildِ تازه جایی گرفته می‌شود که چیزی از دست نرود — هنگامِ بارگذاریِ صفحه و وقتی به تب برمی‌گردید،
هرگز روی یک نشستِ زنده، یک ترمینال یا نمای یک اجرا، و هرگز وقتی تایپ می‌کنید — و هر جای دیگر به‌شکلِ یک
toastِ به‌روزرسانی پیشنهاد می‌شود؛ وقتی سرور روی buildی تازه ری‌استارت می‌شود، تبِ باز همان لحظه آن را می‌خواهد
(<span dir="ltr">`lib/pwa.ts`</span>).

**هر ساعت می‌گوید چه چیزی را اندازه می‌گیرد** (#28). یک فاز پنج مهرِ زمانی دارد، و صفحه‌ای که هر جفتی را
که خودش می‌خواست از هم کم می‌کرد با صفحه‌ی کناری‌اش ۴۷ ثانیه روی یک فازِ تمام‌شده و ۱۱٫۷ دقیقه روی یک فازِ
در حالِ اجرا اختلاف داشت. حالا payloadهای اجرا و `run:progress` فیلدِ `phaseClocks` را حمل می‌کنند —
`sinceFirstBoardedMs` (خودِ فاز، که جزئیاتش نشان می‌دهد)، `sinceThisAttemptMs` (تلاشِ جاری، که ردیف چاپش
می‌کند)، `workedMs`، `queuedMs`، `attemptWindows[]` و `timeToFirstToolMs` — از `shared/phase-clocks.js`،
و `durationMs` همان `workedMs` است: مجموعِ پنجره‌های تلاش، منهای زمانی که فاز منجمد بوده. `startedAt`ِ یک
پلن نخستین سوارشدنِ اجراهایش است، تا ثانیه، کنارِ تاریخِ نگارشِ `created`، و `spanMs` از همان حساب
می‌شود. هر بازه‌ی زمانی را یک قالب‌بندِ واحد، `shared/interval-format.js`، در سه رجیستر می‌نویسد — `clock`
(`1:59`)، `prose` (`1m 59s`)، `table` (`1m 59s`) — با یک قاعده‌ی گرد کردن: رو به پایین. و یک لاینِ ساکت
سکوتش را نام می‌برد: `silence.kind` یکی از `no-output`، `unproductive` (صدایش می‌آید ولی چیزی تولید
نمی‌کند)، `in-tool`، `own-job` یا `external-wait` است، با `sinceMs` (لحظه‌ی آغازش) و آستانه‌ای که
آشکارساز آن را با آن می‌سنجد.

**هر قفل با یک خواندن در دسترس است** (#24). `GET /api/locks` همه‌ی ادعاهایی را که این کنسول می‌بیند،
بدترین اول، فهرست می‌کند — ادعای منقضی‌شده‌ای که هنوز روی دیسک است، بعد ادعای زنده‌ای که چیزی را معطل
کرده، بعد ادعای زنده‌ای که چیزی را معطل نکرده — با مالک و میزبان، زمانِ ادعا و پایانِ مهلتش، scope،
نشست و حضورِ آن نشست، شاخه و درختِ کاری‌ای که فایلِ قفل نام می‌برد، `lapsed` (با `lockLapsed` سنجیده
می‌شود، که می‌داند نشستِ پایان‌یافته پیش از تمام‌شدنِ مهلت ادعا را منقضی می‌کند)، `holderKind` (`autopilot`
یا `person`)، فازهای صف‌کشیده‌ای که `blocking` است و `eta`ِ پلنِ نگه‌دارنده. `?held=1`، `?lapsed=1` و
`?scope=<repo>` آن را محدود می‌کنند. Sessions ▸ **Locks** (`#/sessions/locks`) ردیف‌ها را نشان می‌دهد،
هر کدام با همان فعلِ Release که بقیه‌ی صفحه‌ها دارند.



## اتوپایلوت

سوییچِ `--allow-run` به کنسول اجازه می‌دهد نشستِ ایجنت بسازد. عمداً از `--allow-writes` جداست: یک
«نوشتن» فقط اسکلتِ یک فایل را می‌سازد، اما یک «اجرا» ساعت‌ها مخزن شما را ویرایش می‌کند. سوییچِ `--no-converge` گذرهای خودکارِ حلقه‌ی همگرایی
(بوت، تغییرِ داکس، جاروبِ دوره‌ای، دقیقه‌ی پس از هر توقف) را خاموش نگه می‌دارد و Recover & continue را
همچنان کارا می‌گذارد — *حلقه‌ی همگرایی* را پایین‌تر ببینید.

هر فاز یک پروسه‌ی `claude -p` است، پس «کانتکست را بین فازها پاک کن» اصلاً نیاز به پیاده‌سازی ندارد —
پروسه تمام می‌شود و کانتکستش را با خودش می‌برد. یک فاز فقط وقتی جلو می‌رود که **سه بررسیِ مستقل با هم
موافق باشند**: دستورهای راستی‌آزماییِ خودِ طرح پاس شوند، `validate.sh` همچنان پاس باشد، و تابلو که
**دوباره از روی دیسک** خوانده شده بگوید فاز انجام شده. هیچ‌کس از خودِ نشست نمی‌پرسد که آیا موفق بوده یا نه.

**پیش از نخستین اسپاون، پیش‌درآمد (از ۵.۰.۰).** یک اجرا نمی‌تواند با یک تصمیمِ باز شروع شود: درِ شروع
ردیف‌های `## Decisions` طرح را می‌خواند و پنج کاوش انجام می‌دهد — ورود و ظرفیتِ حساب‌های اعلام‌شده،
سرورهای MCP طرح، اعتبارنامه‌هایی که نام برده (`gh`، ورودِ `claude`، شناسه‌های `env:`، `keychain:` و
`file:` — فقط حضور، هرگز مقدار)، اینکه آیا چیزی می‌تواند اعلانی برساند، و (از ۲۰۲۶-۰۹-۱۸) هر فرمانِ
§Verification که اجرا به‌خاطرش برای یک انسان می‌ایستد: فازی که زیرِ `Person-check: halt` پارک می‌شود یا
زیرِ `halt-on-everything` همیشه می‌پرسد — و با **409** پاسخ می‌دهد و هر ردیفِ مسدودکننده یا کاوشِ ناموفق را
نام می‌برد. ردیفِ **Decisions** در صفحه‌ی راه‌اندازی (یکی از نُه ردیفِ آن)، که تا وقتی یک ردیفِ مسدودکننده
باز است کهربایی می‌شود و دکمه‌ی شروع را نگه می‌دارد، همین گزارش را نشان می‌دهد، سه پاسخی را می‌پرسد که
هر اجرا باید بدهد (ازسرگیری پس از ری‌استارت، رله، حساب‌ها)، و هر چنین فرمانِ راستی‌آزمایی را فهرست می‌کند تا
**تأیید** شود — گره‌خورده به متنِ دقیقش، با همه‌ی بررسی‌های دیگر، و فقط جایی که تأیید می‌تواند اجرایش کند —
یا **برای همین اجرا کنار گذاشته شود**؛ یک
نادیده‌گیریِ ثبت‌شده به‌هرحال شروع می‌کند و در ژورنال می‌نویسد چه کسی چه چیزی را نادیده گرفت. در میانه‌ی
اجرا، مداخله‌ای که جدولِ سیاست می‌تواند پاسخ دهد — پایانِ دورهای QA با
`qa.exhausted: waive`، ری‌استارتِ کنسول با `resumeOnRestart` — پاسخ داده و به‌صورت `phase.policy-answered`
در ژورنال ثبت می‌شود، نه اینکه کارتی بالا بیاید؛ `blocked-declared:unknown` همیشه کارت است.
`phase-console doctor [instance]` همان کاوش‌ها را با دست اجرا می‌کند، به‌علاوه‌ی هوک‌ها، نسخه‌ی CLI در
برابر کفِ رله، `gh auth status`، دکترِ محیط و سلامتِ خودِ کنسول، و با کد ۱ خارج می‌شود و نخستین ردیفِ
ناموفق را نام می‌برد. پیش‌درآمد مالِ اجراست؛ هر فاز هنگامِ سوارشدن دوباره می‌پرسد. اعتبارنامه‌هایی که فاز
نام برده دوباره کاوش می‌شوند (`phase.credential-preflight`): زیرِ `**Credential policy:** require` نبودنِ
یکی فاز را با یک خواسته پارک می‌کند (`blocked-declared:credential`)، و زیرِ `continue` — پیش‌فرض، پس از
ردیفِ `credentials` جدولِ سیاست — فاز سوار می‌شود و این کمبود روی رکوردش می‌ماند.

**هر شروعِ خودکار خودش را نام می‌برد.** شروعی که کسی دکمه‌اش را نزده در یکی از `START_DOORS` تصمیم
گرفته می‌شود — `boot-readopt`، `wait-clock`، `converge-relaunch`، `converge-heal`، `watch-landed`،
`outcome-inbox`، `auto-reviewer` و بقیه — و فشارِ یک آدم درِ `operator` است. هر شروع و هر ردشدن در دفترِ
اجرا نوشته می‌شود (`GET /api/run/:slug/ledger`) و تاشوی **Why it started and what it cost** در نمای اجرا آن را
برای هر شروع با یک جمله بازمی‌خواند. درهای خودکار در هر کنسول یک سقفِ مشترک روی یک ساعتِ لغزان دارند —
`ceilingStartsPerHour` برابرِ ۴۰ و `ceilingUsdPerHour` برابرِ ۲۵۰ دلار (Settings ▸ Automation ▸ **The start ceiling**؛
صفر هرکدام را خاموش می‌کند؛ Logs ▸ Health شمارنده‌های زنده را می‌کشد، <span dir="ltr">`GET /api/ceiling`</span>) — که
پس از آن شروع رد می‌شود (`run.start-refused`) و در هر پنجره
یک اعلانِ سلامتِ *Start ceiling reached* فرستاده می‌شود. فشارِ یک آدم هرگز شمرده و هرگز رد نمی‌شود.

**پروتکل خروجی (outcome).** نشست می‌تواند به‌جای اینکه رانر از یک خروجِ تمیز حدس بزند، اعلام کند چطور
تمام شده: `scripts/phase-outcome.sh <slug> <N> <status>` یک فایل JSONِ اتمی به مسیری می‌نویسد که
رانر به‌صورت `PE_OUTCOME_FILE` تزریق می‌کند، و رانر هنگام خروج آن را می‌خواند، در ژورنال ثبت می‌کند و
مصرف می‌کند. پنج وضعیت: `complete` (فقط اعلامی؛ تصمیم با تابلوست)، `waiting-external` (کار به یک
ساعتِ بیرونی نیاز دارد: بیلد CI، ادغام خودکار PR، پنجره‌ی دیپلوی)، `blocked` (با رفرنسِ
`lock:<slug>/<N>` روی قفلِ کسِ دیگری دوباره در صف می‌رود — رفرنسی که قفلِ خودِ همان فاز را نام ببرد
رد می‌شود، و مانعی که تنها قفلش قفلِ خودش بوده برای یک آدم پارک می‌شود؛ در غیر این صورت «بیانیه‌ی مانع» تصمیم می‌گیرد — نردبان را
پایین‌تر ببینید)، `needs-human` (اجرا را برای یک آدم پارک می‌کند، با ثبتِ خواسته، و شکست حساب
نمی‌شود) و `partial` («کار مانده، من را ادامه بده»: نشست ناچار شد متوقف شود — بودجه، کانتکست — بی‌آنکه
چیزی خراب باشد؛ رانر آن را کارِ در جریان می‌خواند و همان نشست را ادامه می‌دهد، به‌جای سیخونکِ
بستنی که حق ندارد کار را انجام دهد). هر پرامپتی که رانر می‌فرستد
قراردادِ نشستِ بی‌سرنشین را با خود دارد — از جمله این واقعیت که `ScheduleWakeup` و `Monitor` و
واچرهای پس‌زمینه بعد از پایانِ نوبت در `-p` زنده نمی‌مانند. یک **هوک Stop** هم همین را تحمیل می‌کند:
نشستی که می‌خواهد بدون هندآف روی تابلو و بدون خروجیِ اعلام‌شده تمام کند، دقیقاً می‌شنود به‌جایش چه
کند (حداکثر دو بار در هر نشست؛ در نبودِ کنسول باز است — لایه‌ی اصلی همان بررسیِ خودِ رانر است).

**انتظار برای کار بیرونی.** خروجیِ `waiting-external` فاز را به حالت `waiting` پارک می‌کند — نه شکست
است و نه بسته: لِین و گرانت و قفلش آزاد می‌شوند تا فازهای دیگر بدوند، و در `parkedUntil` رانر **همان
نشستِ خودِ فاز را** ادامه می‌دهد (`claude -p --resume`، با کانتکستِ دست‌نخورده) تا راستی‌آزمایی و
بستن را تمام کند یا انتظارِ تازه‌ای اعلام کند — مگر آن نشست دیگر ارزشِ ادامه نداشته باشد (بندِ
*کانتکست* در پایین)، که آن‌وقت فاز تازه با بریفِ resume و انتظار در آن سوار می‌شود. وقتی هر فازِ قابل‌شروع پارک باشد، خودِ اجرا با
نزدیک‌ترین ساعت می‌خوابد (`waitUntil`) — در برابر ری‌استارت امن است و بوتِ کنسول دوباره آن را کوک
می‌کند. بودجه‌ی انتظار آن را صادق نگه می‌دارد: حداکثر ۴ انتظارِ اعلام‌شده و، به‌طورِ پیش‌فرض، ۸ ساعت پارک
برای هر فاز (`**Wait budget:**` یا بولتِ `- **Waits on:** <ref> · <max>` یک فاز آن را بالا می‌برد). از باقیِ
بودجه که بگذرد، انتظاری که refی قابلِ پایش برای کنسول نام ببرد همان باقی‌مانده را می‌گیرد و از آن پس فقط
منتظرِ همان ref می‌ماند؛ انتظاری که هیچ refی نام نبرد روی بودجه‌ی تمام‌شده پارک می‌شود — `waiting`، بی‌ساعتِ
خودش، با یک errand زیرِ کلیدِ `budgets` که حسابش را می‌گوید — و این هرگز شکست نیست و به `failure-streak`
چیزی نمی‌افزاید (فازِ ۴۵ از control-tower). بودجه هنگامِ ادامه دوباره خوانده می‌شود، پس ساعتی که وقتی هیچ‌چیز اجرا نمی‌شد گذشته، به‌جای
شلیک‌شدن، داوری می‌شود (`run.wait-overdue`: دیرکرد در ژورنال، بررسیِ refها، و ردِ ادامه‌ی نشستی که هنوز
اجرا می‌شود). پارکِ خودکارِ نگهبان سهمیه‌ی خودش را خرج می‌کند، هرگز سهمیه‌ی نشست را.
از ۶.۱ (فازِ ۱۲۱ از control-tower) طرح شمارِ انتظارها را هم بالا می‌برد — `**Wait count:** <n>` در
§Session budget یا `- **Wait count:** <n>` روی یک فاز، ۱ تا ۹۹ — و شمار یا بودجه‌ی تمام‌شده‌ای که refِ
watchش هنوز پرسیده می‌شود انتظاری روی همان ref است، نه یک errand: اجرا روی آن `waiting` می‌شود و هر شش ساعت
دوباره به آن سر زده می‌شود. فقط یک `date:` تنها، یا refهایی که ساعتِ watch برای همیشه ردشان کرده، errandِ
`budgets` را به جا می‌گذارند. یک `date:` کنارِ یک refِ زنده پشتوانه‌ی (backstop) آن ref است: اگر زودتر بگذرد، فاز
را ازسر می‌گیرد در حالی که به آن گفته شده ref به نتیجه نرسیده (`phase.waiting` فیلدِ `backstop` را دارد). و
`unit:<host>/<unit>` منتظرِ یک یونیتِ systemd روی ماشینی دیگر می‌ماند (`server/watch-unit.ts`) — یک اتصالِ
ssh مشترک برای هر میزبان، هر ۵ دقیقه یک بار پرسیده می‌شود، نشانی، کاربر، کلید و پورتِ میزبان از
`hosts.<name>` در `~/.config/phase-console/fleet.json` خوانده می‌شود، و هیچ‌کدامشان در رکوردِ اجرا نوشته
نمی‌شود.

**حکم‌ها (rulings) — نشست چه تصمیمی گرفت.** شکلِ دومِ همان اسکریپت،
`phase-outcome.sh <slug> <N> ruling --what … [--why …] [--kind ambiguity|deviation|deferral]
[--cost-if-wrong …]`، یک خطِ NDJSON به `$PE_RULINGS_FILE` اضافه می‌کند (بدون سرپرست:
`runs/<instance>/<slug>/rulings.ndjson`). حکم یک outcome نیست و **هیچ‌چیز روی آن عمل نمی‌کند** — فاز
را پارک نمی‌کند، از نردبان بالا نمی‌رود و نوبت را تمام نمی‌کند — و دقیقاً همین است که ثبتِ هر
داوریِ شخصی را که پلن برایت تصمیم نگرفته بی‌خطر می‌کند. کنسول این دفتر را در اجرا جذب می‌کند
(`run.rulings`، ژورنالِ `phase.ruling`)، در `GET /api/run/:slug/rulings` سرو می‌کند، حکم‌های همان فاز را
روی تشخیصِ فاز می‌گذارد و برای هر حکمِ تازه یک ردیفِ `fyi` در صندوق می‌سازد؛ «دیدم» هم یک خطِ تازه
اضافه می‌کند، نه ویرایشِ فایلی که ممکن است نشستی زنده هنوز در آن بنویسد. از ۵.۰.۰ هر خط با
شناسه‌اش مُهر می‌خورد و، با `--needs <key>`، با کلیدِ تصمیمی که پاسخش می‌دهد: حکمِ کلیددار ردیفِ
خودش را دارد با **Remember for this plan** (یک سطرِ `## Decisions` از راهِ `decisions.sh promote`،
منبعِ `ruling`، پشتِ `--allow-writes`) و — وقتی واژه‌هایش پاسخی است که کنسول می‌تواند برای آن کلید
نگه دارد — **Remember on this console** (`policy.<key>`)؛ هر دو `POST /api/run/:slug/rulings/:id/remember`
و هر دو حکم را به نام تأیید می‌کنند (`appendAck` تأییدی را که کسی پشتش نیست رد می‌کند). نشست اولی
را همان لحظهٔ ثبت با `--remember plan` انجام می‌دهد و دومی را با `--remember global` درخواست می‌کند.
پاسخ‌های خودِ کنسول در Settings ▸ Automation ▸ **Policy answers** است — یک کنترل برای هر سطرِ
جدولِ سیاست، شیء یکجا نوشته می‌شود، هر کلیدِ تغییریافته با `policy.changed` ثبت می‌شود — و
پرامپتِ جادوگرِ طرح با خواندنِ دفترهای مخزن باز می‌شود (`Service.planFacts`) و سپس مانیفست و هر
فیلدِ طرح را که `phase-graph.sh` بازمی‌خواند (`server/plan-fields.ts`، که `test/agent.test.ts` آن را
به فهرستِ پرچم‌های اسکریپت گره می‌زند) پرسش‌به‌پرسش و شماره‌دار می‌پرسد. Settings ▸ Permissions
وقتی فهرستِ ask ادغام‌شده خالی است یا یک قاعدهٔ deny پیش‌فرض خط خورده، هشداری تأییدپذیر بالا
می‌آورد (`policy.advisory`، یک بار در هر بوت؛ `GET /api/policy` ← `advisory`) و `editPolicy` قاعده‌ای
را که هرگز منطبق نمی‌شود رد می‌کند — پیشوندِ خالی، ابزاری که CLI ندارد (`shared/cli-tools.js`، به
اضافهٔ ابزارهایی که این کنسول دیده).

**زنده‌بودن (liveness) — آیا این لِین واقعاً کار می‌کند؟** یک `Bash` گیرکرده، نشستی که دور خودش
می‌چرخد و نشستی که در آستانه‌ی کامیت است، هر سه `running` با یک اسپینر دیده می‌شوند. حالا هر لِینِ
زنده `{lastOutputAt, lastToolUseAt, turnsSinceLastTool, commitsSinceStart, treeDirty, openTool?,
stall?, retries?, tokens?}` را در `GET /api/run/:slug` نشان می‌دهد و یک تیکِ ۶۰ ثانیه‌ای سیگنال‌ها را روی آن
می‌سنجد (`STALL_SIGNALS`، بدترین اول): `stalemate` (به تعدادِ `stallStalemateAttempts` تلاش که چیزی کامیت
نکرده‌اند و درخت را تمیز گذاشته‌اند)، `retrying` (به تعدادِ `stallRetryBurst` تلاشِ دوباره‌ی API پشتِ سرِ
هم، بی هیچ کارِ ثمربخشی میانشان)، `external-wait` (پایین‌تر)، `silent` (هیچ خروجی‌ای به‌مدتِ
`stallSilentMs`، با نامِ فراخوانی‌ای که بیشترین مدت باز مانده) و `spinning` (به تعدادِ `stallSpinTurns`
نوبت بدون هیچ فراخوانیِ ابزار). فازی که داخلِ §Verificationِ خودش است معاف است — بیلد ساکت است و مشکلی
ندارد. هر اپیزود یک کارت است: فقط گذارها در ژورنال می‌آیند (`phase.stall` / `phase.liveness`) و اعلام
می‌شوند، زیر دسته‌ی **`stalled`** (*Nothing is happening*) که پیش‌فرض روشن است و عمداً فوری نیست. بیشترِ
سیگنال‌ها یعنی نمایش، اعلان و فعل‌های دستی (تلنگر، فریز، توقفِ لِین)؛ دو تا خودشان عمل می‌کنند.
`external-wait` لِین را پارک می‌کند (پایین‌تر)، و لِینی که بوت شده و هنوز هیچ نگفته یک بار تلنگر می‌خورد،
اگر `STALL_NUDGE_GRACE_MS` (۵ دقیقه) بعد هنوز ساکت باشد یک بار از نو راه می‌افتد، و بعد برای یک آدم
می‌ماند — در هر فاز حداکثر یکی از هرکدام تا Retry، و هرگز نشستی که کاری کرده باشد
([docs/loop.md](../docs/loop.md)).

**کانتکست — هزینه‌ی هر فراخوانیِ بعدی.** هر فراخوانیِ ابزار کلِ گفت‌وگو را دوباره می‌خواند، پس رانر
`message.usage` هر فراخوانیِ API را از استریم جمع می‌زند (`runner/usage.ts`، یکتا بر اساسِ شناسه‌ی پیام):
`tokens` هر لِین کانتکستِ الان و اوجش، آنچه این تلاش از کش خوانده و در آن نوشته، بازسازی‌های کش
(فراخوانی‌هایی که دست‌کم max(100k، نیمی از کانتکست) نوشته‌اند) و بررسی‌های وضعیتی را که نگهبانِ
poll-loop شمرده نشان می‌دهد، و نمای اجرا آن‌ها را به‌صورت یک چیپ کنارِ چیپِ زنده‌بودن می‌آورد. نشستِ
خودِ فاز با پنجره‌ی مدلش سنجیده می‌شود (`scripts/models.env`: `[1m]` و خانواده‌های بزرگ 1M، بقیه 200k):
در 0.6 × یک بار به آن گفته می‌شود جمع کند — کامیت، هندآفِ `in-progress`، اعلامِ
`partial --reason context` (`phase.context-wrapup`) — و در 0.8 × کنسول آن را چک‌پوینت می‌کند و تلاشِ
بعدی را تازه با بریفِ resume سوار می‌کند. شمارنده‌های هر نشست با `phase.tokens` ژورنال می‌شوند و روی
رکورد به‌صورتِ `tokens[]` می‌مانند. خودِ resume هم سنجیده می‌شود، در همان یک دروازه (`resumePolicy`):
نشستی که با ≥ 250k توکن تمام شده و سرد است (≥ 55 دقیقه) یا زیرِ حسابِ دیگری است، یا
`partial --reason budget|context` اعلام کرده، یا کنسول چک‌پوینتش کرده، به‌جای `--resume` تازه با بریفِ
resume سوار می‌شود — resumeِ سرد کلِ کانتکستش را دوباره در کش می‌نویسد (`phase.resume-policy`).

**پول — ثبت‌شده و زنده.** هزینه‌ی یک نشست فقط وقتی تمام شود به `spentUsd` اجرا اضافه می‌شود، پس کاشیِ
Spent در نمای اجرا هزینه‌ی جاریِ نشست‌های زنده را کنارش نشان می‌دهد (`+ $X live`) — `spentUsd` هر لِین در
`liveness[]`، جمعِ جاریِ خودِ CLI تا آخرین `result`، که همان لحظه‌ای که نشست تمام و ثبت شود ناپدید می‌شود.

**نردبان در دلِ حلقه.** رکوردهای `interrupted` و `failed` دیگر پایانی نیستند. در ابتدای هر تیکِ حلقه،
بعد از هماهنگ‌سازی، رانر هر کدام را — و هر فازی را که هندآفش هست ولی کامل نیست — در برابر تابلو،
هندآف، قفل و درختِ کاری **طبقه‌بندی** می‌کند (`runner/situation.ts`: `never-started`،
`work-in-progress`، `done-unrecorded`، `verify-red`، `blocked-declared:<sub>`، …)، یک پله از نردبانِ
درمان (`runner/ladder.ts`، با همان تاریخچه و سقف‌هایی که شفادهنده دارد) را با وسیله‌های خودش بالا
می‌رود و فاز را با **خلاصه‌ای** که آن پله نام می‌برد سوار می‌کند: `fresh` (فقط پرامپتِ موتور — فازی که
هرگز شروع نشده)، `resume` (پرامپت به‌علاوه‌ی بلوکِ RESUMING: وضعیت هندآف، مسیرهای کامیت‌نشده،
آخرین راستی‌آزمایی، آخرین حرف‌ها)، `unblock` (پرامپت به‌علاوه‌ی متنِ Outstanding هندآف و «تو
اجازه داری کار را انجام دهی؛ اگر مانع کارِ اپراتور است، با خواسته‌ی دقیق `needs-human` اعلام کن» —
یک نشستِ محدود)، `continue` / `closeout` (نشستِ خودِ فاز با `--resume`). پس هندآفِ blocked دیگر
فوراً متوقف نمی‌کند: زیرنوعِ قفل دوباره در صف می‌رود، `credential`/`gate` بلافاصله با یک **خواسته**
(errand) پارک می‌شوند، `unknown` یک نشستِ unblock می‌گیرد و بعد خواسته. پایانِ نردبان فاز را با
خواسته پارک می‌کند — یک درخواستِ نام‌دار، در ژورنال `phase.errand` — و اجرا بقیه‌ی کارهای آماده را
ادامه می‌دهد. واژگانِ ژورنال: `phase.situation` → `phase.rung` → `phase.brief` → `phase.start`،
`phase.errand`، `phase.ladder-deferred` (پله‌ای مانده که فقط شفادهنده، روی اجرایی متوقف، می‌تواند براند؛
آن پله را به‌صورتِ `next` نام می‌برد). وضعیتی که جدولش هیچ پله‌ای ندارد که این کنسول بتواند براند همان
لحظه تمام‌شده حساب می‌شود — فاز با خواسته‌اش پارک می‌شود و بخشِ *how*ِ آن همین را می‌گوید — به‌جای اینکه
منتظرِ پله‌ای بماند که هیچ‌چیز از آن بالا نمی‌رود. هر وسیله یک راننده دارد (`VEHICLE_DRIVERS`: `console`،
`writes` برای آنچه `--allow-writes` می‌خواهد، `agent` برای یک نشستِ تازه یا ایجنتِ pty، و `never`).
فراخوانِ ابزاری که یک قاعده‌ی deny ردش کرده (`blocked-declared:permission`) یک پله دارد، `widen-rule`:
کارتی با عنوانِ *Phase N: widen `<rule>`?* که **Allow**ِ آن همان قاعده‌ی deny را برای این طرح خط می‌زند — از
۶.۲ یک اجازه در گستره‌ی طرح، یک ردیف در `grants.ndjson` که می‌شود revoke کرد — و
نشستِ خودِ فاز را ادامه می‌دهد، و **Deny**ِ آن — یا بی‌پاسخ‌ماندنش — فاز را با خواسته پارک می‌کند.
شفادهنده از بیرونِ حلقه با `startRun({resumeRunId, reboard: [{phase, situation, rung, brief}]})` به
همین وسیله می‌رسد. روشن‌بودنش همان سوییچِ ریکاوریِ خودکارِ اجراست؛ فازِ هرگزشروع‌نشده در هر حال
تازه سوار می‌شود، چون این کارِ خودِ اجراست.

**حلقه‌ی همگرایی.** از ۲.۳.۰ این ماشین بدون این‌که کسی نگاه کند می‌چرخد (`server/converge.ts`). هر
گذر برای هر پلن — `planConvergence` (خالص) تصمیم می‌گیرد، `executeConvergence` عمل می‌کند،
`ConvergeScheduler` ساعت است — **در بوت** (بعد از بازپذیرشِ اجراهای صف‌شده)، **با تغییرِ داکس**
(دیبانسِ دنباله‌دار ۲ ثانیه)، **هر `convergeEveryMs`** (Settings ▸ Automation، پیش‌فرض ۵ دقیقه، کفِ ۳۰
ثانیه)، **یک دقیقه بعد از هر توقف** (همان دقیقه‌ی سکوتی که تایمرِ ریکاوریِ خودکارِ قدیم نگه می‌داشت؛
تغییری در دلِ آن کوتاهش نمی‌کند) و **با Recover & continue** (همین حالا، منتظرمانده، بدون پین‌ها —
فشارِ خودِ اپراتور است) اجرا می‌شود. کارِ هر گذر به ترتیب: آزادکردنِ **آوارِ قفل** — ادعایی با مالکِ
`autopilot/<runId>` از اجرایی که هیچ‌کس نمی‌راند، منقضی یا نه، با همان مالک از طریق `phase-lock.sh
release` (هرگز با `--git`) آزاد و در ژورنال `run.lock-debris-released` ثبت می‌شود؛ ادعای یک شخص هرگز
آوار نیست؛ **راه‌اندازیِ دوباره‌ی** اجرایی که ری‌استارتِ خودِ کنسول متوقفش کرده (`stoppedBy: 'system'`):
لِین‌هایی که ری‌استارت کشته از `startRun({resumeRunId, reboard})` با اشاره به **ادامه‌ی نشستِ خودشان**
(`brief: continue`؛ نشستی که قابلِ ادامه نباشد به بوتِ تازه با بلوکِ resume تنزل می‌کند) دوباره سوار
می‌شوند، محدود به `MAX_BOOT_RESUMES` = ۳ برای هر فاز و در ژورنال `phase.resume-automatic` با `trigger` و
`path` — همان دروازه و شمارنده‌ای که هر ادامه‌ی خودکاری از آن می‌گذرد (انتظارِ دیرکرده، مسلح‌شدنِ دوباره‌ی
پارکِ سقفِ قفل، خاموشی بینِ لِین‌ها، و `partial` یک نشستِ دستی) — وقتی *Resume killed lanes at boot* در
Settings ▸ Automation روی **Never** باشد، اجرا با یک خواسته که دقیقاً همین را می‌گوید منتظرِ یک نفر می‌ماند (روی
**Ask**، پیش‌فرضِ ارسالی، پرسش تا دفعه‌ی بعد که اپ را باز می‌کنید روی صفحه منتظر می‌ماند و تا جواب ندهید چیزی شروع
نمی‌شود)؛ پارکِ سقفِ قفل وقتی قفلی که منتظرش بود رفت دوباره مسلح می‌شود (`phase.lock-cap-rearmed`؛ حلقه‌ی
زنده هم در ابتدای هر تیک همین کار را می‌کند)؛ و خاموشیِ بینِ فازها صرفاً ادامه می‌یابد. بعد **شفادهنده**
(`maybeAutoRecover`: طبقه‌بندیِ فازهای باز، یک پله بالا، راندنش از راهِ رانر) — یک بار برای هر شواهد:
گذری که چیزی را شفا نداد اثرانگشتِ شواهد را به خاطر می‌سپارد و تا چیزی عوض نشده دوباره نمی‌خواند. به
چه چیزی هرگز دست نمی‌زند: اجرایی که **اپراتور** مکث یا متوقفش کرده (`stoppedBy: 'operator'` — Pause،
Stop، فریزِ تشدیدشده؛ برای رکوردهای پیش از این فیلد، هر مکثی)، اجرای **resolved**، اجرای زنده، اجرایی
که منتظرِ ساعتِ خودش است، اجرای `finished` یا `queued` — و اجرایی را که با `failure-streak` یا `credential-refused` متوقف شده
(`PRESS_ONLY_HALT_KINDS`) هرگز خودش دوباره راه نمی‌اندازد: فقط فشارِ یک آدم این کار را می‌کند، راه‌اندازیِ
دوباره‌ای که با رشته‌ی شکستِ تمام‌شده به رانر برسد رد می‌شود (`run.relaunch-refused`)، و شفادهنده همچنان از
فازهای آن اجرا بالا می‌رود. `--no-converge` تریگرهای خودکار را خاموش نگه
می‌دارد (هارنسِ خام به‌طورِ ساختاری خاموش است)؛ فشارِ اپراتور همچنان همگرا می‌کند. هر گذری که عمل کند
`run.converge` را روی همان اجرا ژورنال می‌کند. `POST /api/run/<slug>/recover` هر جا چیزی راه نیفتاد با
`outcome: 'errand'` و بدنه‌ی `Errand` — چه لازم است و چطور بدهیدش — پاسخ می‌دهد؛ دیگر `needs-you`ِ خالی
وجود ندارد. رکوردِ `done` روی تابلویی که done نمی‌خواند یک هشدارِ سلامت است، `record-ahead-of-board`،
که هرگز بازنویسی نمی‌شود.

**تابلو زنده است، نه به‌ازای هر لِین.** واچرِ داکس حلقه‌های زنده را سیخونک می‌زند، پس هندآفی که یک
نشستِ دستی وسطِ اجرا می‌نویسد **همان لحظه** دیده می‌شود؛ و در ابتدای هر تیکِ حلقه، رکوردهایی که تابلو
از آن‌ها جلو زده بسته می‌شوند («closed outside this run» — یا برای فازی که همین اجرا شروعش کرده بود،
«closed while checkpointed — the board reads done; not verified by this run») و توقف‌های لنگرشده به آن‌ها حل می‌شوند —
این مسیر فقط می‌بندد و هرگز فازِ شکست‌خورده را دوباره اجرا نمی‌کند.

**ترتیبِ ریکاوری.** اول حل‌کردن: پیش از هر اسپانی تابلو دوباره خوانده و هماهنگ می‌شود — توقفی که
تابلو از آن گذشته `superseded` می‌شود و هیچ نشستی خرج نمی‌شود. بعد APIِ نشست: برای توقف‌های
`no-handoff` و `verify-failed` و `waiting-external-timeout` با نشستِ قابل‌ادامه، ریکاوریِ خودکار
همان نشستِ خودِ فاز را از طریق رانر ادامه می‌دهد (settings و denyها و هوک‌ها و ژورنال همه برقرارند؛
فقط `--allow-run` می‌خواهد). ایجنتِ pty برای تعمیرهای طرح‌گونه زیر `--allow-agent` می‌ماند و برای
آدم‌ها. ریکاوری‌ای که چیزی برای درست‌کردن پیدا نکند `no-defect` ثبت می‌شود — توقف کنار می‌رود بی‌آنکه
`done` جعل شود — و ریکاوری‌ای که زیر یک حلقه‌ی زنده تمام شود حکمش را به خودِ حلقه می‌سپارد. ریکاوریِ
یک فاز (`POST /api/run/:slug/recheck`، `closeout` یا `resume-phase`) با 409 رد و `run.recover.refused` ثبت
می‌شود وقتی شواهد از ریکاوریِ قبلی تکان نخورده (`unchanged`) یا فاز پیشاپیش `RECOVER_MAX_PER_PHASE` (۶)
ریکاوری داشته (`capped`)؛ Retry شمارنده را پاک می‌کند.

**قفل‌های بینِ طرح‌ها.** یک قفلِ خارجیِ منقضی‌نشده — اجرای طرحی دیگر، نشستی دستی، ماشینی دیگر از راه فایل‌های
قفلِ سینک‌شده با گیت — فاز را **پشتِ دارنده در صف می‌گذارد** (با نام و پایانِ اجاره، روی خطِ اجرا در گروهِ
**Queued** خانه‌ی Runs) به‌جای پارکِ نهایی. صف با واچرِ داکس (قفل‌ها زیر `docs/handoffs/**/.locks` هستند)، با
تایمری روی نزدیک‌ترین انقضای اجاره، و با پولِ بیکاری بیدار می‌شود؛ بعد از ۲ ساعت انتظارِ قفل، فاز صادقانه پارک
می‌شود با نامِ دارنده. تا وقتی نشستِ یک لِین زنده است، رانر هر ۱۰ دقیقه قفلش را با همان `PE_OWNER` تازه می‌کند
(claim با همان مالک اجاره را جلو می‌برد)، پس فازِ ۴۷ دقیقه‌ای هرگز بی‌صدا اجاره‌ی ۹۰ دقیقه‌ای‌اش را از دست
نمی‌دهد؛ تصاحب با `--force` خارجی فقط ثبت می‌شود و هرگز با آن جنگ نمی‌شود. **آن keepalive یک تایمر است و بس** —
نشانه‌ی زنده‌بودنِ یک پروسه است، هرگز نشانه‌ی پیشرفتش نیست، پس عمداً از `evidenceFingerprint`ِ شفادهنده
(`server/converge.ts`) بیرون گذاشته شده. قبلاً داخلش بود، و لِینی که هیچ کاری نمی‌کرد هر ده دقیقه به شفادهنده
می‌گفت «چیزی عوض شد».

پیچ‌های پارک و قفل ثابت‌های رانر هستند و عمداً در `scripts/sizing.env` نیستند (قانون F5 عددهایی را
تک‌منبع می‌کند که هم bash و هم TS می‌خوانند؛ bash این‌ها را هرگز نمی‌خواند): `WAIT_DEFAULT_MS` ۳۰
دقیقه، `WAIT_MAX_PER_PHASE` ۴، `DEFAULT_WAIT_BUDGET_MS` ۸ ساعت (پیش‌فرضی که طرح عوضش می‌کند)،
`WATCHDOG_PARKS_MAX_PER_PHASE` ۴، `WAIT_SETTLE_GRACE_MS` ۱۰ دقیقه (رکوردِ `waiting`ای که هیچ‌چیز
ساعتش را نمی‌زند بعد از آن تسویه می‌شود)، `DECLARED_CLOCK_MAX_MS` ۷ روز (سقفِ `--until` برای
`blocked`/`needs-human`)، `DECLARATIONS_MAX_PER_PHASE` ۴ برای هر واژهٔ اعلام‌شده، `DECLARATION_COOLDOWN_MS`
۵ دقیقه (دومین `partial` بی‌ناظر در این پنجره در اولی ادغام می‌شود)، `LOCK_WAIT_CAP_MS` ۲ ساعت،
`LEASE_REFRESH_MS` ۱۰ دقیقه، `RUNNER_LEASE_S` ۹۰ دقیقه — پیچ‌های انتظار کنارِ `evaluateWait` در
`server/runner/wait-budget.ts` و بقیه در `server/runner/runner-core.ts` (همه از `runner.ts` دوباره صادر
می‌شوند). سریِ پیشنهادِ دوبارهٔ ساعتِ نگهبانی پس از ردِ یک فرود `WATCH_REDELIVER_SERIES_MS` (۱، ۲، ۵، ۱۵،
۳۰ دقیقه) در `server/watch-refs.ts` است؛ `watchMintedCmdRefs` (تنظیمات ▸ خودکارسازی، خاموش) کلیدی است
که اجازه می‌دهد یک `cmd:` که خودِ کنسول ضرب کرده اصلاً اجرا شود.

**هر نشست سقف دارد و ثبت می‌شود، هر کسی که تمامش کند.** هر `claude -p` که رانر راه می‌اندازد از یک در
می‌گذرد (`RunnerBase.spawnSession`)، هم `--max-turns` و هم `--max-budget-usd` را با خود دارد و یک
رکوردِ `phase.session` با یک شکل می‌نویسد. سقف‌ها از `phaseBudgetUsd` خودِ اجرا می‌آیند اگر تعیینش
کرده باشد، وگرنه اندازه‌گیری‌شده‌اند — صدک ۹۹ِ هر حالت روی نشست‌های خودِ همین کنسول در دو هفتهٔ اخیر به‌علاوهٔ
۵۰ درصد، هر ساعت دوباره حساب می‌شود، و تا بیست نشست جدولِ همراهِ انتشار (۱۲۰ دلار / ۴۹۰ نوبت برای یک فاز)؛
شیوهٔ اندازه‌گیری روی هر رکورد ثبت می‌شود؛ نشست‌های جانبی (closeout، repair، QA، PR، review) یک‌چهارمِ دلارها و
`CLOSEOUT_MAX_TURNS` ۶۰ یا `REPAIR_MAX_TURNS` ۹۰ را می‌گیرند — و سقفی که CLI تمام‌شده گزارشش کند،
همان نشست را با دو برابرِ آن ادامه می‌دهد. پایانِ عمدی اول می‌خواهد نوبت بسته شود: SIGINT، بعد
`INT_GRACE_MS` ۵ ثانیه، بعد SIGTERM، بعد SIGKILL، تا CLI همان `result`ی را بنویسد که نوبت‌ها و
دلارهای نشست را ثبت می‌کند. ساعت‌های خودِ `spawn.ts` این‌ها هستند: `SPAWN_FIRST_EVENT_MS` (۲۰ دقیقه
بی‌خروجی) و `SPAWN_INIT_IDLE_MS` (۵۵ دقیقه سکوت میانِ `init` و نخستین `result`). تعریف در
`server/runner/session-record.ts`، `server/runner/signals.ts` و `shared/attention-model.js`. هر فرزند
همچنین با `CLAUDE_CODE_MAX_RETRIES` برابرِ ۱۵، `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` برابرِ 600000 و
`CLAUDE_CODE_RETRY_WATCHDOG` برابرِ 1 راه می‌افتد (`childEnv` در `server/runner/errors.ts`) — مقداری که از
محیط به ارث رسیده برنده است — و `phase.retry-ceiling` ثبت می‌کند زیرِ کدام سقف اجرا شد و آن سقف از کجا آمد.

**لِینی که منتظرِ ساعتِ کسِ دیگری است، خودش را پارک می‌کند.** فراخوانِ `Bash`ی که با واژگانِ مشترکِ ساعتِ
بیرونی جور درآید — `EXTERNAL_WAIT` در `scripts/verify.env`، همان فهرستی که lint F16 هنگامِ نوشتنِ طرح از
رویش هشدار می‌دهد — و بیش از `stallExternalWaitMs` (۵ دقیقه، `STALL_DEFAULTS`) باز بماند، سیگنالِ
`external-wait` را بالا می‌آورد، و این سیگنال فقط خبر نمی‌دهد، عمل می‌کند: فاز از همان `parkWaiting`ی پارک
می‌شود که یک `waiting-external`ِ اعلام‌شده به کار می‌برد، **قفلش آزاد می‌شود**، و نشستِ خودش وقتی پنجره سر
رسید ادامه می‌یابد. این واژگان عمداً یک رشته در یک فایل است که دو زبان می‌خوانندش، پس آنچه lint هنگامِ طرح
درباره‌اش هشدار می‌دهد دقیقاً همان است که هنگامِ اجرا پارک می‌شود (`viewer/test/verify-env.test.ts` هر دو
موتور را روی ورودی‌های یکسان اجرا می‌کند). اندازه‌گیری‌شده: فازی بیش از ۳۵ دقیقه داخلِ دو حلقه‌ی پول، ادعایی
انحصاری روی کلِ یک مخزن نگه داشت و روی هیچ سطحی دیده نمی‌شد — تا یک فراخوانِ Bash باز است هیچ رویدادِ
استریمی نمی‌رسد، و keepaliveِ بالا قفل را سالم نشان می‌داد. اینکه ساعت مالِ کیست چاره را تعیین می‌کند:
انتظار برای کارِ خودِ نشست — یک مجموعه‌تست، یک build، لاگی که خودش راه انداخته — در هوک مجاز است (یک
فراخوانِ پیش‌زمینه که مهلتِ Bash محدودش می‌کند)، اگر باز بماند یک بار با رویه‌ی انتظار steer می‌شود
(`LOCAL_JOB_NUDGE`)، و فقط پس از `stallLocalJobMs`ِ بسیار بلندتر (۴۵ دقیقه، `STALL_LOCAL_JOB_MS`) پارک
می‌شود. انتظار روی ساعتِ کسِ دیگر در هوک با همان رویه رد می‌شود. نشستی که نوبتش در حالی تمام می‌شود که
agentها یا monitorهای پس‌زمینه‌ی خودش هنوز کار می‌کنند، از سوی Stop hook رها می‌شود (`hook.stop-awaiting`)
و `silent` خوانده نمی‌شود: اعلانِ آن‌ها نوبتِ بعدی‌اش را شروع می‌کند. با خاموش‌بودنِ **Park a
waiting lane by itself** در Settings ▸ Automation (`stallAutomaticPark`، پیش‌فرض روشن) نگهبان هیچ لِینی را
پارک نمی‌کند و کارتِ توقف برای یک آدم می‌ماند.

**اجرا تا پایانِ طرح می‌رانَد.** بعد از هر فاز، تابلو دوباره خوانده می‌شود و کاری که با تمام‌شدنِ یک فاز باز شده
خودش شروع می‌شود — صف فقط چیزی را نشان می‌دهد که *همین حالا* قابل اجراست، و قابِ **Waiting** در **Sessions and
their consoles** نمای اجرا (<span dir="ltr">`?lane=waiting`</span>) بقیه را نشان می‌دهد: هر فازِ منتظر با همان
وابستگی‌هایی که منتظرشان است، تا فازهای ۱۰ و ۱۱ یک طرحِ ۱۱ فازی وقتی ۷ و ۹ می‌دوند رهاشده به نظر نرسند. اجرا
وقتی تمام می‌شود که کلِ گراف تمام شده باشد، یا با نام‌بردنِ دقیقِ چیزی که به آدم نیاز دارد پارک می‌کند. فشردنِ
Start یا Continue بودجه‌ی شکست‌های پیاپی را هم برمی‌گرداند — اپراتوری که برگشته همان علامتی است که موفق‌شدنِ یک
فاز است. و فقط فشار این کار را می‌کند: راه‌اندازیِ دوباره‌ی خودکار شمارش را نگه می‌دارد، و بازنشانی با مقدارِ
قبلی‌اش در ژورنالِ `run.failure-streak-reset` ثبت می‌شود.

**متوقف‌کردنِ یک فاز.** دو مکث، که عمداً نام‌های جدا دارند. *Pause after this phase* صبر می‌کند کارِ در
جریان تمام و راستی‌آزمایی شود. *Freeze now* **همه‌ی** نشست‌های در حالِ اجرا را همان‌جا که هستند نگه می‌دارد
(`SIGSTOP`) — فوری، برگشت‌پذیر، و بی‌آنکه چیزی از دست برود، چون هر پروسه هنوز آن‌جاست و نشستش را نگه
داشته. فریزی که بیش از پانزده دقیقه بماند خودش را به یک checkpoint تبدیل می‌کند: از فرزند خواسته می‌شود
متوقف شود، شناسه‌ی نشستش در اجرا نوشته می‌شود، و Continue آن را با `--resume` برمی‌دارد. پروسه‌ی متوقف
حافظه‌اش را نگه می‌دارد و کشِ پرامپتی را که به‌هرحال منقضی می‌شود، پس فریزِ شبانه آن گزینه‌ی ارزانی که به
نظر می‌رسد نیست.

**متوقف‌کردنِ یک نشستِ تنها.** وقتی چند فاز هم‌زمان می‌دوند، فرمان‌های سطحِ اجرا برای یک نشستِ خطاکار
پتکِ بزرگی‌اند — پس هر لِین، روی ردیفش زیرِ لِین‌های نمای اجرا و روی قابش، دکمه‌های **Freeze/Continue** و
**Stop** خودش را دارد. Freeze همان `SIGSTOP` است اما فقط برای همان لِین؛ بقیه‌ی نشست‌ها کار می‌کنند و اجرا فقط
وقتی «frozen» خوانده می‌شود که هیچ‌چیز در حالِ دویدن نمانده باشد. Stopِ تک‌نشست همان نشست را تمام
می‌کند (اول SIGCONT، بعد SIGTERM، بعد پشتیبانِ SIGKILL پس از ۱۵ ثانیه)، فاز را **interrupted** ثبت
می‌کند و شناسه‌ی نشست را نگه می‌دارد — Retry می‌تواند ادامه‌اش بدهد — و حلقه بلافاصله به زمان‌بندی
برمی‌گردد: بقیه‌ی اجرا ادامه می‌یابد و فازهای وابسته صادقانه منتظر می‌مانند. Stop روی فازِ در صف، آن را
پیش از هر spawn از صفِ پذیرش بیرون می‌کشد. هیچ‌کدام به بودجه‌ی شکست دست نمی‌زنند: توقفِ اپراتور نه شکست است و نه تأیید.

**اینکه یک فاز با چه تنظیماتی اجرا می‌شود** از سه جا حل می‌شود، به همین ترتیب: چیزی که شما برای این اجرا
انتخاب کرده‌اید، بعد بولت‌های `**Model:**` / `**Effort:**` خودِ طرح برای آن فاز، بعد پیش‌فرض‌های اجرا —
و این کار **به‌ازای هر فیلد** انجام می‌شود، پس انتخابِ یک مدل باعث دورریختنِ effort ای که طرح خواسته بود
نمی‌شود. ژورنال ثبت می‌کند که هر فیلد را کدام منبع جواب داده است.

**صفحه‌ی راه‌اندازی همین جواب را پیش از فشردنِ Start نشان می‌دهد.** هر ردیفِ جدولِ فازهایش (بازنویسی‌های
هر فاز در ردیفِ **Engine**) زیرِ انتخاب‌گرهای مدل
و effort می‌نویسد `runs <value> · <source>` — *plan*، *set here*، *run default* یا *this attempt* — و آن را همان
`resolvePhaseChoice` (`shared/run-settings.js`) محاسبه می‌کند که اجراکننده فاز را با آن سوار می‌کند، پس فرم
نمی‌تواند یک effort را وعده دهد و فاز با effort دیگری اجرا شود. جایی که طرح و اجرا با هم نمی‌خوانند، خلاصه‌ی
جدول یک برچسبِ *plan and run differ on N phases* و برای هر فیلد یک یادداشت دارد: مقدارِ طرح پایین‌تر یا بالاتر
از پیش‌فرضِ اجراست (و طرح برنده است)، یا انتخابی که این‌جا شده جای مقدارِ طرح را می‌گیرد. با روشن بودنِ
**Review each phase**، فرم این را هم می‌گوید که طرح خودش کارش را بازبینی می‌کند — بخشی که یک بازبین را
dispatch می‌کند، یا `**QA gate:** on` — چون آن‌وقت هر فاز دو بار بازبینی می‌شود، حدودِ ۷ تا ۱۰ دلار برای هر
فاز. این یک توصیه است، هرگز مانع نیست.

**اسکیل‌ها.** کنسول همه‌ی اسکیل‌هایی را که یک نشست می‌تواند صدا بزند فهرست می‌کند — شخصی، مالِ همین مخزن،
و مالِ هر پلاگینِ نصب‌شده — و آن‌هایی را که انتخاب کنید به بوت‌پرامپت اضافه می‌کند، برای هر اجرا یا هر فاز.
خطِ `Skills (every session)` خودِ طرح همچنان از موتور می‌آید و به‌شکلِ ثابت نمایش داده می‌شود.

**حرف‌زدن با فازی که در حال اجراست.** ورودیِ استاندارد (stdin) نشست باز می‌ماند، پس یک سؤال فقط یک نوبتِ
دیگر در همان گفت‌وگوست، نه دلیلی برای متوقف‌کردنش:

<div dir="ltr">

```bash
btw "why did you skip the cache?"     # or the box under the session console
```

</div>

دو حالت، چون دو کارِ متفاوت‌اند. **Ask** پیش از ارسال به‌عنوانِ «خارج از مسیرِ اصلی» قاب‌بندی می‌شود، تا یک
جواب به تغییرِ مسیر تبدیل نشود. **Steer** برعکس است و همین را هم می‌گوید: دستوری که باید در کار جا بیفتد — با
این قید که معیارهای خروج و دستورهای راستی‌آزماییِ طرح همچنان تعیین می‌کنند فاز پاس می‌شود یا نه، پس
steer کردنِ یک فاز از روی گیتش چیزی نیست که بتواند رخ دهد. هر پیام یک برچسب دارد؛ کنسول آن را یک بار نشان
می‌دهد، وقتی CLI آن را بازتاب داد تیکش را می‌زند، و پاسخِ نشست را کنارِ همان پرسش می‌گذارد، نه اینکه در یک
ساعت خروجیِ build گمش کند.

**پیام به یک لِین فرستاده می‌شود.** با سه فازِ در حالِ اجرا سه نشست هست، و فازی که جعبه زیرِ آن باز شده
همراهِ پیام می‌رود — سرور stdinِ همان لِین را پیدا می‌کند و فقط وقتی کسی لِینی نام نبرده به لِینِ زنده‌ای با
کمترین شماره برمی‌گردد. لِینِ تسویه‌شده با ذکرِ دلیل رد می‌کند، به‌جای اینکه دستوری را به ناکجا بپذیرد؛ جعبه
هم با همان واقعیت خودش را غیرفعال می‌کند.

جعبه در دو جا ظاهر می‌شود، از یک مؤلفه: قابِ یک لِین در **Sessions and their consoles** نمای اجرا، و
صفحه‌ی خودِ فاز، زیرِ *This phase is running*. روی صفحه‌ی فاز، دروازه `PhaseView.live`
است — چیزی که دیده شده روی فاز کار می‌کند — و هرگز واژه‌ی تابلو نیست، چون `in-progress` جمله‌ای از یک هندآف
است نه یک پروسه‌ی در حالِ اجرا. فقط لِینی که همین کنسول می‌رانَد steer می‌شود؛ فازی که یک فایلِ قفل یا یک
نشستِ ترمینال نگهش داشته همین را می‌گوید، به‌جای پیشنهادِ جعبه‌ای که نمی‌تواند پیام را برساند.

**تماشای یک فاز.** پروسه‌ی `claude -p` به‌طورِ پیش‌فرض مات است، و ترنسکریپتی که اسکرول می‌خورد به «چه گفته»
جواب می‌دهد نه «چه می‌کند». پس قابِ هر لِین در نمای اجرا همان استریم را به‌شکلِ *وضعیت* هم می‌خواند: **فهرستِ کارهای**
نشست، **فراخوان‌های ابزارش** با مدت و نتیجه‌ی ok/error برای هرکدام — که با شناسه‌ی `tool_use`ِ خودِ CLI
جفت می‌شوند، تا فراخوانی که هنوز در جریان است از فراخوانی که فوری تمام شده تشخیص داده شود — و **یک لِین
برای هر ساب‌ایجنت**، که به فراخوانِ `Agent`ِ سازنده‌اش گره می‌خورد نه اینکه در یک صدا تا شود. هر سه از
ترنسکریپتِ ذخیره‌شده بازسازی می‌شوند، پس مثلِ خودِ کنسول از یک رفرش جان به در می‌برند.

**چقدر مانده** از روی زمانی برآورد می‌شود که فازها واقعاً گرفتند (6.0): شاهدِ هر فازِ تمام‌شده زمانِ *کارشده‌ی*
آن روی همه‌ی نشست‌هایی است که رویش کار کردند — ازسرگیری، تعمیر، QA، بستن، فرود و بازبینی هم — و فازِ
تمام‌شده‌ای که اندازه‌گیریِ واقعی ندارد (بستنی پنج‌ثانیه‌ای که فقط کاغذبازیِ پایانی بود، یا فازی که بیرون از اجرا
بسته شد) کنار گذاشته و به‌عنوانِ شاهدِ غایب شمرده می‌شود، نه این‌که بی‌صدا حذف شود. هر فاز **یک کف به‌علاوه‌ی
شیبی ضربدر وزنش** طول می‌کشد: شکل از میانه‌های هر اندازه روی شصت فازِ اندازه‌گیری‌شده‌ی تازه‌ی این کنسول می‌آید و
سطح از دوازده فازِ تازه‌ی خودِ طرح، پس یک داده‌ی پرت برآورد را حداکثر ۱٫۵ برابر جابه‌جا می‌کند و یک L شش برابرِ یک
S نیست. بازه پراکندگیِ همان فازها دورِ مدل است، نه شمارِ آن‌ها. هر عدد ساعتش را نام می‌برد — *کار* یعنی فازها
پشتِ سرِ هم، *روی تقویم* یعنی تاریخی که با چرخه‌ی کاریِ اخیرِ طرح کشیده شده — و تقویم به‌جای برون‌یابیِ طرحی که
بیشترِ وقت بیکار ماند، **نامعلوم** می‌خواند. یک فاز می‌تواند `- **Wall-clock floor:**` اعلام کند (یک gate کامل،
انتظارِ یک استقرار) که برآورد هرگز زیرش نمی‌رود. این برآوردگر به این دلیل عرضه می‌شود که در آزمونِ بازپسین روی
اجراهای ذخیره‌شده‌ی همین ماشین از میانه‌ی ساده‌ی اخیر بهتر است (`test/eta-backtest.test.ts`). به‌شکلِ یک بازه‌ی
درشت نشان داده می‌شود و هرگز شمارشِ معکوس نیست. حدس‌زدن کارِ آن است؛ وانمود به دانستن نه.

**باخبر شدن.** چهار راه، به ترتیبِ اینکه تا کجا می‌رسند — و یکی‌شان یک نسخه نگه می‌دارد.

**Announcements**ِ زنگ (<span dir="ltr">`?bell=1`</span>، جایی که <span dir="ltr">`#/notifications`</span>ِ
قدیمی به آن می‌رسد) همان نسخه است. هر اعلانی پیش از آنکه به جایی تحویل شود در یک لاگِ فقط‌افزودنی نوشته می‌شود،
پس ساختاراً کامل است: رویدادی که وقتی گوشی خواب بود، هیچ تبی باز نبود و هیچ دستگاهی مشترک نبود رسید، صبح هم
همان‌جاست. تازه‌ترین اول، با محدودکردن به خوانده‌نشده‌ها یا یک دسته در نشانی (<span dir="ltr">`?unread=`</span>،
<span dir="ltr">`?category=`</span>)، و هر ردیف همان چیزی را باز می‌کند که درباره‌اش بود. از ری‌استارت جان به در
می‌برد، ۵۰۰ رکورد یا ۳۰ روز نگه می‌دارد، و فقط وقتی خودتان بگویید پاک می‌شود. هر ردیف همچنین نشان می‌دهد برای هر
دستگاه چه بر سرش آمد — `sent`، `throttled`، `failed`، `gone` — چون پوشی که بی‌صدا به هیچ‌جا نرسید، در غیر این
صورت از پوشی که رسید قابلِ تشخیص نیست.

*In this tab* همان Notification APIِ مرورگر است: رایگان، فوری، و با بسته‌شدنِ تب رفته. *On this device* یک
اشتراکِ push است — یک service worker و یک جفت‌کلیدِ VAPID، تا اعلان با کنسولِ بسته و گوشیِ قفل هم برسد. هر
دو در Settings ▸ Notifications هستند، برای هر دستگاه، روی بیست دسته: permission needed، a session
waiting on you، a phase needs you، a gate needs a person، a QA verdict owed or failed، run halted، run
parked or waiting، nothing is happening، phase finished or failed، plan finished، work became ready، plans
changed on disk، a session ended، console problems، usage limits، usage climbing، budget spent or running
low، issue drafted by a session، hourly digest (اول Your turn)، permission granted. پنج‌تا فوری فرستاده
می‌شوند: permission needed، a session waiting on you، a phase needs you، a QA verdict owed or failed و run
halted. پوش نامِ کنسولی را که از آن آمده می‌برد — عنوانش به `· <console>` ختم می‌شود — و تحویلی که هیچ
دستگاهِ مشترکی پیدا نکرد، یا هیچ دستگاهی که آن دسته را بپذیرد، به‌جای اینکه بی‌صدا دور ریخته شود `no-device`
ثبت می‌شود. دکمه‌ی **Send a test** از راهِ سرویسِ push واقعی می‌رود و برمی‌گردد، پس کلِ زنجیره را اثبات
می‌کند نه فقط آخرین حلقه را. اعلانِ تأیید، **Allow** و **Deny** را به‌صورتِ کنش‌های خودِ اعلان دارد، پس
جواب‌دادن از صفحه‌ی قفل یک ضربه است. پوشِ یک مورد از Your turn خودِ مورد را باز می‌کند
(<span dir="ltr">`#/turn/<id>`</span>) و فقط دکمه‌هایی را دارد که درِ `device` می‌تواند فشار دهد — جدولش در
`docs/phone.md` است.

متغیرِ `PHASE_CONSOLE_NOTIFY=<command>` چیزی را پوشش می‌دهد که هیچ‌کدام نمی‌توانند: ماشینی که اصلاً مرورگری
در کارش نیست. به‌صورتِ `cmd "<title>" "<body>"` اجرا می‌شود، و اینکه یک متغیرِ محیطی است و نه یک تنظیمِ
داخلِ برنامه، عمدی است — چون یک دستور را روی همین ماشین اجرا می‌کند.

هر مقصد با یک تابع تعیین می‌شود (`routeFor`) که اعلانِ SSE، payloadِ push، service worker و ردیفِ صندوق
همه از آن استفاده می‌کنند، و یک تست کاتالوگ را در برابرِ روترِ خودِ کلاینت می‌پیماید. پیش از آن دو URLِ
دست‌نویس بود و هر دو تبی را نام می‌بردند که وجود ندارد، پس در تمامِ عمرِ این قابلیت هر اعلانِ تأیید صفحه‌ی
اشتباه را باز می‌کرد.

payloadها برای مرورگرِ مشترک رمز می‌شوند ([RFC 8291](https://datatracker.ietf.org/doc/html/rfc8291))، پس
یک سرویسِ push اعلانی درباره‌ی طرح‌هایتان را جابه‌جا می‌کند بی‌آنکه بتواند بخواندش. مثلِ بقیه‌ی این کنسول،
چیزی برای نصب نیست — `node:crypto` هر عنصرِ اولیه‌ای را که لازم دارد در خود دارد.

**کاری که انجام نمی‌دهد.** لیستِ `permissions.deny` به هر نشست در سطحِ CLI داده می‌شود و همان لایه‌ای است
که **حتی با مردنِ این کنسول** سرِ جایش می‌ماند — این اندازه‌گیری شده، نه فرض‌شده. اما لیستِ `ask` از یک
هوکِ HTTP رد می‌شود که **fail-open** است، یعنی اگر در دسترس نباشد اجازه می‌دهد؛ پس آن لیست حاملِ
«روالِ کاری» است و هرگز حاملِ «امنیت» نیست. صفحه‌ی Settings هر دو را نشان می‌دهد و می‌گوید کدام کدام است.
از همان‌جا می‌شود قانون اضافه یا حذف کرد — هر قانونی با × روی چیپِ خودش برداشتنی است، از جمله
پیش‌فرض‌های هر سه لیست که با نام حذف می‌شوند (خط‌خورده زیر لیست می‌مانند، با **Restore** برمی‌گردند، و
دکمه‌ی **Restore defaults** هر بخش را یک‌جا به حالت اولیه برمی‌گرداند). حذفِ یک قانونِ پیش‌فرض از
`deny` وسیع‌ترین ویرایشِ این صفحه است — دیوار برای هر اجرای آینده جابه‌جا می‌شود، از جمله در
تنظیماتِ سمتِ CLI که حتی با مردنِ کنسول برقرار می‌ماند — پس فقط همان یک حذف، پیش از نوشتن، از شما
تأیید می‌گیرد. قانون‌هایی که خودتان اضافه کرده‌اید مثل همیشه یک‌ضربه‌ای برداشتنی‌اند.

اجراکننده همچنین دستورِ راستی‌آزمایی‌ای را که از درختِ کاری بیرون بزند اجرا نمی‌کند، مگر اینکه بتوان
نشان داد فقط-خواندنی است — `curl -X POST` و `ssh box 'systemctl restart …'` و `psql -c 'DELETE …'` همه
به یک آدم ارجاع داده می‌شوند (همراه با دلیلش)، در حالی که `docker ps` و `psql -c 'SELECT …'` همچنان
اجرا می‌شوند.

### مجوزها: یک اجرا چقدر اجازه دارد

سه پروفایل، که هنگام شروعِ اجرا انتخاب می‌شوند و وسطِ کار هم قابلِ تغییرند:

| پروفایل | فهرستِ ask | argv فرزند | کِی از آن استفاده کنید |
|---|---|---|---|
| **Guarded** (پیش‌فرض) | برقرار — کامیت، نصب و merge کارت بالا می‌آورند | `--permission-mode acceptEdits` | وقتی خودتان هستید و جواب می‌دهید |
| **Trusted** | خالی‌شده | `--permission-mode acceptEdits` | اجرای شبانه روی کاری که به آن اعتماد دارید |
| **Bypass** | خالی‌شده | `--permission-mode bypassPermissions` | وقتی حتی پرسشِ خودِ CLI هم سرِ راه است |

**فهرستِ `deny` در هر سه یکسان است.** پروفایل فقط فهرستِ ask را جابه‌جا می‌کند — و «یکسان» یعنی هرچه
دیوارِ ویرایش‌شده‌ی اپراتور همین حالا دارد، با حذف‌ها و اضافه‌های خودش. این زیرِ Bypass هم برقرار است:
توصیفِ خودِ CLI از `bypassPermissions` این است که «هر فراخوانِ ابزار را خودکار تأیید می‌کند *به‌جز
قوانینِ صریحِ deny*».

**Bypass یک disclaimer دارد که فقط به‌صورتِ تعاملی می‌شود پذیرفتش.** این از رفتارِ خودِ CLI خوانده شده:
اگر `--permission-mode bypassPermissions` بدهید و آن disclaimer پذیرفته نشده باشد، Claude Code نه خطا
می‌دهد و نه پرچم را رعایت می‌کند — بی‌صدا به `default` تنزل می‌کند، و `default` در حالتِ `-p` یعنی
پرسیدن از ترمینالی که وجود ندارد، یعنی ردکردنِ هر ویرایش. پس روی ماشینی که کسی هرگز آن را نپذیرفته،
Bypass اجرایی می‌سازد که **کمتر** از Guarded می‌تواند کار کند، بی‌آنکه دلیلش دیده شود. یک‌بار در یک
نشستِ عادیِ `claude` بپذیریدش، یا از Trusted استفاده کنید. کنسول خطِ تنزلِ خودِ CLI را می‌پاید و
نشانش می‌دهد، به‌جای اینکه بگذارد فاز بی‌صدا شکست بخورد.

تعویضِ وسطِ کار به‌صورتِ `run.permission-profile` با نامِ عاملش ژورنال می‌شود، در هوکِ **فراخوانِ ابزارِ
بعدی** اثر می‌کند، و در **فازِ بعدی** به argv فرزند می‌رسد — فرزندِ در حالِ اجرا نمی‌تواند تنظیماتِ خودش
را دوباره بخواند، و کنسول همین را می‌گوید به‌جای اینکه خلافش را القا کند. اجرایی که روی چیزی جز
Guarded باشد، تا وقتی برقرار است یک بنر حمل می‌کند.

**پرسش یک ask نیست، و هیچ پروفایلی آن را بی‌صدا نمی‌کند.** `AskUserQuestion` دسته‌ی خودش را دارد
(`QUESTION_CLASS`) که درست بعد از deny و پیش از فهرستِ ask بررسی می‌شود، پس خالی‌شدنِ فهرستِ ask زیرِ
Trusted یا Bypass هرگز پرسشی را به یک اجازه‌ی بی‌صدا بدل نمی‌کند. هوک نگهش می‌دارد: با رله‌ی مسلح، پرسش
یک کارت می‌شود (*وقتی هیچ‌کس جواب نمی‌دهد*، پایین‌تر)؛ بدونِ آن ردیفِ `ambiguity`ِ جدولِ سیاست پاسخ می‌دهد
— زیرِ پیش‌فرضش، `ruling`، به نشست گفته می‌شود از روی طرح تصمیم بگیرد، یک حکم ثبت کند و ادامه دهد، و زیرِ
هر پاسخِ دیگری `needs-human` اعلام کند و بایستد — و با `class: 'question'` در `phase.policy-answered` ثبت
می‌شود. نشستی که رله مسلحش نکرده با `--permission-prompts none` راه می‌افتد: هر چیزی که بخواهد بپرسد رد
می‌شود و به نشست گفته می‌شود کسی نمی‌تواند تأیید کند، `AskUserQuestion` برداشته می‌شود و elicitationها لغو
می‌شوند. CLIای که معلوم است از این پرچم قدیمی‌تر است (`PERMISSION_PROMPTS_CLI_FLOOR`، 2.1.259) پرچم را
نمی‌گیرد و اجرا یک بار `run.permission-prompts-skipped` ثبت می‌کند؛ نسخه‌ی نامعلوم همچنان آن را می‌گیرد، تا
CLIِ قدیمی هنگامِ spawn با صدای بلند شکست بخورد، به‌جای اینکه این کف بی‌خبر برداشته شود.

### پاسخ خودکار به مجوزها (Auto-grant)

از ۲۰۲۶-۰۸-۲۳ کنسول به‌طور پیش‌فرض کارت‌های فهرست ask را **خودش پاسخ می‌دهد**: پرسش همچنان اتفاق
می‌افتد — طبقه‌بند همچنان ask می‌گوید و هوک باز می‌ماند — فقط دستِ پاسخ‌دهنده خودکار است. هر کارتِ
خودکار در تاریخچهٔ approvals ثبت می‌شود (`decided by auto-grant`) و در ژورنال اجرا هم می‌نشیند
(`phase.approval-auto-granted`، همراهِ قاعده‌ای که منطبق شد)؛ چیزی کمتر پرسیده نمی‌شود، فقط کمتر معطل
می‌ماند. فهرست deny دست‌نخورده است، wrapperی که چیزی از جنس deny را پنهان کرده باز هم به آدم می‌رسد، و
تأیید verification و gateها هرگز خودکار پاسخ نمی‌گیرند. **انتشار هم هرگز خودکار پاسخ نمی‌گیرد**:
`git push` و `gh pr create` (`OPEN_PR_ASK`) منتظرِ یک آدم می‌مانند، مگر ردیفِ `permission.destructive` در
طرح یا اجرا همان قاعده را به‌عنوانِ استثنا نام برده باشد — پاسخی که زیرِ چنین استثنایی داده شود اعلام
می‌شود، *Published under a plan exception*، و خطِ ژورنالش استثنا را با خود دارد. سه دامنه، خاص‌ترین برنده: هر فاز (پنل **More** در دیالوگ اجرا) → هر پلن →
همه‌جا (Settings ▸ Permissions)؛ پیش‌فرض روشن، و در هر دامنه که خاموشش کنید همان کارت‌ها مثل قبل
منتظر آدم می‌مانند. پرسشِ **Who was asked** در Insights هر دو سو را از یک تاریخ به بعد می‌شمارد — آنچه برای
یک آدم بالا آمد، آنچه auto-grant پاسخ داد، آنچه همین حالا منتظر است، آخرین بالاآمدن — از همان شمارش‌هایی که
`/api/state` به‌صورتِ `approvals` سرو می‌کند (`raised`، `autoGranted`، `since`، `lastRaisedAt`، `pending`).

### نوشتن یک قانون از دلِ همان کارتی که مزاحمتان شد

**Grant**ِ یک موردِ مجوز، کنارِ **This call** و **This phase**ِ تنگ‌تر، **This plan** و **This repository** و
**Always** را پیشنهاد می‌دهد (control-tower phase 149)، و هرکدام می‌گوید چه چیزی را می‌پوشاند و کِی تمام می‌شود. در گستره‌ی طرح و پهن‌تر، یک اجازه
خودش یک ویرایشِ سیاست است، و آن قانون از همان قاعده‌ی ask ای مشتق می‌شود که واقعاً فراخوان را متوقف کرد، پس
پذیرفتنش دقیقاً همان چیزی را لغو می‌کند که مزاحمتان شد — و **پیش از** تمام‌شدنِ مورد نوشته می‌شود، تا فراخوانِ
بعدیِ همان نشست از همان لحظه زیرِ آن طبقه‌بندی شود. ردیفِ اجازه در `grants.ndjson` فایل، فهرست و قاعده‌ای را که
تغییر داد نام می‌برد (`strike`، `remove` یا `add`)، پس یک revoke دقیقاً همان را برمی‌گرداند؛ بقیه‌اش در
بخشِ *Your turn* پایین‌تر است.

- قانون‌های در سطحِ طرح در `~/.config/phase-console/plans/<instance>/<slug>.json` می‌نشینند، قانون‌های در
  سطحِ مخزن در `~/.config/phase-console/repositories/<instance>.json` — لایه‌ای میانِ فایلِ طرح و فایلِ
  ماشین، برای هر طرحِ این کنسول — و سراسری‌ها در `~/.config/phase-console/autopilot.json`. هر سه روی
  پیش‌فرض‌های عرضه‌شده **افزوده** می‌شوند.
- ارزیابی به این ترتیب است: **deny ← allowی که خودتان نوشته‌اید ← ask ← allow**، اولین تطابق برنده،
  و خاص‌بودن بی‌اهمیت. تنها انحراف از ترتیبِ خودِ Claude Code عمدی است: یک قانونِ allowِ ساده هرگز
  نمی‌تواند یک قانونِ ask را لغو کند، پس «همیشه این را اجازه بده» وگرنه قانونی می‌نوشت و هیچ چیزی
  عوض نمی‌شد.
- هر نوشتن روی اجرای زنده ژورنال می‌شود — یک ویرایش به‌صورتِ `policy.edited`، یک اجازه به‌صورتِ
  `policy.grant-applied` و پایانش `policy.grant-ended` — با نویسنده و دامنه‌اش، و از
  **Settings ▸ Permissions** با × روی چیپش برداشتنی است.
- **این هم گشاد می‌کند و هم تنگ**، که خلافِ قاعده‌ی قدیمی‌ترِ کنسول است که می‌گفت یک مرورگر فقط
  می‌تواند اجرا را محتاط‌تر کند. آنچه آن نسخه‌ی سخت‌گیر در عمل تولید کرد، ده کارتِ `git commit` در یک
  اجرا بود و آدمی که بی‌خواندن Allow می‌زد — یعنی دقیقاً همان شکستی که برای جلوگیری از آن ساخته شده
  بود، از راهی دیگر.

### قانون‌هایی که این کنسول واقعاً اعمال می‌کند

هوکِ PreToolUse فقط برای `Bash`، `Write`، `Edit`، `NotebookEdit`، `WebFetch` و `WebSearch` شلیک
می‌شود. قانون‌هایی درباره‌ی هر چیزِ دیگر — `Read`، `Agent`، `Cd`، `mcp__*` — واقعی‌اند و CLI اعمالشان
می‌کند، اما هیچ‌چیز اینجا خوردنِ یکی‌شان را به شما نشان نخواهد داد، و Settings ▸ Permissions کنارِ
قانون‌ها همین را می‌گوید به‌جای اینکه خلافش را القا کند. شکل‌های پشتیبانی‌شده همان تاکسونومیِ مستندند: ابزارِ خالی،
پیشوندِ دستور (`Bash(git commit:*)`)، گلابِ دستور (`Bash(npm run test *)`)، یک پارامتر
(`Agent(model:opus)`)، مسیرها (`Read(~/.ssh/**)`)، دامنه‌ها (`WebFetch(domain:*.example.com)`)، MCP،
نوعِ ایجنت و `Cd`.

لبه‌ها در رابط نشان داده می‌شوند، چون هرکدام یک بعدازظهر از کسی گرفته‌اند:

- `Bash(ls:*)` همان `Bash(ls *)` است — و با `lsof` تطابق **نمی‌کند**. `ls *` و `ls*` دو قانونِ متفاوت‌اند.
- wrapperها دیده می‌شوند — `timeout time nice nohup stdbuf command builtin noglob` و `xargs`ِ خالی —
  اما **نه** `npx`، `docker exec` یا `devbox run`.
- `watch`، `setsid`، `flock` و `find -exec` هرگز خودکار تأیید نمی‌شوند: آنچه اجرا می‌کنند از بیرون
  دیده نمی‌شود، پس کارت می‌گیرند.
- فقط قانون‌های مسیرِ `Read(…)` و `Edit(…)` خوانده می‌شوند؛ مسیرهای `Write(…)`، `NotebookEdit(…)` و
  `Glob(…)` نادیده گرفته می‌شوند. `Bash(command:rm *)` پارس می‌شود و هیچ کاری نمی‌کند. Settings هر
  قانونی از این جنس را که نوشته باشید زیرِ **These parse and do nothing** فهرست می‌کند.

### وقتی هیچ‌کس جواب نمی‌دهد

یک کارتِ ابزار **یک ساعت** صبر می‌کند، نه ده دقیقه. سرِ ده دقیقه، یک اجرای شبانه‌ی واقعی کامیتش رد شد
چون همه خواب بودند — بدترین نتیجه‌ی ممکن، چون کار انجام شده بود و به نشست «نه» گفته شد به دلیلی که در
واقع «شما نبودید» بود. تا کارتی باز است، اجرا به‌جای «در حالِ اجرا» `waiting` برای یک آدم خوانده می‌شود
(`run.waiting-person`، با نامِ کارت و مهلتش). هوک همچنان پیش از تایم‌اوتِ خودش جواب داده می‌شود (سکوت
fail-open است)، اما یک تایم‌اوت حالا **اجرا را** با نوعِ `awaiting-person` **پارک می‌کند** به‌جای اینکه
بگذارد نشست آن ردشدن را حکمی درباره‌ی کار بداند: `run.parked`، بی‌آنکه شکستی شمرده شود، و فاز از همان
لحظه‌ای که کارت جواب بگیرد دوباره قابلِ اجراست.

**کارت از ری‌استارت جان به در می‌برد، اگر نشستش جان به در ببرد.** هنگامِ بوت، کنسول توکنِ هوکِ فرزندی را که
زنده مانده از فایلِ تنظیماتش برمی‌دارد و کارت‌های ابزارِ پاسخ‌پذیرش را دوباره به حالتِ انتظار برمی‌گرداند؛
کارتی که دیگر نمی‌شود پاسخش داد `unanswerable` خوانده می‌شود — واژه‌ای که جای `expired` را گرفت — همراهِ
دلیلش: `session-gone`، `token-lost`، `asker-gone`، `reoffered` یا `hook-closed`. پاسخی که یک آدم به کارتِ
بازیابی‌شده بدهد یک بار نگه داشته می‌شود و وقتی نشست همان فراخوان را تکرار کند به آن تحویل می‌شود.

**پرسش یک دقیقه فرصت دارد، بعد یک قاعده.** ردیفِ **Decisions** در صفحه‌ی راه‌اندازی از هر اجرا رله‌اش را
می‌پرسد: `off` (کنسول هرگز به‌جای یک آدم به پرسشی پاسخ نمی‌دهد) یا `last-resort` (اول به یک آدم خبر داده
می‌شود؛ پس از ۶۰ ثانیه کنسول بر اساسِ قاعده پاسخ می‌دهد). زیرِ `last-resort` نشستِ فازی که CLIاش هم‌تراز یا
بالاتر از `RELAY_CLI_FLOOR` (2.1.268) باشد مسلح می‌شود (`run.relay-armed`؛ `run.relay-refused` دلیلِ
`below-floor` یا `version-unknown` را می‌گوید)، و پرسشی که بپرسد یک **کارتِ پرسش** می‌شود — در نمای اجرا،
به‌صورتِ یک مورد روی Your turn با شمارشِ معکوس، و به‌صورتِ پوش، *A session asks — answered by rule in
60 s unless you do* — با یک دکمه برای هر گزینه. یک آدم `RELAY_WINDOW_MS` (۶۰ ثانیه) فرصت دارد؛ پس از آن
کنسول با یک قاعده‌ی رله پاسخ می‌دهد، وگرنه با تنها گزینه‌ی `(Recommended)`، وگرنه با گزینه‌ی اول
(`phase.question-answered`)، به نشست می‌گوید کسی پاسخ نداد و این تغییری در فاز نیست، و یک حکم اضافه می‌کند.
قاعده‌های رله در Settings ▸ Automation ▸ Policy answers ▸ **Relay rules** هستند (`relayRules`؛ هیچ‌کدام از
پیش عرضه نشده، حداکثر ۵۰): یک glob روی کلیدِ پرسش، ابزار (`AskUserQuestion` مگر نامِ دیگری بیاید)، پروفایلِ
اجرا (`*` برای هر پروفایل) و گزینه‌ای که باید پاسخ داده شود، که دقیقاً یا به‌عنوانِ پیشوندی یکتا منطبق
می‌شود. پرسشی که رله با قاعده پاسخ نمی‌دهد — `QUESTION_EXCLUSIONS` (`deny-list`، `multi-select`،
`destructive-option`، `run-stopped`، `repeated-key`)، یا پرسشی فراتر از `RELAY_QUESTIONS_PER_PHASE` (۸) در
یک فاز — فاز را `needs-human` پارک می‌کند و پوشِ *A question needs you* می‌فرستد.

هر نشستِ Claude که هوک گزارشش را می‌دهد — نشستِ agent، `claude`ای که خودتان در ترمینال باز کرده‌اید، و از ۵.۰.۰
یک لِینِ اتوپایلوت — کانالِ دومی دارد: هوکِ سراسریِ نشست رویدادهای `Notification`ِ CLI را می‌فرستد، پس نشستی که
پشتِ یک پرسشِ مجوز یا یک elicitation مانده به‌صورتِ **Session ask** در **Needs you**ِ زنگ، در فهرستِ Sessions و
به‌صورتِ پوش (**Session waiting on you**) دیده می‌شود؛ لِینی که همین حالا کارتی برای فازش در انتظار دارد دو بار
پوش نمی‌شود (`sessions.ask-suppressed`). ردیفی که به لِینی از همین کنسول گره خورده همان‌جا پاسخ می‌گیرد —
**Answer it** لِین را با کلماتِ شما steer می‌کند؛ برای هر نشستِ دیگری ردیف می‌گوید به ترمینالی بروید که نشست در
آن اجرا می‌شود، چون کنسول نمی‌تواند به‌جایش پاسخ دهد. ثبت‌نامه هر اپیزود را به‌صورتِ `lastWait`ِ نشست نگه
می‌دارد (`answered`، `ended` یا `unanswered`) و اپیزودی را که کسی جوابش نداده پس از `WAIT_ANSWER_CAP_MS` (۶۰
دقیقه) می‌بندد.

### چیزی که درمان‌گر اول می‌خواند: وضعیت (situation)

از ۲.۳.۰ به بعد، درمان‌گرِ بی‌مراقب (و *Why is this not done?*ِ یک فاز، در جزئیاتش) دیگر درمان را
فقط از روی نوع توقف (halt kind) انتخاب نمی‌کند. هر فاز باز از روی شواهدی که همین حالا وجود دارند
— خط تخته، وضعیت و متن Outstanding هندآف، رکورد و توقف اجرا، قفل، درخت کاری مخزن‌هایی که فاز
نام برده، گیت، QA، MCP و سلامت طرح — در یک **وضعیت** دسته‌بندی می‌شود
(`viewer/shared/situation-model.js`: `never-started`، `work-in-progress`، `done-unrecorded`،
`verify-red`، `blocked-declared:<lock|permission|credential|gate|external|unknown>`، `waiting-external`،
`gated-manual`، `plan-broken` (`lint`، `unreadable`، `verification`، `issue`)، `mcp-unavailable`، `resource-wall:<usage|auth|budget|model>`،
`foreign-live`، `foreign-stale`، `qa-pending`، `qa-failed`، `superseded`، `unknown`). سپس یک
**نردبان درمان** (`server/runner/ladder.ts`) پلهٔ بعدی را برای آن وضعیت نام می‌برد — هرگز یک پله
دو بار روی یک فاز، و محدود به ازای فاز / اجرا / روز هم به تعداد تلاش و هم به **دلار**
(Settings ▸ Automation: `ladderPerPhaseRungs` ۳، `ladderPerPhaseUsd` ۱۰۰، `ladderPerRunRungs` ۱۰،
`ladderPerRunUsd` ۴۰۰، `ladderPerDayUsd` ۶۰۰) — و وقتی نردبان تمام شد، فاز یک **Errand** با خود
دارد: چه چیزی لازم است، چطور بدهید، چه چیزهایی قبلاً امتحان شده. ژورنال `phase.situation`،
`phase.rung` و `phase.errand` را ثبت می‌کند. خودِ جدول پله‌ها
`viewer/shared/ladder-model.js` است — که نردبان سرور، کلاینت و تست‌ها آن را با همان هویت import
می‌کنند — پس آنچه اتوپایلوت بالا می‌رود همان چیزی است که هر گروه **Ways forward** نشان می‌دهد: چیپ
وضعیت، پله‌هایی که امتحان شده با نتیجهٔ هرکدام، پلهٔ بعدی، و وقتی نردبان تمام شد، همان یک کارت errand
(چه لازم است، چطور بدهید، چه امتحان شده). **Your turn** فقط errandها، درخواست‌های مجوز و
ورودها را فهرست می‌کند — اجرای متوقفی که errand ندارد مالِ حلقه است که بالا برود، نه مالِ شما که به
آن زل بزنید؛ نمای اجرا errandهای یک اجرای پارک‌شده را کامل فهرست می‌کند؛ وقتی چیزی منتظرِ شما نیست، خانه‌ی
Runs می‌گوید حلقه دفعه‌ی بعد کِی خودش جاروب می‌کند (`GET /api/converge` و رویداد `run:converge`)، و هر گذری که
کاری بکند `run.converge` را روی همان اجرا در ژورنال می‌نویسد؛ و گروه‌های **The ladder** و **What it does by
itself** در Settings ▸ Automation سقف‌ها، تک‌افزایشِ بودجه، کلیدها، فاصلهٔ جاروب و ساعتِ پارکِ MCP را ویرایش می‌کنند.
مشخصات کامل — وضعیت‌ها، پله‌ها، محرک‌های هم‌گرایی، حضور، و آنچه هنوز کار آدم است — در
`docs/loop.md` است.

## نوبتِ شما — هر کاری که فقط از یک آدم برمی‌آید

هر چیزی که یک اجرا از یک آدم می‌خواهد به‌شکلِ یک **مورد** روی یک صفحه می‌رسد: `#/turn`، با عنوانِ *Your turn* و
روشن‌کنندهٔ Runs (`client/src/screens/turn/`، یک chunkِ تنبل که `check-dist` آن را با `data-turn-page` پیدا
می‌کند). نیمهٔ سروری `server/turn/` است؛ واژه‌هایش `shared/turn-model.js` (همزادِ bash: `scripts/turn.env`) و
`shared/guide-grammar.js` است، تنها parserِ راهنما که سرور و صفحه شریکش‌اند. `references/turn.md` طرفِ نشستِ همین
ماجراست.

**یک در به داخل، یک فهرست به بیرون.** هر منبعی از `raiseTurn` (`server/turn/index.ts`) می‌گذرد، تنها
فراخوانندهٔ `declareHumanStep`: بولتِ `Human step:` یک طرح، <span dir="ltr">`phase-outcome.sh … needs-human --step`</span>
یک نشست، یک errandِ آدمی، دیواری که یک نشست به آن خورد (`permission`)، اعتبارنامه‌ای گم‌شده (`secret-entry`،
اثبات‌شده با schemeِ دیده‌بانِ `credential:<id>` — `gh`، `claude`، `env:NAME`، `keychain:SERVICE` یا `file:PATH`،
که با حضورشان خوانده می‌شود و هرگز با مقدارشان)، سرورِ MCPای که زیرِ `require` در دسترس نیست (`mcp-login`) و
پرسشِ رله‌شده‌ای که هیچ قاعده‌ای جوابش نمی‌دهد (یک `decision` که گزینه‌هایش را نگه می‌دارد و گزینهٔ
`(Recommended)` را علامت‌دار). `GET /api/turn` پاسخِ `{round, headline, groups, handled, counts}` را می‌دهد: هر
ردیفِ صندوق که از یک آدم کاری می‌خواهد یک نمای `turn` دارد (`server/turn/fold.ts`) که مورد و رکوردی را که نگهش
می‌دارد نام می‌برد — دفترِ human-step، یا رکوردِ خودِ ردیف برای یک کارتِ تأیید، یک گیت، یک طرحِ نگه‌داشته، یک
پرسشِ QA، یک پرسشِ زندهٔ رله، یک person-check، یک ورود یا یک تعارض — و ردیف‌های یک مورد در یکی جمع می‌شوند.
ردیف‌های سلامت، قفل، ruling، سیاست و پیام در زنگ می‌مانند. `GET /api/turn/:id` یک مورد را توضیح می‌دهد (راهنما، تلاش‌ها، اینکه چرا مالِ یک آدم است) و
<span dir="ltr">`?seen=<ISO>`</span> آخرین نگاهِ آدم را می‌رساند.

**یک مورد می‌گوید چرا.** یکی از ده دلیل (`WHY_PERSON`: `permission`، `identity`، `secret`، `money`، `legal`،
`decision`، `physical`، `reach`، `third-party`، `reserved`)، مقید به آنچه نوعش اجازه می‌دهد (`KIND_REASONS`؛ موردی
که هیچ دلیلی نام نبرد دلیلِ پیش‌فرضِ نوعش را می‌گیرد، با علامتِ `inferred`)؛ یک راهنما (یک بندِ «چرا»،
`## Steps`، `## If it goes wrong`؛ حداکثر ۲۰ گام و ۲۴ کیلوبایت، فقط پیوندهای `http(s)`، هر خط از غربالِ رازها
گذشته)؛ و یک اثبات از یکی از انواعِ `PROOF_TYPES` (`probe`، `answer`، `judgement`، `attest`، `grant`). دفتر،
`human-steps.ndjson`، خط‌های نسخهٔ ۲ می‌نویسد و خط‌های نسخهٔ ۱ را با پیش‌فرض می‌خواند؛ human step هجده نوع و
یازده حالت دارد، که `permission` در میانِ نوع‌ها و `returned` و `declined` در میانِ حالت‌هاست. نگهبان (G1–G7) هم
در پیش‌بررسیِ اعلام و هم دوباره هنگام ورود اجرا می‌شود: دلیلی که نوع اجازه دهد؛ اثباتی، مگر پاسخ همان نتیجه باشد
(کدِ خروج ۲)؛ یک موردِ `permission` یا `reserved` اعلام‌شده که هر دستورش را سیاستِ خودِ اجرا اجازه می‌دهد، یک
`reach` بی‌`--tried`، و بلوکِ مجوزی که هیچ دیوارِ ثبت‌شده‌ای را نام نمی‌برد با کدِ خروج ۴ رد می‌شوند
(`GUARD_REFUSAL_EXIT`)؛ همان مورد که لِینِ دیگری اعلام کند یک مورد است با یک منتظرِ دیگر، و وقتی اثبات شد همهٔ
منتظرها ازسر گرفته می‌شوند.

**حرکت‌ها.** خواندن بی‌سوییچ است. هر فعل یک <span dir="ltr">`POST /api/human-steps/:id/<verb>`</span> است با
بررسیِ cross-site و منتسب به یک actor: `open` (روی ماشین پشتِ `--allow-terminal` یا `--allow-agent`، فقط پیوندِ
`http`/`https`)، `check`، `snooze`، `cannot`، `dismiss`، <span dir="ltr">`answer {option?, note?}`</span>،
<span dir="ltr">`decline {reason}`</span>، <span dir="ltr">`ask {text}`</span>،
<span dir="ltr">`evidence {kind, text | data, mime?, name?}`</span>، `override`، `rewrite`، `deny`، `convert` و `grant`.
`dismiss`، `answer`، `decline`، `override`، `rewrite`، `deny`، `convert`، `grant` و `check` (یک `attest` وقتی حرفِ
آدم همان اثبات است) ردیف‌های `AUTHORITY_ROUTES`‌اند، پس هیچ دَرِ نشستی نمی‌تواند آن‌ها را فشار دهد؛ `ask`
و `evidence` اقتداری ندارند، و خودِ route درِ یک ایجنت را روی آن‌ها رد می‌کند. `check` بدنه‌ای را که رازی داشته
باشد رد می‌کند و به‌جایش می‌گوید مقدار کجا می‌رود — آیتمِ keychainِ <span dir="ltr">`phase-console-<id>`</span> روی
macOS، یک فایلِ `0600` جای دیگر، یا جای `credential:`ِ خودِ مورد. هر پاسخ هر نشستِ منتظر را یک‌بار ازسر می‌گیرد،
با جمله‌ای که کنسول می‌سازد («The operator answered `<option>`: <note>»، «The operator declined: <reason>. Do not
ask again; …») و هر پرسشی را که آدم پرسیده با خود می‌برد؛ پاسخی که یک کلیدِ `## Decisions` را نام ببرد اول از
راهِ `decisions.sh` در جدولِ تصمیم‌های طرح نوشته می‌شود. مدرک یک یادداشت، یک تصویر یا یک فایل است — ۱۶۰ کیلوبایت
برای هر تکه، شش تا در هر تلاش، غربال‌شده برای رازها، با دسترسیِ `0600` و با هشِ محتوا در `turn-evidence/` (۳۰ روز،
۶۴ مگابایت: یک retention sink) و هرگز push یا ژورنال نمی‌شود.

**بررسی.** <span dir="ltr">*I've done this — check*</span> یک حکم می‌گیرد (`VERDICTS`): `passed`، `rejected` با
دقیقاً آنچه باید دوباره انجام شود، یا `needs-info`. یک probe — اثباتِ یک دستور — فوراً خوانده می‌شود؛ اثباتی که
فقط با کلمات می‌شود گفت را یک نشستِ بررسیِ کوتاه و فقط‌خواندنی برای همان یک مورد می‌خواند
(`server/turn/checker.ts`: حداکثر ۱۲ نوبت، ۰٫۵۰ دلار و پنج دقیقه؛ `checkModel` و `checkEffort`، `sonnet` با `low`،
و `checkJudgement` — خاموش، حرفِ آدم پذیرفته می‌شود و مورد «تأییدنشده» علامت می‌خورد — همه در Settings ▸
Automation)، که حکمش از آخرین بلوکِ fencedاش پارس می‌شود و هرگز ساخته نمی‌شود. هر تلاش مدرک و حکمِ خودش را نگه
می‌دارد؛ یک ردشدن یک‌بار به آدم می‌گوید چه چیزی را دوباره انجام دهد و هیچ‌چیز را ازسر نمی‌گیرد؛ یک قبولی هر
نشستِ منتظر را یک‌بار ازسر می‌گیرد و می‌گوید چه چیزی اثبات شد. پس از `turnEscalateAfter` ردشدن (۳) مورد یک‌بار
ارجاع می‌شود، با سه راهِ خروج: `…/rewrite`، *I can't*، یا `…/override` از مالک — *Accept anyway*، تنها routeای که
حکم می‌نویسد، که تأییدنشده ثبت می‌شود. داوری فقط بر آنچه آدم برای همان تلاش فرستاده می‌گذرد، و یک attest، یک
override یا یک rewrite فقط از راهِ دَرِ یک آدم حساب می‌شود. `phase_console_turn_checks_total` و
`phase_console_turn_check_usd_total` بررسی‌ها را می‌شمارند.

**دورها، و آنچه هوش مصنوعی رسیدگی کرد.** یک دور (`server/turn/round.ts`) یک گذر از ساعتِ human-step (یک دقیقه) و
از هر خطِ journalِ هر اجراست (با debounce دو ثانیه). اجازه‌هایی را که تمام شده‌اند پایان می‌دهد، یادآوری‌های
سررسیده را می‌فرستد، موردی را که کسی به آن نیاز ندارد کنار می‌گذارد و پنجره‌ای را که بسته شده منقضی می‌کند،
موردی را که یک اجازهٔ زنده اکنون می‌پوشاندش کنار می‌گذارد و منتظرهایش را ازسر می‌گیرد، موردی را که
`turnEscalateAfter` بار برگشته و هنوز ارجاع نشده ارجاع می‌دهد، کاری را که موعدش در راه بود با یک push سررسید
می‌کند، و اثبات‌های بازی را که کنسول صاحبشان است می‌خواند (راه‌اندازیِ خودِ کنسول، `credential:<id>` هم، با
back-offش) و آنکه نشسته را اثبات‌شده می‌کند. هرگز اثباتِ `cmd:` یا `unit:` را اجرا نمی‌کند، و آنچه ازسر
می‌گیرد از دَرِ خودِ کنسول می‌گذرد، فقط جایی که `--allow-run` اجازه دهد. دوری که turn را عوض کرد
`round.n` را بالا می‌برد و یک server-sent event، `turn`، می‌فرستد؛ دورِ آرام چیزی را عوض نمی‌کند. تیتر
(`server/turn/headline.ts`) با قاعده ساخته می‌شود، هرگز با مدل. *Handled by the AI* از `handled.ndjson`
(`server/turn/handled.ts`، یک retention sink) می‌خواند: آنچه نگهبان از پرسیدنش خودداری کرد (G4، G5)، آنچه جدولِ
قاعده‌ها اجازه داد (یک ردیف برای هر قاعده در هر فاز، با شمار)، پاسخ‌های رله به قاعده و بازیابی‌های نردبان،
هرکدام با پیوند به خطِ journalی که آن را می‌گوید. یک نشست موردِ خودش را با
<span dir="ltr">`phase-outcome.sh <slug> <N> handled --what … [--note …] [--link …]`</span> می‌افزاید — هرگز یک
outcome نیست، پیوندهایش به یک commit، یک pull request، یک issue یا یک خطِ journal مقید است، غربالِ رازها روی هر
فیلد — در `handled-sessions.ndjson`، که هر خطش به‌نامِ نشست خوانده می‌شود، پس یک نشست هرگز نمی‌تواند به‌جای
نگهبان یا جدولِ قاعده‌ها حرف بزند. `phase_console_turn_rounds_total` و `phase_console_turn_handled_total` آن‌ها را
می‌شمارند.

**درخواست‌های مجوز، و اجازه‌ها.** هر دیواری که یک نشست به آن می‌خورد روی لِینش ثبت می‌شود
(`server/permissions/walls.ts`): یک قاعده‌ی deny، هر نگهبانِ hookِ خودِ کنسول، ردِ خودِ CLI، و یک pushِ فرودِ
ردشده به‌شکلِ قابلیتی که خاموش است. `blocked --needs permission`ای که یکی از آن‌ها را نام ببرد یک موردِ
`permission` می‌سازد؛ آنکه چیزِ ثبت‌شده‌ای نام نبرد همان دم رد می‌شود (G5). یک اجازه
(`server/permissions/grants.ts`، <span dir="ltr">`POST /api/human-steps/:id/grant`</span>) به آن پاسخ می‌دهد، در یکی
از پنج گستره (`GRANT_SCOPES`): `call`، یک بار استفاده، در دفتر نگه‌داشته می‌شود و با استفاده تمام می‌شود؛
`phase`، تا وقتی فاز تسویه شود، حداکثر ۲۴ ساعت؛ `plan`، فایلِ سیاستِ طرح؛ `repository`،
`~/.config/phase-console/repositories/<instance>.json`، میانِ فایلِ طرح و فایلِ ماشین؛ `always`، فایلِ ماشین.
زیرِ گستره‌ی طرح، hookِ کنسول اجازه را دقیقاً برای همان لِین، همان قاعده و (برای `call`) همان فراخوان اعمال
می‌کند، و تنظیماتِ اجرا قاعده را فقط برای همان اجرا پایین‌آمده نگه می‌دارند و پس از پایان دوباره بالا می‌برند —
پس تا آن وقت فهرستِ خودِ CLI با کنسولِ خاموش آن را نگه نمی‌دارد. ریسک از یک جدولِ کلِ واحد می‌آید، `GRANT_RISK`
(دیوار × خانوادهٔ قاعده × گستره): کم‌خطر و میان‌خطر یک فشارند؛ پرخطر می‌خواهد قاعده دوباره تایپ شود، شعاعِ
اثرش را نشان می‌دهد (یک ۴۰۰ با `{rule, blast}` آن را می‌رساند) و، روی کنسولی که کلیدِ مالک دارد، لمسِ کلید در پنج
دقیقهٔ اخیر؛ فهرستِ «هرگز» — push اجباری یا حذف‌کننده، خانوادهٔ میزبان (`sudo`، `shutdown`، `reboot`، `mkfs`،
`dd`)، هر نگهبان، مسیرِ محافظت‌شده، مقدارِ یک راز، اعتبارنامهٔ گم‌شده، دیوارِ sandbox یا شبکه و طبقه‌بندِ خودِ
Claude Code — از هیچ دری اجازه‌ای پیشنهاد نمی‌کند، و یک قابلیت فقط روی خودِ ماشین اجازه داده می‌شود، هرگز از
یک گوشی. موتور بسته شکست می‌خورد: خودش کلیدِ مالک را می‌خواند، پس اجازهٔ پرخطری که فشارش لمسِ تازه
را ثابت نکرده رد می‌شود، Allowِ یک کارت هم. زیرِ دیوارِ push برداشته‌شده، یک push فقط از راهِ یک allow-list
می‌گذرد، پس پرچمِ مخفف‌شده، پیکربندی پیش از فعل، refspecِ اجباری، گزینه‌ای که برنامه‌ای اجرا می‌کند یا آرگومان‌های
`xargs` مثلِ push اجباری خوانده می‌شوند. نشستِ منتظر خودش ادامه می‌دهد («The operator granted `<rule>` for
<scope> until <end> — run it again»)، و موردِ بازی که اجازه‌ای بعدی می‌پوشاندش خودش کنار می‌رود.
`grants.ndjson` فقط‌افزودنی و `0600` است (یک retention sink که هیچ اجازهٔ زنده‌ای را به چرخش نمی‌بازد): یک خطِ
`grant` — چه کسی، از کدام در، مورد، دیوار، قاعده، گستره، پایان و دقیقاً چه چیزی را تغییر داد — و یک خطِ `end`
وقتی تمام می‌شود، منقضی می‌شود یا revoke می‌شود. یک اجازه ژورنال می‌شود (`policy.grant-applied`،
`policy.grant-ended`) و در دستهٔ push به نام `granted` اعلام می‌شود؛ `GET /api/permissions/grants`،
<span dir="ltr">`POST /api/permissions/grants/:id/revoke`</span>،
<span dir="ltr">`POST /api/permissions/grants/revoke-all`</span> و
<span dir="ltr">`phase-console grants list|revoke|revoke-all`</span> سرویسشان می‌دهند، و یک revoke دقیقاً آنچه
ردیف می‌گوید را برمی‌گرداند.

**چه کسی فشار داد: درها، و کلیدِ مالک.** هر درخواست یک در دارد که با آنچه می‌تواند ثابت کند تعیین می‌شود و
هرگز با آنچه بدنه‌اش می‌گوید (`server/owner/door.ts`، `PRESS_DOORS` در `shared/door-model.js`): `owner` (کلیدِ
مالکی که در این مرورگر تأیید شده)، `device` (ورودی که پروکسیِ `--remote` تأیید کرد، یا یک کنشِ امضاشدهٔ صفحهٔ
قفل)، `local` (درخواستی loopback با سرصفحهٔ کنسول و هیچ‌چیز بیشتر) و `session` (توکنِ یک اجرا)؛ نوشتن‌های خودِ کنسول دو در
دیگر دارند، `checker` (نشستِ بررسی، برای مورد خودش) و `console` (ساعت‌های خودش). `by` فقط یک برچسب است؛ هر فشار
`pressDoor` را کنارش ثبت می‌کند. `DOOR_MAY`، که با `doorMay` خوانده می‌شود، جدولِ در × فعلِ اقتدار × ریسک در دو حالت است، و
`ownerDoor`ِ `GET /api/state` می‌گوید `unenrolled`، `enrolled` یا `unlocked`. `AUTHORITY_ROUTES` هر routeِ اقتدار
را نام می‌برد و از هر دو سو نگه داشته می‌شود: routeای که یک متدِ اقتدار را فشار دهد و ردیفی نداشته باشد suite را
رد می‌کند و خطش را نام می‌برد. درخواستی که توکنِ یک نشست دارد هیچ routeِ اقتداری را که ردیفِ
`permission.destructive` طرح نامش نبرده فشار نمی‌دهد: بی‌کلیدِ مالک پیش از اجرای هر route با ۴۰۳ رد می‌شود و
`owner.door-refused` لاگ می‌شود، با کلید مثلِ هر دری دیگر به‌شکلِ یک درخواست ثبت می‌شود، و routeهای کلیدِ مالک در
هر دو حالت دَرِ یک ایجنت را رد می‌کنند. آزمونِ «آدم»ِ یک گیتِ دستی یک در است (`owner` یا `device`، و `local` بی‌کلید)،
نه یک User-Agent. کلیدِ مالک یک passkey است، WebAuthn که با دست و با `node:crypto` تأیید می‌شود (attestation از
نوعِ `none`، ES256 یا EdDSA، تأییدِ هویتِ کاربر الزامی، یک challenge یک‌بارمصرف با اعتبار پنج دقیقه، origin و
relying party از Hostِ خودِ درخواست — `localhost` یا یک میزبانِ https که کنسول سرو می‌کند، هرگز یک IP — و
شمارنده‌ی امضایی که هرگز عقب نمی‌رود). routeهایش، در هر دو نسخه و پشتِ هیچ پرچم قابلیتی: `GET /api/owner`،
<span dir="ltr">`POST /api/owner/enroll/link|begin|finish`</span>،
<span dir="ltr">`POST /api/owner/assert/begin|finish`</span>، `POST /api/owner/lock`، `DELETE /api/owner/keys/:id` و
<span dir="ltr">`POST /api/owner/requests/:id/confirm|refuse`</span>. کلیدِ اول روی خودِ ماشین از پیوندی ثبت می‌شود
که <span dir="ltr">`phase-console owner enroll`</span> چاپ می‌کند (ده دقیقه اعتبار)؛ ورودش یک نشستِ مالک باز
می‌کند که پس از دوازده ساعت بی‌کاری تمام می‌شود (کوکیِ ۲۵۶ بیتی با `HttpOnly` و `SameSite=Strict`، با `__Host-` روی https، که فقط هشش نگه
داشته می‌شود)؛ فشارِ پرخطر لمسی در پنج دقیقهٔ اخیر می‌خواهد؛ کلیدِ بعدی و حذف فقط درونِ یک نشستِ مالک می‌شوند، و
هر تغییر ژورنال می‌شود، به هر دستگاهِ مشترک push می‌شود و یک هفته در زنگ می‌ماند. با داشتنِ کلید، فشارِ اقتدار از
هر درِ دیگر به‌شکلِ یک درخواست (۲۰۲) ثبت می‌شود، روی مورد با عنوانِ «asked by <label> — confirm?» نشان داده می‌شود و
فقط وقتی مالک تأیید کند از درِ مالک فشار داده می‌شود؛ آنچه مانیفستِ طرح از پیش اجازه داده همچنان اجرا می‌شود، و
کنسولِ بی‌کلید مثلِ قبل رفتار می‌کند. `owner-doors.json`، `owner-sessions.json` و `owner-requests.json` همه `0600`‌اند
و رازی ندارند. خطرِ باقی‌مانده، کامل: فرایندی که با نامِ شما اجرا می‌شود و عمداً فایل‌های خودِ کنسول را بازنویسی
می‌کند می‌تواند هر چیزی را که زیرِ کلیدِ مالک است جعل کند، و می‌تواند خودِ دفترِ کلیدها را عوض کند؛ کنسول
مسیرهایی را که یک نشست می‌رود دیوار می‌کشد و هر اجازه را دیدنی می‌کند، و مرزی در برابرِ حسابِ کاربریِ خودتان
نیست.

**صفحه، و کارت‌های قدیمی.** شش بخش به ترتیبی ثابت (`TURN_GROUPS`: *Do now*، *Needs one detail from you*، *Coming up*،
*Being checked*، *Done*، و بعد *Handled by the AI*). هر مورد یک کارت است — چرا فقط شما، طرح و فاز و اجرا، آنچه باز
می‌کند با شمارشِ معکوس، چقدر طول می‌کشد، راهنمایش به‌شکلِ ایستگاه‌هایی روی یک خط (تیکِ هر گام در مرورگر می‌ماند)،
هر دستور قابلِ کپی همان‌طور که هست و پشتِ <span dir="ltr">`!`</span> برای نشستِ Claude Codeِ خودتان و هرگز اجراشده
توسط صفحه، اینکه چگونه بررسی می‌شود، و یک کنشِ اصلی که نوع و حالتش انتخاب می‌کند. فیلترها و جست‌وجو در نشانی
می‌مانند؛ زیرِ **⋯**، **Export as Markdown** موردهای باز را در یک سند دانلود می‌کند و **Print** آن را چاپ می‌کند؛
**Inspect** یک مورد را در پنل می‌گذارد؛ و یک راهنما زبانش
را با خود دارد (راهنمای فارسی راست‌به‌چپ کشیده می‌شود، دستورهایش چپ‌به‌راست). `#/approve` و
<span dir="ltr">`#/approve?step=<id>`</span> در یک جهش روی صفحه می‌نشینند و یک push روی
<span dir="ltr">`#/turn/<id>`</span> باز می‌شود. صفِ تأییدها، کارتِ پرسشش، کارتِ گیت و کارتِ errand هرکدام همین مورد
را می‌کشند — یک ردیف، نشانِ نوع، عنوان، کنشِ اصلی که دقیقاً به همان شکلی فشار داده می‌شود که سرور نوشته، و *Open
on Your turn* — و گیتی که از هیچ اجرایی پرسیده نمی‌شود Approve خودِ طرح را نگه می‌دارد (`gate-status.md`). درِ
راه‌اندازی موردهای اجرا را فهرست می‌کند، و گامِ طرحی که با `auto-open: host` علامت خورده هنگام راه‌اندازی باز
می‌شود، روی ماشین، پشتِ `--allow-terminal` یا `--allow-agent`، فقط پیوندِ `http`/`https`، پس از اینکه در آن را
کامل نشان داده باشد.


## نشست‌ها، و آن دو نشستی که کنسول برایتان می‌سازد

نشست‌های ایجنت و شل‌ها پروسه‌هایی روی همین ماشین‌اند، نه چیزی داخلِ یک تب. بستنِ مرورگر فقط سوکت را جدا
می‌کند و کار ادامه پیدا می‌کند؛ با باز کردنِ دوباره، با همه‌ی scrollback به آن وصل می‌شوید. هیچ نشستی
به‌خاطرِ بیکاری جمع نمی‌شود — **یک نشست وقتی تمام می‌شود که شما تمامش کنید، نه وقتی کنسول تمام
می‌شود** — و سقفِ ۸ تا فقط پروسه‌های زنده را می‌شمارد، پس نشست‌های تمام‌شده جای نشستِ تازه را
نمی‌گیرند. نشستی که خارج شده با وضعیتِ خروج و `claude --resume <id>` خودش در فهرست می‌مانَد تا وقتی
رَدش کنید، یا تا ۲۴ ساعت.

**ptyها به یک بروکر تعلق دارند، نه به وب‌سرور.** پیش‌تر `service.close()` به هر pty می‌رسید و
تمامش می‌کرد، پس زدنِ Restart هر شل و هر `claude` تعاملی روی ماشین را تمام می‌کرد — از جمله ساعت‌ها
کار — و هیچ خطایی هم پرتاب نمی‌شد؛ کار فقط متوقف می‌شد. یک پروسه را نمی‌شود بعد از تولد به والدِ
دیگری سپرد، پس حالا از جای دیگری شروع می‌شود. `server/pty/broker.ts` جدا (detached)، بدون stdio و
با unref بالا می‌آید — همان سه واژه‌ای که `lifecycle.ts` از پیش برای زنده‌ماندن پس از
برای همین به کار می‌برد — و مالکِ ptyها و scrollback است. کنسول فقط کلاینتِ اوست: یک سوکتِ
یونیکسِ `0600` زیرِ `INSTANCE_STATE_DIR`، یک اعتبارنامه هنگام اتصال، و همان دیوارِ بلیت، پروتکلِ
فریم، محدودکردنِ resize، فشارِ برگشتی و نگه‌داشتی که `Terminals` همیشه داشت. فقط مالکیت جابه‌جا شد.
`resume()` هرچه کنسولِ قبلی زنده گذاشته را به فرزندی می‌گیرد، با **شناسهٔ نشستِ بروکر به‌عنوانِ
شناسهٔ کنسول**، پس `#/sessions/<id>` بعد از راه‌اندازیِ دوباره هم به همان‌جا می‌رسد.

سه نکته که پیش از دست‌زدن به این بخش باید دانست:

- **`Terminals.close()` دیگر نمی‌کُشد، و تنها نگهبانش این است که spawn تزریق شده باشد یا نه.** تستی
  که `options.spawn` خودش را می‌دهد مالکِ ptyهایش است و همچنان کشته می‌شوند؛ ptyهای یک کنسولِ واقعی
  مالِ بروکرند و رها می‌شوند. این تصمیم را عوض کنید و باز یک راه‌اندازیِ دوباره کارِ اپراتور را نابود
  می‌کند — `pty-broker.test.ts` دقیقاً با همین جمله آن را قرمز اثبات می‌کند.
- **خاموشیِ عمدی هم نشست‌ها را نگه می‌دارد**، نه فقط راه‌اندازیِ دوباره: هر دو از `service.close()`
  می‌گذرند. و این کرانه‌دار است نه ابدی — بروکری که نشست دارد بازنشسته نمی‌شود و به‌محضِ پایانِ آخرین
  نشست خارج می‌شود. هر دو دیالوگ `sessionInventory().survives` را می‌خوانند و بازماندگان را زیرِ
  *«این‌ها روشن می‌مانند»* فهرست می‌کنند، چون ادعای متوقف‌کردنِ نشستی که متوقف نمی‌شود همان نقصی است
  که جایش را گرفت.
- **بروکر چیزی از برچسب، نوع یا شناسهٔ `--resume` نمی‌داند.** این‌ها به‌صورتِ یک بلوبِ مبهم سفر
  می‌کنند که او فقط نگه می‌دارد و پس می‌دهد، و همین است که به کنسولی که هرگز آن نشست را ندیده اجازه
  می‌دهد کلِ رکورد را بازبسازد. از `log.ts` هم استفاده نمی‌کند (چون به `config.ts` می‌رسید و نمونه را
  دوباره حل می‌کرد)؛ NDJSONِ کران‌دار در `pty-broker.log` کنارِ سوکتش می‌نویسد — وقتی ترمینالی بدرفتاری
  کرد، **اول همان را بخوانید**.

**حضور نشست — هوک.** کنسول نشست‌هایی را هم می‌شناسد که خودش شروع نکرده. یک هوک Claude Code در سطح
کاربر (`scripts/session-hook.sh`؛ از Settings ▸ Automation ▸ Session presence یا با `phase-console install-hooks` /
`uninstall-hooks` / `hooks-status` نصب می‌شود؛ چهار مدخل را در `~/.claude/settings.json` ادغام می‌کند و به
هیچ کلید دیگری دست نمی‌زند) هر نشست Claude روی این ماشین را که پوشهٔ کاری‌اش متعلق به یک کنسول است —
شروع، پایان هر نوبت، اعلانی که نشست پشتش می‌ایستد (Notification)، پایان نشست — به همان کنسول گزارش می‌دهد (`POST /hooks/session`، فقط از خود ماشین)
و وقتی کنسول خاموش است، در صندوق ورودی نمونه می‌گذارد. ثبت‌نامه (`GET /api/sessions/registry` و فهرستِ
Sessions) آن‌ها را با حضور سه‌حالته نشان می‌دهد: *زنده*، *پایان‌یافته*، *نامعلوم*. قفل فازی که نشستش را
نام برده (`phase-lock.sh --session`، یا `PE_SESSION_ID` که اجراگر صادر می‌کند) به محض پایان آن نشست
زباله می‌شود — زمان‌بند فاز پشت صف را می‌پذیرد و حلقهٔ همگرایی فایل را آزاد می‌کند — نه در پایان اجاره؛
قفل یک نشست زنده صفی است برای انتظار؛ و قفلی که کسی گزارشش نمی‌دهد با قواعد اجاره می‌ماند. و
`phase-outcome.sh` که در نشستی بدون ناظر اجرا شود (بدون `PE_OUTCOME_FILE`) در
`runs/<instance>/<slug>/outcomes/` می‌نشیند و کنسول آن را برمی‌دارد: یک `waiting-external` فاز را
پارک می‌کند و همان نشست را سرِ موعد از سر می‌گیرد، یک `partial` آن را دوباره با ازسرگیری سوار می‌کند.
به‌طور پیش‌فرض خاموش است — نصب هوک انتخاب اپراتور است.

حضور ادعایی است که کنسول آن را در برابرِ خودِ پروسه تسویه می‌کند: پایانی که هوک گزارش داده
`endedBy: 'hook'` است، و پایانی که پروب پیدا کرده — پروسه رفته و هیچ `SessionEnd`ی نیامده —
`endedBy: 'probe'` است، با تاریخِ آخرین نشانه‌ی زندگی، و به‌صورتِ `ended · inferred` نشان داده می‌شود.
پروب‌های خودِ کنسول (سلامتِ MCP، دسترسیِ حساب) با `PE_SESSION_KIND=probe` اجرا می‌شوند و هوک برای آن‌ها
هیچ نشستی ثبت نمی‌کند — پروب نشست نیست (#73). وقتی هیچ کنسولی بالا نیست، رویدادهای هوک در صندوقِ همان نمونه منتظر می‌مانند، و
`phase-console sessions ingest [instance]` آن‌ها را با دست تخلیه می‌کند — تا وقتی کنسولِ خودِ آن نمونه پاسخ
می‌دهد کاری نمی‌کند، و خودِ هوک هم پس از POSTی که نرسید اجرایش می‌کند — رویدادِ قدیمی‌تر از ۱۰ دقیقه را
به‌عنوانِ تاریخچه اعمال می‌کند (بی پوش و بی واکنش به قفل)، رویدادِ قدیمی‌تر از ۷ روز را رد می‌کند، و
`sessions/inbox.lock` را می‌گیرد تا دو تخلیه با هم مسابقه ندهند. نشستی که یک اجرا راه انداخته هم روی
نشانگرهایش دری را که از آن آمده و اینکه چه چیزی با چه هزینه‌ای تمامش کرد نشان می‌دهد.

**و هر نشستِ گزارش‌شده ترمینالی است که می‌توانید بازش کنید.** فهرست پیش‌تر فقط می‌توانست بگوید یک
نشستِ بیگانه *وجود دارد*: ردیف هیچ شناسه‌ای نمی‌ساخت، پس `#/sessions/<id>` به هیچ‌جا نمی‌رسید. حالا
ردیفِ بیگانه گفت‌وگوی (CONVERSATION) خودش را حمل می‌کند — جدا از `id` که یک ptyِ متعلق به همین کنسول
است و می‌تواند بسته شود، و همان چیزی است که وجود یا نبودِ دکمهٔ Close را تعیین می‌کند — و آدرس در سه
گام حل می‌شود: یک pty، سپس ptyای که همین گفت‌وگو را در حالِ **ازسرگیری** است، سپس رکوردِ ثبت‌نامه، و
تنها آن‌گاه «رفته». کاری که صفحه نمی‌کند وانمودکردن است: هیچ‌چیز به ترمینالی که کسِ دیگری در آن تایپ
می‌کند نمی‌چسبد، چون اینجا multiplexer وجود ندارد. پس نشستِ `ended` یک Resume ساده می‌گیرد و نشستِ
`live` (یا `unknown` که زنده خوانده می‌شود) یک Take over پشتِ تأییدی که می‌گوید یک `claude` دوم به
همان گفت‌وگو می‌پیوندد و آنکه می‌بینید همچنان روشن می‌مانَد. بدونِ `--allow-agent` این کنش پیشنهاد
نمی‌شود و صفحه نامِ سوییچ را می‌گوید.

ازسرگیری در همان پوشه‌ای شروع می‌شود که **ثبت‌نامه** می‌گوید نشست در آن کار می‌کرده، و این اندازه‌گیری
شده است نه فرض: `claude --resume <uuid>` یک گفت‌وگو را **سراسری** حل می‌کند، پس ازسرگیری از ریشهٔ
کنسول شکست نمی‌خورد — در مخزنِ اشتباه موفق می‌شود، با مسیرهای نسبیِ دیگر، مخزنِ گیتِ دیگر و
`CLAUDE.md`ِ پروژه‌ای دیگر، و هیچ‌کس هم چیزی نمی‌گوید. مرورگر فقط یک شناسه می‌فرستد؛ سرور رکورد را
می‌خوانَد، دقیقاً همان‌طور که برای recovery، review و account می‌کند.

همین `cwd`ِ رکورد را به یک **پارامترِ spawn** تبدیل می‌کند، و `POST /hooks/session` عمداً از بررسیِ
هدرِ کنسول و Origin معاف است — یک اسکریپتِ شل تغذیه‌اش می‌کند، نه مرورگر — که همین آن را به‌صورتِ یک
درخواستِ سادهٔ cross-origin هم دست‌یافتنی می‌کند. خودِ mint در برابر CSRF محافظت شده، پس حمله به یک
کلیکِ واقعی نیاز دارد و نگهبان هم سرِ همان کلیک می‌نشیند: پوشه‌ای بیرون از ریشهٔ باز و پوشه‌های اخیر
تأیید می‌خواهد، **حتی برای نشستی که پایان یافته**، و مسیر را جلوی چشمِ کلیک‌کننده می‌گذارد. تطبیق پس
از نرمال‌سازی و روی مرزِ مسیر انجام می‌شود، و `cwd`ای که از پیش در فرمِ نرمال نباشد به همین دلیل
ناآشنا است — رکوردی که هوکِ شل می‌نویسد `$PWD` را حمل می‌کند و هرگز قطعهٔ `.` یا `..` ندارد، پس تنها
چیزی که نانرمال می‌رسد چیزی است که می‌خواهد جای دیگری به‌نظر برسد. (`/repo/../../tmp/evil` با
`/repo/` شروع می‌شود؛ نسخهٔ اولِ همین نگهبان آن را آشنا خواند، در حالی که سرور حلش می‌کرد و در
`/tmp/evil` اجرا می‌شد.) صفحه همچنان همان رشته‌ای را نشان می‌دهد که رکورد دارد — نمایشِ مسیرِ
مرتب‌شده‌ای که در رکورد نیست دقیقاً همین را پنهان می‌کرد.

دو نوعش به‌جای اینکه تایپ شوند، برایتان ساخته می‌شوند:

**Recovery.** هر شکلی که یک اجرا در آن متوقف می‌شود، نشستی دارد که جوابش است — راستی‌آزماییِ شکست‌خورده،
فازی که کارش را کرده ولی هندآف ننوشته، اجرای نیمه‌کاره، اجرایی که پشتِ ورود به حساب مانده، ادعای منقضی، و
طرحی که parse نمی‌شود. **پرامپت را سرور می‌سازد** — خودش تابلو، اجرا، تشخیصِ فاز، قفل و مشکلاتِ سلامت را
می‌خواند؛ مرورگر فقط می‌گوید هدف کدام است، و همین هم ویژگیِ امنیتی است و هم ویژگیِ صادقانه‌اش. وقتی
اتوپایلوت در حالِ راندن است رد می‌کند، برای یک فاز دو recoveryِ هم‌زمان نمی‌سازد (به‌جایش لینکِ نشستِ زنده
را می‌دهد)، و موقعِ خروج تابلو را دوباره از دیسک می‌خواند تا بگوید فاز واقعاً سبز شد یا نه.

**Review.** هر فازِ تمام‌شده را می‌شود به یک نشستِ تازه برای QA سپرد. بریفِ آن، خودِ
`phase-graph.sh --qa-prompt N`ِ اسکیل است — کلمه‌به‌کلمه — به‌علاوه‌ی آنچه موتور نمی‌تواند بداند: هندآفی که
آن فاز نوشته، فایل‌های کلیدی‌اش، کامیت‌هایی که به آن خورده‌اند، و معیارهای خروج و راستی‌آزماییِ همان فاز،
عیناً نقل‌شده و نه خلاصه‌شده. این نشست، نشستی که خودِ فاز را ساخته resume نمی‌کند، وقتی اتوپایلوت می‌رانَد
اجرا نمی‌شود، وقتی نشستی هنوز دارد آن فاز را می‌سازد اجرا نمی‌شود، و برای یک فاز دوبار شروع نمی‌شود.
**حکم را خودِ نشست با `qa-record.sh` ثبت می‌کند؛ کنسول فقط آن را پس می‌خوانَد** — موقعِ خروج
`test-status.md` دوباره خوانده و با عکسی که موقعِ شروع گرفته شده مقایسه می‌شود، پس نشستی که بدون ثبتِ حکم
تمام شده، دقیقاً همین‌طور گزارش می‌شود.

هر دو روی `POST /api/terminal` و پشتِ `--allow-agent` سوارند؛ هیچ‌کدام مسیرِ تازه‌ای اضافه نمی‌کند، و
پرامپتی بزرگ‌تر از `MAX_AGENT_PROMPT_BYTES` (۳۲ کیلوبایت) — تایپ‌شده یا ساخته‌شده — با 400 رد می‌شود.
`permissionProfile` (`guarded` | `bypass`) **فقط** با یک review پذیرفته می‌شود و روی هر نشستِ ایجنتِ دیگری
رد می‌شود. روشن‌کردنِ QA برای یک طرح (`POST /api/plans/:slug/qa-mode` با `--allow-writes`) از مسیرِ `--qa`ِ
خودِ اسکیل می‌گذرد، که فازهای تمام‌شده را waived می‌کند به‌جای اینکه پشتِ گیت نگه‌شان دارد.

## قانونی که دنبال می‌کند

`phase-graph.sh` تنها منبعِ حقیقت است برای **done / ready / waiting**، دسته‌بندیِ نشست‌ها،
بوت‌پرامپت‌ها، رژیم QA و lint. کنسول برای همه‌ی این‌ها به اسکریپت‌های خودِ اسکیل shell out می‌کند و
هیچ‌کدام را دوباره حساب نمی‌کند. پارسِ جاوااسکریپتی فقط چیزی را پوشش می‌دهد که اسکریپت‌ها بیرون نمی‌دهند
— بخش‌های متنی، جزئیات فاز، متنِ هندآف‌ها — به‌علاوه‌ی تحلیل‌هایی که آن‌ها ارائه نمی‌دهند (مسیر بحرانی،
ارزشِ بازکنندگی، سرعت پیشرفت). فایلِ `test/engine-parity.test.ts` تابلوی هر طرح را دوباره از روی پارسِ
جاوااسکریپتی می‌سازد و ادعا می‌کند که با موتور یکی است، تا این دو خوانش نتوانند بی‌سروصدا از هم فاصله
بگیرند.

**یک پروسه یک واقعیت است؛ یک رکورد یک ادعا — پس ادعا را در برابرِ واقعیت تسویه کنید.** یک‌بار نشستِ
فاز ۹ از کنسولی که آن را ساخته بود عمرِ بیشتری کرد، سه ساعت‌ونیم متوقف (stopped) ماند در حالی که
session id و قفلش را نگه داشته بود، و رکوردِ ران در تمامِ آن مدت `running` می‌خواند: رکورد در برابرِ
وضعیتِ خودِ ران تسویه شده بود، که آن هم ادعایی است از همان نویسنده‌ی مرده. سه قانون از این ماجرا بیرون
آمد و `test/invariants.test.ts` هر سه را تضمین می‌کند.

- **فقط یک جا می‌پرسد.** `server/pid.ts` تنها پروبِ زنده‌بودن را دارد — تنها `kill(pid, 0)` و تنها
  `ps`ای که در `server/` از شل صدا زده می‌شود. چهار جواب می‌دهد، نه دو تا: `running`، `stopped`،
  `zombie`، `gone`. دو پروب که درباره‌ی یک پروسه با هم اختلاف داشته باشند، همان چیزی است که باعث شد
  یک نشستِ متوقف، زنده خوانده شود.
- **فقط یک جا عمل می‌کند.** `server/runner/signals.ts` تنها نردبانِ خاموش‌کردن را دارد: اول با SIGCONT
  بچه را بیدار کن (پروسه‌ی متوقف، SIGTERM را در صف می‌گذارد و هندلرش هرگز اجرا نمی‌شود)، به **گروهِ**
  پروسه سیگنال بده تا bash و سرورهای MCP و ساب‌ایجنت‌هایش هم با آن بروند، و همیشه یک پشتیبانِ SIGKILL
  بگذار — که `await` می‌شود، نه اینکه روی تایمری سوار شود که با همان کنسولی می‌میرد که تنظیمش کرده.
- **دستگیره از کنسولی که ساختش عمرِ بیشتری دارد.** نقشه‌ی `children` در ران ادغام (merge) می‌شود، نه
  بازسازی؛ پس بچه‌ای که کنسولِ *قبلی* راه انداخته بود از ریکاوریِ یک کنسولِ تازه بایت‌به‌بایت جان به در
  می‌برد و فقط پروب اجازه دارد حذفش کند. و هیچ خواننده‌ای هرگز رکوردی را نمی‌بیند که ادعای کارِ در جریان
  روی پروسه‌ای مرده داشته باشد — هرچه خودِ ران درباره‌ی خودش بگوید.

## نوشتن‌ها

به‌صورت پیش‌فرض خاموش. با `--allow-writes` کنسول می‌تواند شش اسکریپت را اجرا کند، هرکدام پشتِ یک دیالوگ
(و برای گیت‌ها، یک تأییدِ دوبار-فشار) که اول دقیقاً همان دستور را نشان می‌دهد:

| کار | اسکریپت |
|---|---|
| ساختِ اسکلتِ یک طرح | `new-plan.sh` |
| ساخت یا تعمیرِ یک هندآف | `new-handoff.sh` |
| ثبتِ نتیجه‌ی QA | `qa-record.sh` |
| تأیید یا لغوِ تأییدِ گیتِ یک فاز | `gate-approve.sh` — **کارتِ Gate** در صفحه‌ی فاز؛ یک تأیید، گیت از هر نوعی را باز می‌کند و می‌تواند رانی را که پشتِ گیت پارک شده ادامه دهد |
| گرفتن یا آزادکردنِ قفلِ یک فاز | `phase-lock.sh` |
| روشن‌کردنِ QA برای یک طرح | `new-handoff.sh … --qa` (فازهای تمام‌شده را waived می‌کند) |
| بستن یا بازکردنِ دوباره‌ی یک طرح | `close-plan.sh` (یک وضعیت و یک خط دلیل؛ بازکردن هیچ‌کدام را نمی‌خواهد) |

سوییچِ `--git` هرگز پاس داده نمی‌شود، پس این فعل‌ها هیچ‌وقت کامیت یا پوش نمی‌کنند — کامیت عمداً در ترمینال و
با تصمیمِ خودتان می‌ماند، و تنها پوشی که کنسول می‌تواند بکند مالِ `--allow-publish` است، پایین‌تر. ویرایشِ
متنِ طرح‌ها و هندآف‌ها هم عمداً ارائه نشده؛ نوشتنِ آن‌ها کارِ ایجنت‌هاست.

### جداسازیِ اجرا — خاموش مگر بخواهید، و به‌جای شکست، تنزل می‌کند

لِین‌های پایین برای هر **فاز**اند و طرح آن‌ها را انتخاب می‌کند. این یکی چیزِ دیگری است و عمود بر
آن: یک checkout برای هر **اجرا**، تا دو اجرایی که اسکوپِ مخزنشان هم‌پوشانی دارد **هم‌زمان** پذیرفته
شوند، نه اینکه یکی پشتِ دیگری در صف بماند. با *Give this run its own checkout* در ردیفِ **Git** صفحه‌ی
راه‌اندازی روشنش کنید؛ به استراتژیِ **new-branch** نیاز دارد (اجرایی که شاخه‌ی خودش را ندارد چیزی برای checkout
کردن ندارد)، و روی یک اجرای زنده فقط می‌شود خاموشش کرد — کامیت‌های اجرا روی شاخه‌ای در همان
checkout‌ای هستند که با آن شروع شده.

آنچه اپراتور **خواسته** و آنچه اجرا **گرفته** عمداً دو واقعیتِ جدا هستند. جداسازی روی یک
superproject، وقتی دیسک جا ندارد، و وقتی سقفِ worktreeها پر است رد می‌شود — و هر ردشدن به checkoutِ
مشترک با همان معناشناسیِ صفِ همیشگی تنزل می‌کند و در journal و صفحه‌ی اجرا می‌گوید به کدام
ناممکن خورده است. هیچ اجرایی به‌خاطرِ نداشتنِ درخت شکست نمی‌خورد. سه تنظیم در گروهِ **Checkouts and branches**
از Settings ▸ Automation خودِ درخت‌ها را اداره می‌کنند و فقط وقتی جداسازی روشن است دیده می‌شوند: چندتا هم‌زمان مجازند
(پیش‌فرض: ۳)، فرمانِ setup که یک بار داخلِ درختِ تازه اجرا می‌شود، و اینکه فایل‌های `.env`ِ
ignore‌شده‌ی checkoutِ مبدأ کپی شوند یا نه — پیش‌فرض خاموش، چون کپی‌کردنِ راز به یک پوشه‌ی دوم یک
تصمیم است.

اینکه دو شاخه‌ی زنده با هم چه می‌کنند **اندازه‌گیری** می‌شود: کارتِ Git در صفحه‌ی اجرا ahead/behind،
فایل‌های تغییرکرده، حجمِ دیسکِ درخت، و یک رأیِ `git merge-tree` برای هر جفت شاخه‌ی زنده را دارد —
`clean`، `overlap`، `conflicted`، یا `unknown` وقتی probe نتوانسته جواب دهد، که عمداً همان `clean`
نیست. جفتی که `conflicted` شود یک آیتمِ صندوق می‌سازد که کنشِ Serialize آن، اجرای دیگر را به صف
برمی‌گرداند.

وقتی یک اجرای روی شاخه تمام می‌شود، *When the plan completes* تعیین می‌کند شاخه‌اش چه می‌شود:
**pull request** (پیش‌فرض، و تنها پایانی که یک آدم diff را می‌خواند)، **merge queue** (یک نشستِ
دیگر روی آنچه در این مدت لند شده rebase می‌کند، راستی‌آزماییِ سرتاسریِ طرح را دوباره اجرا می‌کند و
فقط اگر سبز شد push می‌کند)، **integration** (کنسول داخلِ checkoutِ staging خودش `pe/integration`
مرج می‌کند و می‌ایستد — نه ریموتی، نه نشستی)، یا **keep** (هیچ). فقط آن دو تایی که به ریموت ختم
می‌شوند اجازه‌ی carve-outِ push را دارند. درختِ تمیز هنگام تسویه حذف می‌شود؛ درختِ کثیف نگه داشته و
در journal ثبت می‌شود.

### لِین‌های worktree — خاموش، مگر طرح بخواهد

دو فاز با اسکوپ‌های جدا می‌توانند هم‌زمان اجرا شوند، و به‌صورت پیش‌فرض هر دو از یک working tree
مشترکِ همان اجرا استفاده می‌کنند. اگر طرحی در §Session budget خودش بنویسد
`- **Worktrees:** on`، به‌جای آن هر لِین یک چک‌اوتِ مستقل می‌گیرد:

```
<root>/.worktrees/runs/<slug>/<runId>/
    integration/    شاخه‌ی اجرا (pe/<slug>) — مرج‌ها اینجا انجام می‌شوند
    p4/             لِینِ فاز ۴، شاخه‌ی pe/<slug>-p4
    p9/             لِینِ فاز ۹، شاخه‌ی pe/<slug>-p9
<root>/.worktrees/staging/          درختِ pe/integration مشترک کل کنسول
<root>/.worktrees/hand/<slug>/p<N>  لِینِ خودِ یک نشستِ دستی (scripts/phase-lane.sh)
```

هر چیزی که کنسول می‌سازد داخلِ ریشه‌ی همان نمونه است، زیر یک پوشه که کنسول آن را در
`.git/info/exclude` ریشه می‌نویسد (Settings ▸ Automation ▸ *Worktree root*؛ جای قدیمی زیر
پوشه‌ی state کنسول، `runs/<instance>/<slug>/worktrees/`، هنوز خوانده و جارو می‌شود). آینه‌ی یک
superproject هم همین شکل را دارد: مخزن‌های mount‌شده در مسیرهای نسبی‌شان زیر `integration/`
می‌ایستند. هرگز پوشه‌ای کنار پروژه، هرگز worktree از خودِ superproject.

**به چک‌اوتِ خودتان هرگز دست زده نمی‌شود** — نه شاخه‌اش عوض می‌شود، نه چیزی داخلش مرج می‌شود، و
لازم هم نیست تمیز باشد. وقتی یک لِین تمام می‌شود، کامیت‌هایش داخلِ `integration/` روی شاخه‌ی اجرا
می‌نشینند: اگر چیز دیگری تکان نخورده باشد یک fast-forward، وگرنه یک کامیتِ مرج. یک **تعارض، مرج را
abort می‌کند** و اجرا را با نوعِ `worktree-merge` متوقف می‌کند، نامِ هر دو لِین و فایل‌های متعارض را
می‌گوید؛ و هیچ چیزی گم نمی‌شود، چون تمامِ کامیت‌ها هنوز روی شاخه‌ی همان لِین‌اند و چک‌اوتش هم سرِ
جایش است. در پایانِ اجرا، کنسول لِین‌هایی را که فرود آمده‌اند پاک می‌کند، آن‌هایی را که نیامده‌اند
نگه می‌دارد — و هیچ شاخه‌ای را حذف نمی‌کند.

این قابلیت به استراتژیِ گیتِ **new-branch** نیاز دارد (لِین‌ها روی شاخه‌ی اجرا فرود می‌آیند) و روی یک
**سوپرپروژه رد می‌شود**: `git worktree add` روی مخزنی که ساب‌ماژول دارد، پوشه‌های ساب‌ماژول را
**خالی** می‌سازد، پس فازی که اسکوپش یکی از آن‌هاست نشستی را داخلِ هیچ سوار می‌کرد. هر رد کردنی با نامِ
خودش در ژورنال ثبت می‌شود و اجرا دقیقاً مثل قبل، با ریشه‌ی مشترک، ادامه می‌دهد.

**اینکه هر نشست کجا داشته کار می‌کرده، از کنسولی که می‌دانسته عمرِ بیشتری دارد.** چک‌پوینتِ اجرا،
`worktree` و `branch` هر لِین را کنارِ pid آن ثبت می‌کند؛ پس کنسولی که وسطِ اجرا دوباره بالا آمده
هنوز نشان می‌دهد یک نشستِ زنده داخلِ کدام درخت است — و همین برای یک نشستِ رهاشده‌ی چند ساعت بعد هم
صادق است، که تفاوتِ میانِ «`git worktree list` یک پوشه را نام می‌برد» و «اپراتور می‌داند مالِ کیست»
است. **نبودنِ این دو یعنی مشترک:** لِینی که هیچ‌کدام را ندارد، در ریشه‌ی خودِ اجرا کار کرده — یعنی
همان کاری که هر اجرا می‌کند مگر طرحی خلافش را بخواهد. ژورنال همین را با **جمله** می‌گوید، نه با
`key=value`: چک‌اوتی که گرفته شد، رد کردنی که اجرا را به درختِ مشترک برگرداند، فرودِ لِین، و تعارضی
که مرج را abort کرد.

**به هر نشستی که ساخته می‌شود گفته می‌شود وضعیتِ کار کجا می‌رود (`$DOCS_ROOT`)، و نشست نباید آن را
بازنویسی کند.** اسکریپت‌های مهارت، ریشه‌ی مستنداتشان را اول از همین متغیر و بعد از راه رفتنِ رو به
بالای گیت از cwd پیدا می‌کنند، و داخلِ یک worktreeِ پیوندی آن راه رفتن به *worktree* می‌رسد نه به
ریشه‌ی اجرا. نشستی در یک لِین که این را نادیده گرفت، هندآف و `.locks/` و ردیفِ QA خودش را جایی نوشت
که برد هرگز نگاه نمی‌کند: فاز تمیز فرود آمد و برد همچنان `no-handoff` می‌خواند. این متغیر برای هر
نشستی تنظیم می‌شود، لِین باشد یا نباشد — نشستی که cwd‌اش خودِ ریشه است، همان مقداری را می‌گیرد که
fallbackِ خودش حساب می‌کرد.

این تنها جایی است که سرور یک مخزن را تغییر می‌دهد، و عمداً فقط یک **فایل** است —
`server/runner/worktree.ts`، تنها استثنایی که `test/never-push.test.ts` می‌دهد. فعل‌هایی که با ریموت
حرف می‌زنند حتی همان‌جا هم ممنوع می‌مانند: کنسول همچنان هرگز منتشر نمی‌کند.

سرور روی `127.0.0.1` می‌نشیند، و هر نوشتنی به هدرِ `x-phase-console` به‌علاوه‌ی یک `Origin` هم‌ریشه نیاز
دارد — چیزی که مرورگر بدونِ یک CORS preflight (که سرور هرگز جوابش را نمی‌دهد) از دامنه‌ی دیگر نمی‌فرستد.

## حساب‌های Claude و سقف‌های مصرف

سنجه‌ی حساب روی همه‌ی صفحه‌ها هست، پایینِ نوارِ کناری (روی گوشی، ردیفی در کشوییِ More). **بدترین پنجره‌ی ۵ ساعته‌ی
همه‌ی حساب‌ها** را می‌خواند، با یک نوارِ کوچک برای هر حساب و پنجره‌های همه‌ی حساب‌ها در عنوانش — حسابِ دومی که به
دیوارش می‌خورد نباید پشتِ نشانگرِ سبزِ حسابِ اصلی پنهان بماند — و Settings ▸ Accounts را باز می‌کند، که جزئیاتِ هر
حساب را دارد: پنجره‌ی ۵ ساعته‌ی نشست، سهمیه‌ی هفتگی، و هر پنجره‌ی مدل‌محوری که سرویس مصرف گزارش کند (Opus، Fable،
… — با «کلید» رندر می‌شوند، پس پنجره‌ای که فردا عرضه شود فردا هم دیده می‌شود)، با شمارش معکوس تا ریست. اعداد همان
اعدادِ `/usage` هستند — وقتی اجرایی با آن حساب خرج می‌کند هر ۹۰ ثانیه و در غیر این صورت هر ۱۰
دقیقه پرس‌وجو می‌شوند (`USAGE_ACTIVE_MS`، `USAGE_IDLE_MS`؛ یک 429 عقب‌نشینیِ سخت‌تری از بقیه‌ی خطاها دارد)،
کش می‌شوند، و وقتی سرویس در دسترس نیست همان آخرین عدد با ذکرِ کهنگی‌اش نشان داده می‌شود — و برای دیدن‌شان
هیچ سوییچی لازم نیست.

سوییچِ `--allow-accounts` **ثبتِ حساب** را روشن می‌کند، و دفترِ حساب‌ها مالِ خودِ کنسول است.
یا با یک حساب دیگر وارد شوید (یک پروفایلِ `CLAUDE_CONFIG_DIR` که کنسول مدیریت می‌کند — کنسول یک
ترمینال روی `claude auth login` باز می‌کند و بعد ایمیل را از همان‌جا می‌خواند)، یا توکنِ بلندمدتِ
`claude setup-token` را بچسبانید و برایش نامی بگذارید. رازها به keychain (یا فایلِ ‎0600) می‌روند؛
هرگز داخل `accounts.json`، هرگز به مرورگر — و کنسول هیچ‌وقت به اعتبارنامه‌های خودِ CLI دست نمی‌زند.
حساب‌ها **تغییرِ نام** می‌گیرند (فقط نامِ نمایشی — شناسه‌ی زیرش کلیدِ ژورنال است و هرگز عوض نمی‌شود) و
**حذف** می‌شوند: حذف، ثبتِ همین کنسول و پوشه‌ی پروفایل و (روی macOS) آیتمِ keychain هش‌شده‌ای را که
فقط برای همان پوشه ساخته شده بود می‌برد — هرگز آیتمِ خودِ ورودِ اصلی ماشین را — و تا وقتی اجرایی زنده
با آن حساب خرج می‌کند، حذف را رد می‌کند.

**ورودِ منقضی خودش خبر می‌دهد.** اعتبارنامه‌ی هر حساب همراهِ نشانگرهایش پاییده می‌شود؛ ورودی که از سالم
به منقضی یا خارج‌شده برود (بعد از اینکه تلاشِ تمدیدِ خودِ CLI هم امتحان شد) اعلانِ «دوباره وارد شوید»
می‌فرستد، در Settings و نشانگرها نشان‌دار می‌شود، و کارتِ ورودِ صفحه‌ی اجرا حسابِ درست را با دستورِ درست
نام می‌برد — اجرایی که به یک پروفایل سنجاق شده **با همان پروفایل** پیش‌پرواز می‌شود، پس ورودِ
منقضی‌اش پیش از خرجِ حتی یک نشست رد می‌شود، نه اینکه هر فاز یک نشست بسوزاند تا بفهمد.

**آنچه کنسول درباره‌ی یک ورود می‌آموزد، از کنسولی که آموخته عمرِ بیشتری دارد.** فایلِ
`accounts/learned.json` زیرِ پوشه‌ی وضعیتِ ماشین — یک فایل برای همه‌ی کنسول‌ها، ‎0600، که اتمی و زیرِ قفل
نوشته می‌شود — هر اعتبارنامه را با یک اثرانگشت کلید می‌زند و سازمانش، دیوارهایی که به آن‌ها خورده،
استحقاقش (entitlement) و آخرین باری را که کار کرده به خاطر می‌سپارد؛ مرورگر همیشه فقط `orgId`ِ هش‌شده را
می‌بیند. استحقاق یک قطع‌کن (breaker) است (`ENTITLEMENT_STATES`: `unknown`، `entitled`، `cooling`،
`suspect`، `retired`). خواندنی که کار کند `unknown` را به `entitled` می‌رساند. دیوارِ مصرف حساب را تا ریستِ
همان دیوار خنک می‌کند، یا وقتی ریست خواندنی نیست به‌مدتِ `ACCOUNT_COOLDOWN_MS` (۳۰ دقیقه)، و حسابِ در حالِ
خنک‌شدن تا آن وقت از رتبه‌بندیِ `auto` بیرون است — اما آن ریست «حداکثر تا» است: هر خوانشِ تازه‌ی مصرف دیوارها را
دوباره می‌خواند (خوانشی زیرِ `WALL_PCT` دیوارش را برمی‌دارد، ریستِ زودتر کوتاهش می‌کند و دیرتر هرگز بلندش
نمی‌کند)، جلسه‌ای که زیرِ آن حساب خرج کند و درست تمام شود دیوارهای مشترک و دیوارِ مدلِ خودش را برمی‌دارد، و
فازی که پشتِ دیوار پارک شده با عقب‌نشینی (`WALL_REPROBE_BACKOFF_MS`: ۱۰، ۲۰، ۴۰ و بعد هر ۶۰ دقیقه) دوباره
سنجیده می‌شود و همان لحظه که حساب جا داشته باشد سوار می‌شود (`phase.wall-lifted`). حکمِ بازنشستگی فقط از کانالِ
خودِ API می‌آید — پیام‌های خطای CLI، نوعِ خطای نتیجه، stderr — یا از جلسه‌ای که هیچ خرج نکرده؛ کلماتی که یک
جلسه‌ی کارکرده چاپ کرده هیچ‌چیز را بازنشسته نمی‌کنند. هر بازنشستگی شاهدش را نگه می‌دارد (کانال، کلماتِ
منطبق، جلسه و فاز) که زیرِ قطع‌کن نشان داده می‌شود. بازنشستگیِ طبقه‌بند که خوانشِ سبزِ بعدی نقضش کند به
`suspect` تنزل می‌کند — هنوز بیرون از رتبه‌بندی — و یک بررسیِ سبز، یک خرج، یا ماندنِ آن نقض به‌مدتِ
`SUSPECT_CLEAR_MS` (۳۰ دقیقه) پاکش می‌کند. ردشدنی از جنسِ اعتبارنامه (`org-policy`، `auth`، `billing`،
`certificate`) حساب را **بازنشسته** می‌کند و سازمانش را هم با آن، پس هر ورودِ آن سازمان `unusable` خوانده
می‌شود؛ اجرا `run.account-retired` را ثبت می‌کند، *Account retired* را اعلام می‌کند و با
`credential-refused` متوقف می‌شود، که فقط فشارِ یک آدم دوباره راهش می‌اندازد. حسابِ بازنشسته هنگامِ شروع با
نامش و در هر سوارشدن (`run.admission-refused`) رد می‌شود، تا وقتی
`POST /api/accounts/:id/clear-retired` (`--allow-accounts`) سازمان و همه‌ی هم‌سازمانی‌هایش را پاک کند —
سازمانِ تازه روی همان اعتبارنامه هم خودش آن را دوباره باز می‌کند. حسابِ حذف‌شده یک سنگ‌قبر به‌جا می‌گذارد، پس
ژورنالی که نامش را آورده همچنان `<name> (removed)` می‌خواند؛ `GET /api/accounts` آن‌ها را به‌صورتِ
`tombstones` سرو می‌کند، و `breaker`ِ هر حساب می‌گوید آیا نامزدِ رتبه‌بندی است و اگر نه، چرا و تا کِی.
`POST /api/accounts/:id/probe-entitlement` (`--allow-accounts`) حساب را با یک نشستِ تک‌نوبتیِ سقف‌دار
(haiku، `--max-budget-usd 0.05`) می‌آزماید که به سقفِ شروع حساب می‌شود — شکست بازنشسته‌اش می‌کند و موفقیت
`unknown` را به `entitled` می‌رساند.

**پیش از آنکه اجرا خرج کند، و سرِ دیوار.** درِ شروع حساب‌ها را بر اساسِ ظرفیت رتبه‌بندی می‌کند و حسابی را
که بازنشسته است، در یک باکتِ آموخته به دیوار خورده، یا به `PREFLIGHT_REFUSE_PCT` (۹۷٪) پنجره‌ی ۵ ساعته‌اش
رسیده رد می‌کند — سراغِ بعدی می‌رود و، اگر هیچ‌کدام نماند، اجرا را با یک خواسته پارک می‌کند
(`run.preflight-refused`). وسطِ اجرا حسابی که به `WALL_PCT` (۹۹٪) رسیده از رتبه‌بندی بیرون است، و اجرایی که
سیاستِ سقفش دو بار در یک ساعت هیچ حرکتی پیدا نکند (`LIMIT_NONE_MAX` در `LIMIT_NONE_WINDOW_MS`) فاز را
به‌صورتِ `resource-wall:usage` به نردبان می‌سپارد: یا پنجره را صبر می‌کند یا با یک خواسته پارک می‌شود
(`phase.live-wall`). وقتی ریست دورتر از `LIMIT_ACTION_COOLDOWN_MS` (۱۰ دقیقه) است — ریستی که پنجره اعلام
کرده، یا تأخیرِ retryِ خودِ CLI — هیچ retry‌ای پیش از آن نمی‌گذرد، پس **همان اولین** رگباری
rate-limit پنجره را صبر می‌کند. پیش از دیوار، هشدارِ یک نشست بالای `ALERT_PCT` (۹۵٪) که هیچ تعویضِ
حسابی جوابش را ندهد **ترمزِ مصرفِ** آن حساب را می‌کشد: تا وقتی یک لِین روی آن حساب زنده است لِینِ تازه‌ای
سوار نمی‌شود — تنها لِین هرگز رد نمی‌شود — تا خوانشی از همان پنجره زیرِ `WARN_PCT` (۸۰٪) یا ریستش
(`run.usage-brake` / `run.usage-brake-released`). خطِ تصمیم (`run.usage-decision`) می‌گوید چه شد، و
نشست‌های زنده‌ای را که هیچ اجرایی نساخته، برای هر حساب از روی config dirی که هوکِ حضورشان گزارش
می‌دهد می‌شمارد (`nonRunSessions`؛ و `unattributed` جایی که نمی‌تواند بگوید).

بعد از آن، هر راه‌اندازی — ردیفِ **Accounts** صفحه‌ی راه‌اندازی، و فرمِ تختی که یک بازبینیِ QA، یک ایجنتِ
بازیابی یا یک نشست باز می‌کند — یک انتخابِ **حساب** دارد (از جمله `auto`: بیشترین ظرفیتِ ۵ ساعته) و برای اجراها یک
**سیاستِ سقف**:

| سیاست | وقتی پنجره‌ی مشترک (نشست/هفتگی) پر شد |
|---|---|
| `switch` *(پیش‌فرضِ دیالوگ‌ها)* | نشست checkpoint می‌شود و بلافاصله زیر حسابی که ظرفیت دارد ادامه می‌یابد — اگر بشود، همان نشست (transcript به پوشه‌ی پیکربندی آن حساب منتقل می‌شود)، وگرنه از boot prompt تازه. با یک حساب، خودش به `wait` تبدیل می‌شود. |
| `wait` *(پیش‌فرضِ روی دیسک)* | تا ریست می‌خوابد و خودش ادامه می‌دهد — حتی بعد از ری‌استارت کنسول، که ساعتِ ادامه دوباره کوک می‌شود. |
| `pause` | checkpoint می‌کند و برای شما می‌ایستد؛ زمانِ ریست روی بنر است. |

سقفِ مدل‌محور (Opus، Fable، …) مسیر خودش را دارد: اجرا **مدل** عوض می‌کند نه حساب، چون آن
پنجره‌ها per-model هستند — و دیوار زیر باکتِ خودش ثبت می‌شود (`seven_day_opus`، `seven_day_fable`،
…)، پس `auto` آن حساب را فقط برای اجراهای همان مدل کنار می‌گذارد و فازِ Sonnet را همچنان همان‌جا
می‌فرستد. وسطِ اجرا هم **Switch account** در نمای **Run** طرح همان لحظه عمل می‌کند — انتخاب‌گر **همه‌ی**
حساب‌ها را نشان می‌دهد و حسابِ فعلی علامت دارد — نشستِ زنده checkpoint می‌شود (شناسه‌ی نشست حفظ
می‌شود) و زیر حسابِ دیگر ادامه می‌یابد؛ زمان‌بندْ فقط حسابِ محدودشده را نگه می‌دارد، پس اجراهایی که با
حسابِ دیگری خرج می‌کنند روان می‌مانند. همه‌چیز در ژورنال ثبت می‌شود؛ دسته‌ی اعلانِ «Usage limits» هر
سقفی را که واقعاً خورده شد و هر ورودی را که به ورودِ دوباره نیاز دارد اعلام می‌کند، و هشدارِ زودهنگامِ
۸۰/۹۵٪ دسته‌ی جداگانه‌ی خودش است — «Usage climbing»، به‌طورِ پیش‌فرض روشن. یک بودجه — انتظارِ یک فاز، دلارهای فاز یا ران، سقفِ نردبانِ بازیابی، رشته‌ی شکست‌ها — در ۸۰٪ و وقتی تمام می‌شود زیرِ «Budget spent or running low» اعلام می‌شود، با حسابش و دکمه‌ی افزایشی کنارش (control-tower phase 14).

Settings ▸ Accounts هر حساب را یک خط می‌کشد — ورودش، پنجره‌ی ۵ ساعته‌اش، و کِی خوانده شده — که همان‌جا باز می‌شود
به هر پنجره با زمانِ ریستش، دیوارهایی که این ماشین یاد گرفته، واژه‌ی breaker و شواهدش، جایگاهش در رتبه و
اعتبارهایش (credits)، با **Probe entitlement**، **Clear retired** روی حسابِ بازنشسته (پشتِ یک تأیید)، **Rename** و
**Remove**. سنگ‌قبرها زیرِ *Removed, still remembered* می‌مانند، و *What this machine holds* هر credentialی را که
یک طرح نام می‌برد، موجود یا نه، فهرست می‌کند. بدونِ `--allow-accounts` فقط‌خواندنی است.


## سرورهای MCP

جلسه‌ها می‌توانند ابزارهایی را که وصل می‌کنید صدا بزنند: یک مرورگر، یک ابزارِ پیگیریِ ایشو، یک سرورِ
مستندات. سهمِ کنسول در این میان باریک است — خودِ Claude Code به‌خوبی به سرورهای MCP وصل می‌شود. کاری
که نمی‌تواند بکند این است که *پیش از آنکه* یک اجرای بی‌ناظر یک ساعت خرج کند به شما بگوید سروری که طرح
انتخاب کرده هرگز وارد نشده است.

طرح می‌گوید به چه نیاز دارد (`**MCP servers (every session):**` در §Session budget و بولتِ
`- **MCP:**` برای هر فاز، که با هم **اجتماع** می‌شوند). این‌ها **شناسه‌های دفتر** هستند: چیزی که فاز
لازم دارد، نه راهِ رسیدن به آن — چون راهِ رسیدن، ماشین‌به‌ماشین فرق می‌کند. دفتر زیرِ state dir همان
نمونه می‌نشیند، مثل دفترِ حساب‌ها و به همان دلیل: سروری که به یک پروژه تعلق دارد، دقیقاً همان چیزی است
که نباید به پروژه‌ی دیگر داد.

پیش از آنکه فاز سوار شود، کنسول دقیقاً همان مجموعه را می‌آزماید — یک
`claude -p --strict-mcp-config --mcp-config <set>` تک‌نوبتی که `system/init`ِ آن وضعیتِ واقعیِ هر سرور
را **پیش از هر فراخوانِ مدل** گزارش می‌کند. این مهم است چون جلسه‌ی بی‌ناظر نمی‌تواند خودش دیوار را
بردارد: در حالتِ `-p` پنلِ `/mcp` وجود ندارد و CLI نبودِ ابزارها را به *مدل* می‌گوید، و مدل دورش را
می‌گیرد. پیش‌پرواز کش و single-flightِ ساعتِ سلامت را به اشتراک دارد (`HEALTH_TTL_MS`، ۵ دقیقه)، پس مجموعه‌ای
که در پنج دقیقه‌ی گذشته آزموده شده دوباره آزموده نمی‌شود، و پروب `PE_SESSION_KIND=probe` را دارد، پس
هیچ نشستی برایش ثبت نمی‌شود. تا وقتی کسی پاسخ‌ها را نمی‌خواند ساعت عقب می‌کشد — پنج دقیقه، دوبرابر تا یک ساعت
(`HEALTH_IDLE_MAX_MS`) — و یک مرورگر، یک Refresh یا یک سوارشدن آن را به پنج دقیقه برمی‌گرداند.

**اما اینکه با آن دیوار چه کند یک سیاست است، و پیش‌فرض «ادامه بده» است.** فاز با سرورهایی که پاسخ
داده‌اند سوار می‌شود، در پرامپتش نامِ آن‌هایی که نگرفته می‌آید با این دستور که نه جایگزینی از خودش
بسازد و نه آن را مانع بداند — کاری را که وابسته به آن‌ها نیست انجام بده و باقی را زیرِ **Outstanding**
به‌عنوان کارِ اپراتور ثبت کن — و شما یک‌بار برای هر سرور در هر اجرا خبردار می‌شوید. برای رفتارِ قدیمی،
*When an MCP server is unavailable* را در Settings ▸ Automation ▸ **Launch defaults** روی *Park the phase* بگذارید —
برای یک اجرا با *If one will not connect* در ردیفِ **Tools** صفحه‌ی راه‌اندازی، یا در جدولِ فازهایش برای یک فاز. طرح
هم می‌تواند با
`**MCP policy:** require` برای خودش اصرار کند و این بر انتخابِ سطحِ اجرا مقدم است، چون طرح یک بیانِ
نسخه‌دار درباره‌ی خودِ کار است نه راحتیِ یک راه‌اندازی.

پیش‌فرض عوض شد چون پارک برای فازی طراحی شده بود که واقعاً بدونِ سرورش نمی‌تواند پیش برود، اما برای هر
فازی که صرفاً سروری به آن وصل بود شلیک می‌کرد. `parked` وضعیتی «تمام‌شده» است، پس اجرایی که همه‌ی
فازهای آماده‌اش پارک شده‌اند چیزی برای شروع ندارد و متوقف می‌شود: یک سرورِ واردنشده، طرحی یازده‌فازی را
که خودش هیچ سرور MCPای نام نبرده بود، با صفر فازِ انجام‌شده خواباند. فازی که حالا پارک می‌شود هر دو در
را نام می‌برد — واردشدن به سرور، یا **Continue without these servers** با یک دکمه روی کارتِ توقف — و
واردشدن به یک سرور همچنان هر چیزی را که پشتِ آن پارک شده دوباره در صف می‌گذارد، حتی روی اجرایی که
پیشاپیش متوقف شده است.

اسپاون همیشه `--mcp-config` را با `--strict-mcp-config` جفت می‌کند تا مجموعه‌ی حل‌شده، تمامِ مجموعه
باشد — بدون آن، CLI هرچه در `~/.claude.json` و `.mcp.json`ِ پروژه باشد را هم اضافه می‌کرد و اجرا با
سرورهایی حرف می‌زد که کسی برایش انتخابشان نکرده بود.

توکنِ `CLAUDE_CODE_OAUTH_TOKEN`ِ یک حسابِ **token** به هر سرورِ stdio که نشست راه بیندازد به ارث می‌رسد، پس
اجرایی که با چنین حسابی خرج می‌کند فقط سرورهای stdioای را نگه می‌دارد که خودِ طرح اعلام کرده — سرورهای
راه‌دور همیشه می‌مانند — و `run.token-scope` را با آنچه نگه داشت و کنار گذاشت ثبت می‌کند.

سه نوع اعتبارنامه داریم و کنسول فقط یکی را نگه می‌دارد. **OAuth** از راهِ
`claude mcp login <id> --no-browser` در یک ترمینال می‌گذرد و توکن در انبارِ خودِ CLI می‌ماند — نویسنده‌ی
دوم همان چیزی است که یک ورود را بینِ دو پروسه خراب می‌کند. **توکنِ هدر** مالِ ماست: keychain روی macOS،
فایلِ ‎0600 در جاهای دیگر، هرگز داخلِ `servers.json` و هرگز در مرورگر. **`${VAR}`** راز نیست بلکه *نامِ*
راز است و بدون بسط رد می‌شود تا CLI آن را در محیطِ فرزند حل کند. آدرسی که اعتبارنامه‌اش را با خودش
حمل کند، هنگامِ افزودن رد می‌شود.

### ورود به سروری که CLI هرگز نامش را نشنیده است

`claude mcp login` یک **نام** می‌گیرد و هیچ فلگِ پیکربندی ندارد، و آن نام را در دفترِ خودِ CLI حل
می‌کند — نه در دفترِ این کنسول. پس برای هر سروری که فقط اینجا ثبت شده بود، دکمه‌ی Sign in ترمینالی باز
می‌کرد که پاسخ می‌داد `No MCP server named "<id>"` و فهرستِ سرورهای *کسِ دیگری* را چاپ می‌کرد. نه خطایی
در کنسول بود، نه راهی به جلو، و زیرِ `require` فازی روی شرطی پارک می‌شد که اپراتور نمی‌توانست بازش کند
(ایشو ‎#8).

پس ورود حالا **تعریفِ سرور را پل می‌زند** — فقط به‌اندازه‌ی طولِ همان جریان (`server/mcp/login.ts`):

```
claude mcp add --transport <http|sse> --scope user <id> <url>   # یک تعریف، نه یک اعتبارنامه
claude mcp login <id> --no-browser                              # حالا نام حل می‌شود
claude mcp remove <id> --scope user                             # دفتر را سرِ جایش بگذار
```

چهار قاعده را نگه می‌دارد. تعریف **هیچ رازی حمل نمی‌کند** — شناسه، ترابری، آدرس و هدرهای غیرِراز که
خودِ دفتر دارد، و هیچ‌چیزی که در keychain است؛ CLI آن را با ‎0600 می‌نویسد. تعریفی که **اپراتور از قبل
داشته هرگز حذف نمی‌شود** — جریان اول می‌پرسد (`claude mcp get`) و بعد می‌نویسد، و فقط چیزی را پس
می‌گیرد که خودش نوشته. پل **پیش از ساختنِ هر ترمینالی** زده می‌شود، پس اگر CLI ثبت را نپذیرد، دقیقاً
همان دستورها روی کارت می‌آیند به‌جای ترمینالِ دومی که شکست می‌خورد. و سرورِ `ws` اصلاً دکمه نمی‌گیرد:
`claude mcp add` برای آن ترابری املایی ندارد. فقط سروری که با **OAuth** احراز می‌شود این جریان را
می‌گیرد؛ سروری که با هدر یا متغیرِ محیطی احراز می‌شود اعتبارنامه‌اش را دارد و ورودی برایش معنا ندارد.

هر گام زیرِ یک `CLAUDE_CONFIG_DIR` اجرا می‌شود، و اینکه کدام‌یک باشد مهم است: CLI اعتبارنامه‌هایش را با
`sha256(CLAUDE_CONFIG_DIR)[:8]` کلید می‌زند، پس توکنی که زیرِ یک دایرکتوری وارد شده برای جلسه‌ای که زیرِ
دایرکتوریِ دیگری اجرا می‌شود نامرئی است. پیش‌فرض، دایرکتوریِ خودِ کنسول است — همانی که آزمایشِ سلامت
می‌خواند، و همین است که باعث می‌شود `GET /api/mcp` بلافاصله پس از ورود `connected` گزارش کند.
`POST /api/mcp/<id>/login` یک `accountId` هم می‌گیرد که کلِ جریان را زیرِ دایرکتوریِ آن حسابِ **پروفایل**
اجرا می‌کند: وقتی به کارتان می‌آید که اجراهایتان با حسابِ پروفایل خرج می‌شوند نه با ورودِ ماشین. کارت
نامِ دایرکتوری‌ای را که توکن در آن نشسته می‌گوید، چون ورودی که جایی بنشیند که اجرا آنجا را نگاه نمی‌کند
همان اشکال است با پیامِ موفقیت بر تن.

هر آزمایش، فهرستِ ابزارهایی را که سرور اعلام کرده انگشت‌نگاری می‌کند. تغییرِ آن هشدار می‌دهد و بی‌صدا
جذب نمی‌شود: سروری که *توضیحِ* ابزارهایش عوض می‌شود می‌تواند دستوری را که به جلسه‌های شما داده می‌شود
عوض کند، و این همان حمله‌ی زنجیره‌ی تأمینِ مستندشده علیه MCP است. ابزارهای علامت‌خورده با
`requiresUserInteraction` هم علامت می‌خورند — یک اجرای بی‌ناظر هرگز نمی‌تواند تأییدشان کند.

فراخوانی‌های MCP هیچ‌وقت به هوکِ PreToolUse کنسول نمی‌رسند، پس قاعده‌های `mcp__server` در
`permissions.deny`ِ فایلِ تنظیمات می‌نشینند و چه کنسول روشن باشد چه نباشد، برقرارند.

سوییچِ `--allow-mcp` فقط **ثبت** را کنترل می‌کند. دیدنِ دفتر، وضعیتِ اتصال‌ها و کاتالوگ به آن نیازی
ندارد — دیدنِ اینکه جلسه‌های خودتان به چه وصل می‌شوند، نمایش است نه توانایی.

سوییچِ `--allow-webhooks` سوییچِ هفتم است و نخستین از دو سوییچی که رو به بیرون دارند: همان اعلان‌ها، به‌صورتِ
JSON به نشانی‌هایی که خودتان ثبت می‌کنید (Slack، Discord، Telegram، یا رله‌ی خودتان). خاموش یعنی هیچ
درخواستِ خروجی‌ای زده نمی‌شود، حتی برای نشانی‌ای که از پیش ثبت شده — پرچم درست پیش از فرستادنِ بار
خوانده می‌شود، نه فقط هنگامِ ثبت. نشانی ذخیره می‌شود و دیگر هرگز پس داده نمی‌شود، چون خودِ نشانیِ یک
incoming-webhook تمامِ مجوز است؛ بارها فقط شناسه، عنوان و یک پیوند به خانه دارند و رشته‌های شبیهِ راز
در مسیرِ خروج پوشانده می‌شوند. شِما و دستور‌العمل‌ها: `docs/webhooks.md`.

سوییچِ `--allow-publish` سوییچِ هشتم است و دومین سوییچی که رو به بیرون دارد — آنجا که وب‌هوک‌ها یک
اعلان را به جایی دیگر می‌فرستند، این یکی خودِ کار را می‌فرستد. به یک فرود اجازه می‌دهد شاخه‌ی `pe/*`
خودِ یک فازِ تمام‌شده را (`pe/<slug>-p<N>` برای یک لِین، `pe/<slug>` برای اجرای جداسازی‌شده یا آینه‌ای)
به `origin` پوش کند، از یک درزِ واحد (`pushRef` در `server/runner/worktree.ts`) و با یک argv یخ‌زده:
`git push --porcelain --no-follow-tags origin refs/heads/<ref>:refs/heads/<ref>`. هرگز یک trunk، هرگز
`pe/integration`، هرگز با force، هرگز یک حذف، هرگز تلاشِ دوباره برای پوشی که رد شده، هرگز نامی بیرون
از `^pe/[A-Za-z0-9._-]+(-p\d+)?$`؛ و پرچم به‌تنهایی کافی نیست — ردیفِ `permission.destructive` طرح هم
باید `git push` را مجاز کرده باشد، وگرنه فرود با `phase.landing-push-refused {reason}` پارک می‌شود و
هیچ‌چیز اسپاون نمی‌شود. نشستِ فرودی که بعدش سوار می‌شود هرگز پوش نمی‌کند؛ `gh pr create` و
`gh pr merge`ِ آن زیرِ هر پروفایلی پرسش‌های سنجاق‌شده می‌مانند. خاموش یعنی کنسول هیچ‌چیز پوش نمی‌کند، و
کنسولِ رایگان هرچه پرچم بگوید چیزی پوش نمی‌کند؛ ردیفِ `publish` در `phase-console doctor` می‌گوید کدام
است.


## از روی گوشی

فلسفه‌ی یک اجرای بدون‌ناظر این است که شما دست از تماشا بردارید، و فلسفه‌ی صفِ تأییدها این است که اجرا
بتواند وسطِ کار از شما چیزی بپرسد. این فقط وقتی جواب می‌دهد که کنسول از هرجایی که هستید در دسترس باشد.

کنسول همچنان روی `127.0.0.1` می‌نشیند. چیزی که عوض می‌شود این است که یک چیزِ دیگر جلوی آن سوکت می‌ایستد،
هویتِ تماس‌گیرنده را احراز می‌کند و می‌گوید او کیست. [Tailscale Serve][serve] همان موردی است که این
قابلیت برایش نوشته شده: TLS را terminate می‌کند، تماس‌گیرنده را در برابرِ شبکه‌ی خصوصی شما بررسی می‌کند و
درخواست را با loginِ او در هدرِ `Tailscale-User-Login` به loopback فوروارد می‌کند.

<div dir="ltr">

```bash
# the console: unchanged bind, plus who may arrive through the proxy
./start --root ~/code/your-repo --allow-writes --allow-run \
        --remote your-machine.your-tailnet.ts.net \
        --remote-user you@example.com

# the proxy: HTTPS on the private network, forwarding to loopback
tailscale serve --bg --https=443 http://127.0.0.1:4123
```

</div>

| سوییچ | معنی |
|---|---|
| `--remote <host>` | به این hostname هم جواب بده، که پشتِ یک پراکسیِ احرازِ هویت‌کننده قرار دارد. قابل تکرار. بررسیِ سخت‌گیرانه‌ی `Host` را روشن می‌کند. |
| `--remote-user <login>` | یک login که اجازه دارد از آن راه بیاید. قابل تکرار، یا از طریقِ `PHASE_CONSOLE_REMOTE_USERS`. برای `--remote` **الزامی** است؛ بدونِ آن کنسول اصلاً بالا نمی‌آید. |

وقتی پروفایلِ ماشین آن را گفته باشد، به هیچ‌کدام از این دو سوییچ نیازی نیست: `remoteHost` و `remoteUsers` در
`~/.config/phase-console/fleet.json` به‌صورتِ یک جفت به ارث می‌رسند — به‌ازای هر فیلد، اول سوییچ یا متغیرِ
محیطی، بعد مقدارِ اختصاصیِ همین کنسول در همان فایل، بعد مقدارِ ماشین — و `notifyCommand`، `webhooks`،
`categories` و `quietHours` هم همین‌طور.

به‌محضِ اینکه یک hostname نام ببرید، دقیقاً دو نوع درخواست سرو می‌شود: یک `Host` لوپ‌بک بدونِ هدرِ هویت
(یعنی خودِ شما، پشتِ همین ماشین) و همان hostname نام‌برده‌شده به‌همراهِ یک loginِ مجاز (یعنی خودِ شما، از
راهِ پراکسی). هر چیزِ دیگری رد می‌شود — از جمله درخواستی که از پراکسی آمده ولی `Host` لوپ‌بک می‌خواهد
(که راهی است که یک نفر در شبکه می‌توانست با آن از بررسیِ هویت فرار کند)، و هر `Host` ناشناخته (که همان
چیزی است که یک صفحه‌ی DNS-rebinding با آن می‌آید). اگر اصلاً `--remote` ندهید، هیچ‌کدامِ این‌ها اعمال
نمی‌شود و هر درخواست دقیقاً مثل قبل رفتار می‌بیند.

**هدرِ هویت فقط به این دلیل ارزش دارد که خودِ اپ روی loopback مانده است.** اگر روی یک اینترفیسِ شبکه گوش
می‌داد، هر کسی می‌توانست خودش همان هدر را بفرستد. سوییچِ `--remote` عمداً `--host` را بازتر نمی‌کند؛
[مستنداتِ Tailscale][serve] هم دقیقاً همین نکته را می‌گوید.

درخواستی که از پراکسی می‌آید به نامِ loginاش ثبت می‌شود: `Tailscale-User-Login`ِ تأییدشده `remoteUser`ِ عامل
می‌شود، و `by`ِ آن هم، مگر بدنه‌ی درخواست برچسبِ خودش را نام ببرد — برچسب همیشه فقط برچسب است، و `via`،
`origin` و `remoteUser` از بدنه قابلِ تنظیم نیستند — پس فشاری که از گوشی می‌آید به نامِ همان کسی که آن را زده
در ژورنال می‌نشیند، از دَرِ `device` (`pressDoor`، control-tower phase 131).

`tailscale serve --https=443` مالِ کنسولِ پیش‌فرض است. پورتِ HTTPSِ هر کنسولِ دیگر پورتِ خودش به‌علاوه‌ی
۴۰۰۰ است (`httpsPortFor`)، و دستورِ Serveی که کنسول می‌سازد (`serveCommandFor`) هرگز پورتی را که یک کنسولِ
در حالِ اجرا سرو می‌کند نمی‌گیرد: آن ساکن را نام می‌برد و پورتِ دیگری پیشنهاد می‌کند.

**راه‌اندازیِ کامل** — آن دو سوییچِ ادمین‌کنسول، گوشی، نصب روی Home Screen که نوتیفیکیشنِ iOS به آن نیاز
دارد، هشدارهای خارج از مرورگر، قوانینِ دسترسی و یک جدولِ عیب‌یابی — در
[docs/phone.md](../docs/phone.md) آمده است.

[serve]: https://tailscale.com/docs/features/tailscale-serve


## هزینهٔ یک صفحه

یک سرورِ محلی بهانه‌ای برای فرستادنِ بایت‌هایی که کسی نمی‌خوانَد ندارد، و این یکی داشت: باز کردنِ یک
طرح روی همان کتابخانهٔ ۱۲۱ طرحی که رویش توسعه داده می‌شود **~۱٬۷۵۳ کیلوبایت** جابه‌جا می‌کرد و
**۱۱٫۲۷ ثانیه** پیش از اولین ترسیم منتظرِ اعتبارسنج می‌مانْد. چهار چیز عوض شد و هیچ‌کدام قابلیتی را
حذف نمی‌کند.

**فشرده‌سازی، اعتبارسنج‌های کش، و دارایی‌های تغییرناپذیر** — `server/http/compress.ts`، فقط با
`node:zlib` و `node:crypto`، چون خالی‌بودنِ `dependencies` در viewer عمدی است. `Accept-Encoding` را
با q-value مذاکره می‌کند (brotli در تساوی، gzip به‌عنوان پشتیبان، `q=0` یعنی ردکردن)، از بدنه‌های
زیرِ ۱ کیلوبایت می‌گذرد، بدنه‌ای را که *بزرگ‌تر* شده همان‌طور می‌فرستد، و روی هرچه فشرده‌شدنی است
`vary: accept-encoding` می‌گذارد — از جمله روی چیزی که identity بیرون آمده، چون آنچه `vary` بیان
می‌کند **وابستگیِ** پاسخ به آن هدر است، نه شکلِ نهایی‌اش. یک `ETag`ِ قوی روی بدنهٔ **identity** گرفته
می‌شود نه روی بایت‌های فرستاده‌شده، پس یک درخواستِ شرطی هرگز هزینهٔ یک پاسِ فشرده‌سازی را نمی‌دهد، و
`If-None-Match` با یک ۳۰۴ بدونِ `content-length` و بدونِ `content-type` پاسخ می‌گیرد.

پاسخ‌های ۲۰۰ برای GETهای API از `cache-control: no-store` به `private, no-cache` رفتند: زیرِ
`no-store` مرورگر اجازهٔ نگه‌داشتنِ بدنه را ندارد، پس هرگز نمی‌توانست تگ را پس بفرستد و ETag تزئین
می‌شد. `no-cache` هنوز پیش از هر استفاده اعتبارسنجی می‌کند و `private` آن را از هر کشِ مشترک روی
`--remote` بیرون نگه می‌دارد. بقیه — رسیدهای POST، خطاها، دانلودها، `/api/metrics` — `no-store`
می‌مانند. `/events` هرگز فشرده نمی‌شود و نخواهد شد: پنجرهٔ flushِ یک فشرده‌ساز دقیقاً همان چیزی است
که SSE تحمل نمی‌کند، پس سرِ خودش را می‌نویسد. و `server/http/static.ts` همان همزادهای از پیش
فشرده‌شدهٔ `.br`/`.gz` را که `npm run build` می‌نویسد سرو می‌کند و هرگز در زمانِ درخواست فشرده
نمی‌کند، با `immutable` روی دارایی‌های هش‌دار.

هر دو جریانِ رویداد از میان **یک نویسندهٔ سقف‌دار** می‌نویسند، `server/api/sse.ts`. وقتی بافرِ هسته پر
است `res.write()` مقدارِ false برمی‌گرداند و نود بایت‌ها را به‌جای شما در حافظه نگه می‌دارد؛ هر دو
هندلر این پاسخ را نادیده می‌گرفتند — که برای مرورگری روی همین ماشین بی‌اشکال است و برای تلفنی روی یک
tailnetِ خوابیده بی‌کران. از `SSE_MAX_BUFFERED_BYTES` (۴ مبی‌بایت) که بگذرد، شنونده با
`sse.slow-client` بازنشسته می‌شود و سوکتش رها — مرورگر با `Last-Event-ID` دوباره وصل می‌شود و همان
بازپخشی را می‌گیرد که SSE دقیقاً برای همین دارد، و سوکتِ بازِ پر از فریم‌های کهنه مانعِ آن بود.
فریم‌های ناتمامِ `run:stream` حالا **به درخواستِ خودِ شنونده و به‌ازای هر اجرا** فرستاده می‌شوند و در
هر `SSE_STREAM_COALESCE_MS` به یک فریم برای هر خط جمع می‌شوند. یک جریان اجراهایش را هنگامِ باز شدن نام
می‌برد (`/events?stream=<runId>[,<runId>…]`، حداکثر `SSE_MAX_STREAMS`) یا بعدتر، بی‌آنکه دوباره باز
شود: فریمِ `hello` آن یک نامِ `connection` دارد و `POST /api/events/subscribe {connection, streams}`
مجموعه‌ای را که آن جریان می‌گیرد جایگزین می‌کند. نامی که این پروسه نگه نمی‌دارد پاسخِ ۴۰۴ با
`{reopen: true}` می‌گیرد و صفحه جریان را با `?stream=` و `?last=` دوباره باز می‌کند — شناسهٔ آخرین
رویدادی که دیده، چون صفحه خودش نمی‌تواند `Last-Event-ID` را بگذارد؛ اگر هر دو برسند سرآیند برنده
است. یک مرورگر برای همهٔ زبانه‌هایش تنها یک جریان از این دست نگه می‌دارد:
`client/src/data/live-share.ts` زبانه‌ای را که یک Web Lock در دست دارد رهبر می‌کند، و رهبر هر فریم را
با یک `BroadcastChannel` به بقیه می‌رساند و اجراهایی را می‌خواهد که هر زبانه‌ای نشان می‌دهد. بقیهٔ
شنونده‌ها به‌جای آن با `run:progress` حرکت می‌کنند — یک فریمِ کوچک برای هر خطِ زنده هر سه ثانیه، تنها
وقتی چکیده‌اش عوض شده باشد، و به‌صورتِ PATCH روی کش، پس هیچ رفت‌وبرگشتی نمی‌دهد. `RUN_PROGRESS_FIELDS`
(`shared/run-lifecycle.js`) همان چیزی است که حمل می‌کند و هر دو سرِ سیم همین فهرست را می‌خوانند.

دو تله که این کار به‌جا می‌گذارد. **`res.req` راهی است که درخواست به `sendBody` می‌رسد** (نود ۱۵٫۷ به
بعد)، نه پارامتری که دست‌به‌دست شده باشد — ۲۴۳ فراخوانیِ `json(res, …)` وجود دارد و پاسخِ ساختگی‌ای
که `req` ندارد به identity مذاکره می‌کند، که مسیری *بی‌صدا متفاوت* از مسیرِ سرور است. و **بدنه‌ها
حالا `Buffer` بیرون می‌روند**، پس هر تستی که روی بدنه ادعا می‌کند باید اول بر اساسِ
`content-encoding` رمزگشایی کند؛ `decode()` را از `routes.test.ts` یا `apiGet()` را از
`transport.test.ts` بردارید. و نکتهٔ آخر: `/api/state` عکسی از یک پروسهٔ زنده است نه یک موجودیتِ
پایدار، پس **هرگز روی آن یک رفت‌وبرگشتِ ۳۰۴ را ادعا نکنید** — دو خواندن به فاصلهٔ یک میلی‌ثانیه
به‌درستی می‌توانند فرق کنند. آن ادعا جای `/sw.js` است، که بایت‌های پایدار دارد و در هر دو حالتِ
build پاسخ می‌دهد.

**`?include=` — هر صفحه همان چیزی را می‌خواهد که می‌کشد.** دو نقطهٔ پایانیِ خواندن هرچه می‌دانستند به
هر فراخوان می‌دادند. `viewer/shared/projection.js` مالکِ واژگان است، پس سرور با همان تعریف تصویر
می‌کند که کلاینت با آن می‌پرسد:

| گروه | چه چیزی |
|---|---|
| `prose` | بخش‌های نثرِ خودِ هر فاز |
| `document` | مارک‌داونِ خودِ طرح — زمینه، معماری، و نمای Source |
| `handoffs` | پاراگرافِ `outstanding` از ارجاعِ تحویل |
| `memory` | فایلِ حافظهٔ طرح |
| `full` | همه‌چیز، بایت‌به‌بایت همان پاسخِ پیش از ۳٫۲ |

اندازه‌گیری‌شده روی کتابخانهٔ زنده: طرحِ ۲۳ فازی **۲۸۶٫۵ → ۳۹٫۳ کیلوبایت**، طرحِ ۳۱ فازی **۱۳۰ →
۵۴٫۰ کیلوبایت**، و یک اجرای زنده درونِ `/api/state` **۳۴۰٫۴ → ۱۱٫۲ کیلوبایت**. `include=full` در هر
دو سوی این تغییر ۳۱۵٬۶۰۸ بایت اندازه‌گیری شد، پس هیچ‌چیز حذف نشده — فراخوانی که شکلِ قدیمی را
می‌خواهد نامش را می‌بَرد. خلاصهٔ اجرا یک فهرستِ **حذف** است نه فهرستِ نگه‌داشتن، پس فیلدی که فردا به
`RunState` اضافه شود خودبه‌خود سوار می‌شود؛ و `detail()` خروجی‌اش کش نمی‌شود و هر تصویر تخصیصِ تازه
می‌گیرد، پس دو فراخوان با مجموعه‌های include متفاوت نمی‌توانند همدیگر را خراب کنند.

🔴 **فایلِ منبعِ یک تب، درختِ رندرِ آن نیست، و اشتباه‌گرفتنش بی‌صداست.** برشِ اول `phase.goal` و کلِ
`phase.handoff` را کنار گذاشت در حالی که تبِ Routeِ نسخه‌ی ۶.x هیچ‌کدام را نخواسته بود — چون فایلش، route-tab.tsx،
هیچ‌کدام را *خودش* نمی‌خوانْد: یک خطِ کوتاه‌شدهٔ `goal` و یک چیپِ handoff را از ماژولِ سلولی سوار
می‌کرد که چهار تب در آن شریک بودند. `goal` روی ۲۳ از ۲۳ فاز خالی درآمد، بدونِ هیچ خطایی.
`tabs.test.ts`ِ صفحه‌ی طرح (نماهای ۷.۰، `TAB_INCLUDES`) همچنان به‌ازای هر کامپوننت یال‌های JSX را می‌پیماید و
نگاشتِ فیلد→گروه را از `projection.js` می‌گیرد؛ نقاطِ کورش در همان فایل نوشته شده و تیزترینشان فیلدی است که داخلِ یک تابعِ
ساده خوانده می‌شود که *فراخوانی* می‌شود نه رندر.

**اعتبارسنج از مسیرِ خواندن بیرون رفت.** `detail()` دیگر منتظرِ `lint()` نمی‌مانَد — lint هنوز حرفِ
موتور است، هنوز کلیدخوردهٔ revision، و هنوز روی `GET /api/plans/<slug>/lint`، اما در یک ماکروتسکِ
بعدی و *پس از* ساخته‌شدنِ پاسخ زمان‌بندی می‌شود و به‌صورتِ رویدادِ SSEِ `plan:lint` می‌رسد که کلاینت
یک‌راست در کشش می‌نویسد. این زمان‌بندی باید **آخرین** دستورِ `detail()` بمانَد: اگر جایی بگذاریدش که
lint خوانده می‌شود، `setTimeout(0)` وسطِ awaitهای بعدی شلیک می‌کند و `validate.sh` پیش از آنکه
فراخوان چیزی ببیند در حالِ اجراست. کنارش، نگاشت‌های revision در `engine.ts` و `service-live.ts`
خودِ **پرامیس** را کش می‌کنند (`Cached<T>` حالا `{ revision, value: Promise<T>, settled? }` است، پس
هر نگاشتِ تازه‌ای که کلیدش revision باشد باید از `this.cached()`/`this.settled()` بگذرد وگرنه
single-flight را از دست می‌دهد)، کشِ موتور TTL و سقفِ بایت و سقفِ مدخل گرفت، `store.scan()` وقتی
اثرانگشتِ یک طرح تکان نخورده revisionش را نگه می‌دارد، و `pid.ts` دیگر `ps` را ناهمگام صدا می‌زند.

**قفل نوشتنِ طرح نیست، و timeout تختهٔ خالی نیست** (control-tower phase 55، #44). `.locks/` در
اثرانگشت نیست — هیچ اسکریپتی که revision کلیدش است آن را نمی‌خوانَد — و `onChange` کشِ طرحی را که یک
دستهٔ رویدادِ پایش فقط از راهِ `.locks/`ش لمس کرده نگه می‌دارد (`lockOnlySlugs`)، پس claimها و
تمدیدهای leaseِ یک اجرای زنده دیگر طرحی را که آدم باز می‌کند سرد نمی‌کنند؛ فهرستِ قفل‌ها، زمان‌بند و
دفترِ قفل‌ها هنوز هر نوشتن را می‌بینند. خواندنِ تخته‌ای که timeout می‌خورد به صفحه و فهرست
(`pageBoard`، از راهِ `pageContext`) به‌صورتِ آخرین تختهٔ سالم با `summary.boardStale` داده می‌شود، هرگز
`EMPTY_BOARD`، و پس از `BOARD_RETRY_MS` دوباره امتحان می‌شود؛ هر خوانندهٔ دیگرِ `board()` — درمانگر،
سلامتِ طرح، اجراها — هنوز همان timeout را می‌بیند. lint به‌صورتِ آخرین حکمِ شناخته با `lint.stale`
داده می‌شود (`pageLint`). سقف‌ها برای هر فعل جداست (`timeoutFor`: خواندنِ تخته ۴۵ ثانیه، lint ۱۸۰
ثانیه؛ درزِ آزمون `setEngineTimeouts` است)، و `GET /api/engine` استخرِ موتور را برای خطِ «Computing
the board (N queued)» صفحه جواب می‌دهد.

**اولین ترسیم و تختهٔ اعلانات.** چانکِ مسیر از افکتی بالاتر از هر بازگشتِ زودهنگام پیش‌بارگذاری می‌شود — آن را
زیرِ یکی ببرید و باز چانکِ طرح منتظرِ `/api/state`ای می‌مانَد که به آن وابسته نیست — و هزینهٔ واقعیِ یک مسیر
بستارِ گذرای importهای **ایستای** چانکش است، که هیچ فایلی نشانش نمی‌دهد: ۷۷٫۶ کیلوبایت run-setup سوارِ مسیرِ طرح
بود، از راهِ کامپوننتی که دیالوگ را فقط با یک فشار رندر می‌کند. حالا `check-dist.mjs` آن گراف را می‌پیماید و فقط
یال‌های ایستا را دنبال می‌کند، تا یک `lazy()` هرگز پس‌رفت خوانده نشود. یک گریدِ بلند — جدولِ فازها هم از آن جمله
— روی اسکرولرِ `<main>`ِ پوسته پنجره‌بندی می‌شود (`useWindow`، `ui/grid/engine.ts`) — نه اسکرولرِ خودش، چون
`overflow-x`ِ `TableWrap` باعث می‌شود `overflow-y`ِ محاسبه‌شده auto شود و یک بسته‌بندیِ ارتفاع‌دار به اسکرولرِ
عمودیِ دومی بدل شود که فلیک‌های لمسیِ صفحه را می‌بلعد — و به‌شکلِ بدنه‌های فاصله‌گذارِ `aria-hidden` که هرکدام
یک `<tr>` دارند، نه با موقعیت‌دهیِ absolute، چون سطری که از جریان بیرون برود دیگر برای چیدمان و برای صفحه‌خوان
سطرِ جدول نیست. `aria-rowcount`/`aria-rowindex` اندازهٔ واقعی را حمل می‌کنند.

دو واقعیتِ موتور که یادگرفتنشان یک پاس هزینه داشت: وقتی اسکرولر صفر اندازه‌گیری شود،
`@tanstack/virtual-core` **هیچ سطری** نمی‌دهد، پس هر تستِ jsdom که یک گریدِ پنجره‌بندی‌شده را رندر می‌کند باید
`offsetHeight` را جعل کند (و اگر روی خودِ پنجره ادعا می‌کند، `getBoundingClientRect().height` را هم)؛
و عنصرِ اسکرولش را در یک layout effect می‌بندد، پس رندرِ #۱ اصلاً بازه‌ای ندارد. هر دو با حل‌کردنِ
تنبلانهٔ اسکرولر داخلِ `getScrollElement` و `initialOffset`ای که از خودِ اسکرولر خوانده می‌شود حل شده‌اند — و
این درست است چون `shell/layout.tsx` در هر تغییرِ مسیر `scrollTop` را صفر می‌کند. `OVERSCAN` یک تنظیمِ دسترس‌پذیری
است نه پیچِ کارایی: سطری که کشیده نشده فوکوس نمی‌گیرد، پس پایین‌آوردنش به‌سمتِ صفر گرید را در لبهٔ دید به بن‌بستِ
Tab بدل می‌کند. و همهٔ memoهای جدولِ فازها روی روشن‌بودنِ `structuralSharing`ِ TanStack Query تکیه دارند — خاموشش
کنید و سلول‌های memoشده از پرداختن بازمی‌ایستند در حالی که همه‌چیز هنوز درست رندر می‌شود، و دقیقاً به همین دلیل آن
پیش‌فرض تستِ خودش را دارد.
