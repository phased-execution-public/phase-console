# Journal events

Every event kind this console can write, what emits it, and what it means.

**Why the file exists.** Every event kind the console emits is a row in the table below — a
couple of hundred, and `viewer/test/debug-index.test.ts` pins the table against the code, so the
number is never written here to go stale; before this the five doc surfaces between them named 27. A journal is only evidence if a reader can tell
what a line means, and "grep the server for the string" is not a document — it
is the absence of one.

**Two sinks, and the difference matters.**

| sink | goes to | who reads it |
|---|---|---|
| `journal` | the RUN's journal (`runs/<instance>/<slug>/run-<runId>.jsonl`) | the console's timeline, the phase detail, `analysis/timeline.ts`, and you |
| `log` | the console's own log file | an operator debugging the console itself |

A `log` line is about the CONSOLE; a `journal` line is about the WORK. A few
kinds appear in both, and are marked `both`.

**Both tables are machine-checked in BOTH directions** by
`viewer/test/docs-parity.test.ts`: every `'<phase|run|policy>.<name>'` string
literal under `viewer/server/`, every name a `log.info/warn/error('…')` call
writes, and every name handed to the sessions registry's `onWarn` must appear
here, and every row here must appear there. Add an event without a row and the
suite goes red; delete an event and leave its row and the suite goes red the
other way. That is the only thing that keeps a list this size true. Two rules
the widening added (LFC-4): an event name is never composed at runtime — no
template literal, no name arriving in a variable — because a composed name is
one this file cannot hold (`run.park-withdrew` reached a journal that way,
undocumented); and a **retired** event keeps its row, with `retired <version>`
in the emitter column instead of a file, so a log written before the upgrade
stays readable — the checker skips such a row in the "must be emitted"
direction and fails if the name is ever emitted again.

**Payload.** Every entry carries `at`, and a phase-scoped one carries `phase`.
The rest is per-event; the emitting file named below is the authority on it.

## Console log events

The `log` sink's own names — lines about the CONSOLE rather than about the work: what it did at
boot and shutdown, which door it refused, which clock fired, which file it could not read. They
carry no fixed prefix (the first segment is the subsystem — `shutdown`, `mcp`, `push`, `terminal`,
`runner`, …), so `viewer/test/docs-parity.test.ts` reads them off the CALL — the first argument of
`log.info/warn/error(…)`, and of the sessions registry's `onWarn`/`onInfo` callbacks that
`service-base.ts` forwards to `log.warn`/`log.info` — rather than off a prefix. Same columns, same rule as the table above: every
name written under `viewer/server/` has a row here, and every row names something written. The
`run.*` and `policy.*` log names sit in the table above beside the journal's, because their prefix
puts them there. The audit that widened the check (sep-review, LFC-4) found 70 of the 90 names the
two consoles had actually written in their logs outside the checked alphabet; the source writes
these 247.
