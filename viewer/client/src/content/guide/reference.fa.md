## پرچم‌های کنسول

هر هشت کلیدِ قابلیت، مگر نام برده شوند، خاموش‌اند. پرچم‌ها فقط یک بار، هنگامِ راه‌اندازی، خوانده می‌شوند.

| پرچم | معنی |
|---|---|
| <span dir="ltr">`--root <dir>`</span> / <span dir="ltr">`-r`</span> | مخزنِ داده‌شده را فوراً باز می‌کند و از انتخابگر می‌گذرد. |
| <span dir="ltr">`--allow-writes`</span> | اسکلتِ طرح‌ها و هندآف‌ها را می‌سازد، QA را ثبت می‌کند، قفل می‌گیرد، طرح‌ها را می‌بندد و دوباره باز می‌کند. هرگز کامیت نمی‌کند، هرگز پوش نمی‌کند. |
| <span dir="ltr">`--allow-run`</span> | اتوپایلوت را روشن می‌کند. عمداً از نوشتن جداست. |
| <span dir="ltr">`--no-converge`</span> | گذرهای خودکارِ حلقه‌ی همگرایی را خاموش نگه می‌دارد — راه‌اندازی، تغییرِ docs، جاروب، و یک دقیقه پس از یک توقف. *Recover & continue* (بازیابی و ادامه) هنوز وقتی بزنیدش یک گذر اجرا می‌کند. |
| <span dir="ltr">`--allow-terminal`</span> | در مرورگر یک شِل باز می‌کند. نه فهرستِ deny دارد و نه هوکِ تأیید: هر که پشتِ کیبورد است، خودش سیاست است. |
| <span dir="ltr">`--allow-agent`</span> | نشست‌های تعاملیِ `claude` — از جمله بازیابی و بازبینی‌های QA — و ویزاردِ *New plan with AI*. |
| <span dir="ltr">`--allow-accounts`</span> | حساب‌های Claude را ثبت می‌کند و برای هر اجرا یکی را انتخاب می‌کند. شمارنده‌های مصرف به هیچ پرچمی نیاز ندارند. |
| <span dir="ltr">`--allow-mcp`</span> | سرورهای MCP را ثبت می‌کند، اعتبارنامه‌هایشان را نگه می‌دارد و آن‌ها را به طرح‌ها و فازها وصل می‌کند. *خواندنِ* دفترِ ثبت، وضعیت‌ها و کاتالوگ به هیچ پرچمی نیاز ندارد. |
| <span dir="ltr">`--allow-webhooks`</span> | هر اعلانی را که این کنسول می‌دهد به نشانی‌هایی که ثبت می‌کنید POST می‌کند — Slack، Discord، Telegram، یا رله‌ی خودتان. خاموش یعنی هیچ درخواستِ خروجی اصلاً فرستاده نمی‌شود، هر چه ثبت شده باشد. *خواندنِ* فهرستِ مقصدها به هیچ پرچمی نیاز ندارد. اسکیمای payload و دستورالعمل‌های Slack/Discord/Telegram در [docs/webhooks.md](https://github.com/phased-execution-public/phase-console/blob/main/docs/webhooks.md) است — یک لینک، نه یک مسیر، چون نسخه‌ی بسته‌بندی‌شده پوشه‌ی <span dir="ltr">`docs/`</span> ندارد. |
| <span dir="ltr">`--allow-publish`</span> | شاخه‌های <span dir="ltr">`pe/*`</span> را پوش می‌کند (هرگز یک trunk، هرگز با force) و issue ثبت می‌کند، در جایی که ردیفِ `permission.destructive` و خطِ <span dir="ltr">`Issues:`</span> طرح اجازه بدهند. خاموش یعنی هرگز نه پوشی، نه issueای؛ فرودِ `Land: pr` با ذکرِ دلیل پارک می‌شود. |
| <span dir="ltr">`--port <n>`</span> / <span dir="ltr">`-p`</span> | به‌جای مشتق‌کردنِ پورت از مسیرِ مخزن، یک پورت را ثابت می‌کند. هرگز سراغ پورتِ بعدی نمی‌رود. |
| <span dir="ltr">`--host <addr>`</span> | نشانیِ bind. پیش‌فرض `127.0.0.1` است و دلیلِ خوبی برای تغییرش نیست — **Mobile setup** (راه‌اندازی موبایل) را ببینید. |
| <span dir="ltr">`--no-open`</span> | هنگامِ راه‌اندازی مرورگر را باز نمی‌کند. `PHASE_CONSOLE_NO_OPEN=1` همین کار را می‌کند. |
| <span dir="ltr">`--remote <host>`</span> | به این hostname هم جواب می‌دهد، پشتِ پروکسی‌ای که درخواست‌کننده‌ها را احراز هویت می‌کند. بررسیِ سخت‌گیرانه‌ی `Host` را روشن می‌کند. |
| <span dir="ltr">`--remote-user <login>`</span> | یک loginِ مجاز برای ورود از این راه. <span dir="ltr">`--remote`</span> آن را **الزامی** می‌کند. |
| <span dir="ltr">`--max-sessions <n>`</span> | سقفِ سراسری برای نشست‌های هم‌زمان. پیش‌فرض ۳؛ یک اجرا می‌تواند کمتر بخواهد، هرگز بیشتر. |
| <span dir="ltr">`--default-skills <csv>`</span> | اسکیل‌هایی که در هر اجرای تازه از پیش گذاشته می‌شوند. تکرارپذیر و افزایشی است — برداشتنِ تیکِ یکی در کنسول هنوز یک خاموشیِ واقعی است. |
| <span dir="ltr">`--scripts <dir>`</span> | از یک checkoutِ دیگرِ phased-execution استفاده می‌کند. |
| <span dir="ltr">`--log-file <path>`</span> / <span dir="ltr">`--no-log-file`</span> | مقصدِ لاگِ ساختاریافته. پیش‌فرض زیرِ <span dir="ltr">`~/.local/state/phase-console/`</span> است. |

## متغیرهای محیطی

| متغیر | کاری که می‌کند |
|---|---|
| `PHASE_CONSOLE_NOTIFY` | دستوری که برای هر اعلان به‌شکلِ <span dir="ltr">`cmd "<title>" "<body>"`</span> اجرا می‌شود. عمداً فقط از راهِ محیط. |
| `PHASE_CONSOLE_URL` | `btw` با کدام کنسول حرف می‌زند. |
| `PHASE_CONSOLE_HOME` | نصبِ خودِ کنسول کجاست، برای CLI. |
| `PHASE_CONSOLE_REMOTE_USERS` | loginها، جداشده با ویرگول — مثلِ تکرارِ <span dir="ltr">`--remote-user`</span>. |
| `PHASE_CONSOLE_MAX_SESSIONS` | پیش‌فرضِ <span dir="ltr">`--max-sessions`</span>. |
| `PHASE_CONSOLE_DEFAULT_SKILLS` | پیش‌فرضِ <span dir="ltr">`--default-skills`</span>. |
| `PHASE_CONSOLE_NO_OPEN` | `1` بازشدنِ مرورگر را خاموش می‌کند. |
| `PHASE_CONSOLE_LOG` | مسیرِ پیش‌فرضِ لاگ؛ مقدارِ خالی فایل را غیرفعال می‌کند. |
| `PHASE_EXEC_GATES` | `1` به بررسی‌های گیتِ `cmd` اجازه می‌دهد واقعاً یک دستور اجرا کنند. |

## فعل‌های کنسول

| فعل | کاری که می‌کند |
|---|---|
| <span dir="ltr">`phase-console <repo>`</span> | کنسولِ آن مخزن را اجرا می‌کند. یک آرگومانِ اولِ ساده یک **root** است، نه یک فعل. |
| `phase-console install-skill` | فایل‌های اسکیل را جایی می‌گذارد که Claude Code می‌خواند. برای یک نسخه‌ی بسته‌بندی‌شده است — پلاگین یا clone هرگز به آن نیاز ندارد. `uninstall-skill` دوباره برشان می‌دارد. |
| `phase-console install-hooks` | هوکِ حضورِ نشست را به <span dir="ltr">`~/.claude/settings.json`</span> اضافه می‌کند، تا کنسول بداند کدام نشست‌ها زنده‌اند. `uninstall-hooks` آن را برمی‌دارد؛ `hooks-status` می‌گوید هست یا نه. |
| <span dir="ltr">`phase-console doctor [instance] [--json]`</span> | بررسی می‌کند این ماشین آماده‌ی اجرا هست یا نه: همان بررسی‌هایی که شروعِ یک اجرا انجام می‌دهد، بدونِ طرح — حساب‌ها، سرورهای MCP، loginِ `claude`، یک کانالِ تحویل، هوک‌های حضور، نسخه‌ی CLI در برابرِ کفِ relay، `gh auth status`. کدِ خروجِ ۱ اولین ردیفِ مسدودکننده‌ی ناموفق را نام می‌برد. |
| <span dir="ltr">`phase-console sessions ingest [instance]`</span> | dropهای در صفِ هوکِ حضور را وقتی هیچ کنسولی اجرا نمی‌شود اعمال می‌کند — هوک وقتی POSTش کسی را پیدا نکند، خودش آن را اجرا می‌کند. تا وقتی کنسول جواب می‌دهد کاری نمی‌کند، چون همان کنسول صندوقِ ورودیِ خودش را تخلیه می‌کند. |

<span dir="ltr">`./start`</span> معادلِ clone است، و یک **مخزن می‌گیرد، نه یک فعل**: اولین آرگومانِ ساده‌اش به <span dir="ltr">`--root`</span> تبدیل می‌شود.

## بررسی‌های گیت

برای اینکه بگویید چه چیزی یک فاز را نگه داشته — و **چه کسی می‌تواند آن را رفع کند** — به آن فاز <span dir="ltr">`- **Gate-check:** <type> …`</span> اضافه کنید. گیتِ `ai` را خودِ نشستِ سوارشده رفع می‌کند؛ گیتِ `manual` منتظرِ یک آدم است؛ بقیه خودشان رفع می‌شوند.

| نحو | دسته | کِی رفع می‌شود |
|---|---|---|
| <span dir="ltr">`ai <check>`</span> | ai | یک نشستِ سوارشده شرط‌های Gates طرح را بررسی می‌کند، کارِ لازم برای برقراری‌شان را می‌کند و رفعِ گیت را ثبت می‌کند — یا شما آن را تأیید می‌کنید. این را ترجیح دهید. |
| <span dir="ltr">`manual <who>`</span> | human | هرگز خودبه‌خود. یک آدم گام‌های شماره‌دارِ بولتِ Gates را انجام می‌دهد، بعد روی کارتِ Gate صفحه‌ی فاز تأیید می‌کند. |
| `phase 8` | auto | فازِ ۸ این طرح انجام شده است. |
| `phases 6,7,9` | auto | همه‌ی آن‌ها انجام شده‌اند. |
| `plan other-slug:6,8` | auto | آن فازها در یک طرحِ دیگر انجام شده‌اند. |
| `date 2026-12-01` | auto | در آن تاریخ یا پس از آن. بازه‌اش بررسی می‌شود، پس یک تاریخِ بی‌معنی گیت را بسته نگه می‌دارد. |
| `deadline 2026-12-01` (یا <span dir="ltr">`by …`</span>) | auto | فقط پیش از آن تاریخ — بعد از آن گیت OVERDUE خوانده می‌شود. |
| <span dir="ltr">`cmd <command>`</span> | auto | دستور با کدِ ۰ خارج می‌شود. **اتوپایلوت آن را ارزیابی می‌کند (`PHASE_EXEC_GATES=1`)؛ دیدنِ صفحه‌ها هرگز آن را اجرا نمی‌کند** — اجرای دستوری که در یک سند نوشته شده ارزشِ یک opt-in صریح را دارد. |

**تأیید کردن** — از راهِ کارتِ Gate صفحه‌ی فاز، یا <span dir="ltr">`scripts/gate-approve.sh <slug> <N> --by <who>`</span> — گیتی از **هر** نوع را رفع می‌کند: ردیف در `docs/handoffs/<slug>/gate-status.md` می‌نشیند، و لغوِ آن گیت را برمی‌گرداند. سرفصلِ <span dir="ltr">`*(GATED)*`</span> که هیچ Gate-checkای ندارد، به‌عنوانِ گیتِ **ai** خوانده می‌شود (پیش‌فرض از ۵.۰.۰) — و تا وقتی نویسنده نگوید کدام است، lintِ طرح را رد می‌کند.

## نگه‌داشت‌های بازبینی

رأیِ `requested-changes` روی یک فاز (**Plan → a phase → Read the diff**) این کنسول را از سوار کردنِ هر فازی که *مستقیماً* به آن وابسته است باز می‌دارد. مثلِ یک گیتِ تأییدنشده رفتار می‌کند — رکوردِ فاز `gated` خوانده می‌شود، خطِ ژورنال `phase.review-held` است — و با تأیید یا پس‌گرفتنِ رأی آزاد می‌شود.

| محل | `runs/<instance>/<slug>/review/phase-NN.json` (هرگز <span dir="ltr">`docs/`</span>) |
| --- | --- |
| چه کسی رعایتش می‌کند | فقط همین کنسول — `phase-graph.sh` آن را نمی‌بیند |
| رأی‌ها | `approved` · `requested-changes` · `commented` |
| پرچمِ ثبتِ یک رأی | <span dir="ltr">`--allow-writes`</span> (خواندنِ دیف به هیچ پرچمی نیاز ندارد) |
| Endpoint | `GET`/<span dir="ltr">`POST /api/plans/<slug>/review/<phase>`</span> |

## کامنت‌های بازبینی و Send back

کامنت‌ها به `path` + `side` + `line` لنگر می‌خورند و کنار رأی در همان فایل ذخیره می‌شوند (اسکیمای v2). **Send back** فاز را با نقلِ هر کامنتِ حل‌نشده دوباره سوار می‌کند؛ پرامپت روی سرور ساخته می‌شود و هرگز از بدنه‌ی درخواست گرفته نمی‌شود.

| پرچمِ کامنت‌گذاشتن | <span dir="ltr">`--allow-writes`</span> |
| --- | --- |
| پرچمِ Send back | <span dir="ltr">`--allow-run`</span> — نشستی را شروع می‌کند که مخزن را ویرایش می‌کند |
| Endpointها | <span dir="ltr">`POST /api/plans/<slug>/review-comment/<phase>`</span> · <span dir="ltr">`POST /api/plans/<slug>/review-send-back/<phase>`</span> |
| خطِ ژورنال | `phase.review-follow-up` |
| سوار شدن | پله‌ی `reboard-review-follow-up`، موقعیتِ `review:follow-up` — تنها اشاره‌ای که فازی را سوار می‌کند که تابلو آن را `done` می‌خواند |

## بازبینِ خودکار

به‌طور پیش‌فرض خاموش است. با روشن‌بودنِ **Review each phase**، یک نشستِ تازه دیفِ هر فازِ تمام‌شده را می‌خواند و یافته‌هایش را به‌شکلِ کامنت ثبت می‌کند. هرگز نشستِ خودِ فاز را ادامه نمی‌دهد. وقتی طرح از قبل کارِ خودش را بازبینی می‌کند — بخشی که یک بازبین را اعزام می‌کند، یا <span dir="ltr">`**QA gate:** on`</span> — فرمِ launch می‌گوید هر فاز دو بار بازبینی می‌شود؛ یکی از دو را نگه دارید. کنارِ مدل و effortِ هر فاز، همان فرم <span dir="ltr">`runs <value> · <source>`</span> را نشان می‌دهد، یعنی مقداری که فاز با آن سوار می‌شود.

| تنظیم | `reviewEachPhase` (اجرا) · `reviewEachPhaseByDefault` (ترجیح) |
| --- | --- |
| آنچه می‌تواند ثبت کند | `reviewerPolicy`: `comment-only` (پیش‌فرض — هیچ‌چیز نگه داشته نمی‌شود) یا `may-hold` |
| ابزارهایی که به آن داده می‌شود | `Read`، `Grep`، `Glob` — نه `Bash`، نه `Edit`، نه `Write` |
| هزینه | یک‌چهارمِ بودجه‌ی فاز، که به حسابِ فاز و اجرا گذاشته می‌شود |
| خط‌های ژورنال | `phase.review-session` · `phase.review-session-done` · `phase.review-session-skipped` · `phase.review-session-failed` |

## سطح‌های ultra

دو opt-in که CLI می‌تواند انجامشان دهد و کنسول برایتان روشنشان نمی‌کند. هر دو روی هر اجرا، در هر پروفایل، خاموش‌اند و هیچ‌کدام یک ترجیحِ ذخیره‌شده نیست: خرج می‌کنند، و چیزی که خرج می‌کند جلوی چشمِ یک نفر انتخاب می‌شود.

**Ultracode** یک واژه است، نه یک پرچم. وقتی روشن باشد، هر پرامپتی که این اجرا می‌سازد — بوت‌پرامپت و هر پنج بریف — یک خطِ ثابت دارد که می‌گوید نشست می‌تواند هر جا کار به چند شاخه تقسیم می‌شود از ابزارِ Workflow استفاده کند. یک workflow ده‌ها ایجنت را هم‌زمان اجرا می‌کند، پس یک صورتحسابِ توکن است نه یک تنظیمِ سرعت. نشست‌های محدودِ کنارِ یک فاز هرگز آن را نمی‌گیرند: بازبینِ خودکار، رأیِ QA، closeout، و نشست‌های PR و merge-queue هرکدام یک خروجی می‌خواهند و بودجه‌ی همان یکی را دارند.

| تنظیم | `ultracode` — روی اجرا، روی یک فاز (`phaseOptions`)، یا روی یک تیکتِ ایجنت |
| --- | --- |
| تعیین مقدار | پاسخِ فاز بر پاسخِ اجرا می‌چربد، در هر دو جهت؛ سکوت در هر دو یعنی خاموش |
| کجا می‌نشیند | فقط پرامپتِ فاز — `ULTRACODE_LINE` در `server/skills.ts` |
| هزینه | توکن، بدونِ هیچ سقفی از چیزهایی که این کنسول می‌سنجد |

**Cloud review** دستورِ `claude ultrareview` را اجرا می‌کند — یک بازبینیِ چندایجنتی در ابرِ Anthropic، که به حسابی که اجرا از آن خرج می‌کند صورتحساب می‌شود. یافته‌ها همان مسیری را می‌روند که یافته‌های بازبینِ خودکار می‌روند: همان فایل، همان بنر، همان `reviewerPolicy`. رانر آن را اجرا می‌کند، هرگز یک نشستِ فاز، چون تا نیم ساعت مسدود می‌ماند.

| تنظیم | `ultraReview`: `off` (پیش‌فرض) · `each-phase` · `at-settle` |
| --- | --- |
| از کجا می‌خواند | worktreeِ لِینِ خودِ فاز، یا checkoutِ اجرا پیش از تسویه‌ی شاخه |
| یک کلیک | `POST /api/run/<slug>/ultrareview` — شکلِ at-settle، بنا به درخواست، در هر زمان |
| اگر CLI نتواند | اجرا همین را می‌گوید و ادامه می‌دهد: `unknown` همراه با یک دلیل، هرگز یک رأی و هرگز یک پارک |
| خط‌های ژورنال | `run.ultrareview` · `run.ultrareview-done` · `run.ultrareview-skipped` |

## خطِ زمانیِ اجرا

**Plan → a run → Run timeline** اجرا را روی یک محورِ مطلق می‌کشد: یک ردیف برای هر فاز، و هر نوار به یک خطِ ژورنال بند است. به پرسشی متفاوت از کارتِ *Timeline* زیرِ خودش جواب می‌دهد — آن ساعتِ خودِ هر فاز را تقسیم می‌کند، این می‌گوید هر فاز *کِی* لِین را در دست داشت.

| نوار | لِین چه می‌کرد |
| --- | --- |
| `working` | یک نشست در حال اجرا بود — از خطِ `phase.session`اش اندازه‌گیری می‌شود: همان‌جا تمام شد، و `ms`ِ همان خط زودتر شروع شده بود |
| `verifying` | §Verification در حال اجرا بود — اثباتِ خودکار که از زمانِ دستورهای خودِ `phase.verify` به عقب اندازه‌گیری می‌شود، و مسیرِ person-check که میانِ `phase.awaiting-verification` → `phase.verify` محصور است |
| `queued` | منتظرِ scopeای بود که کسِ دیگری نگه داشته بود — یک دوره‌ی صف، `phase.queued` → `phase.queue-closed` |
| `waiting` | روی چیزی بیرون از فاز پارک بود — یک انتظار، یک preflightِ MCP |
| `down` | *اجرا* با این فازِ در جریان از کار افتاده بود — halted، parked، paused، stopped یا shut down — تا شروعِ بعدی؛ tooltipِ نوار علت را نام می‌برد (`halted: plan-lint`، `stopped by operator`) |
| `frozen` | اپراتور متوقفش کرده (یک SIGSTOP: بدونِ خرج، ولی ساعتِ واقعی می‌گذرد) |

Working یعنی یک نشست و هیچ‌چیزِ دیگر، پس بازه‌ای که هیچ خطی ادعایش نکند به‌شکلِ شکاف می‌ماند: فاز در دستِ هیچ‌کس نبود. فازی که reconcile تسویه‌اش کند لِینش را همان‌جا پایان می‌دهد، و اجرایی که از کار می‌افتد کارِ هر لِینی را که در دست داشت پایان می‌دهد (فازِ ۶۱ از control-tower — تا آن زمان همه‌اش `working` کشیده می‌شد).

نوارِ **هاشورخورده** هنوز باز است. نشانه‌ها در طولِ یک لِین این‌ها را علامت می‌زنند: `board`، `verify`، `rung`، `park`، `wall`، `outcome`، `session` (یک نشست تمام شد — حالتش، چطور تمام شد، چقدر خرج داشت)، `ask` (یک پرسش یا یک کارت مطرح یا پاسخ داده شد) و `policy` (کنسول خودش چیزی را پاسخ داد)؛ نشانه‌های `start` روی خودِ محور می‌نشینند، یکی برای هر شروعِ اجرا، و درِ آن را نام می‌برند. نشانه‌ی `note` یادداشتِ یک آدم روی اجراست — روی لِینِ فازش وقتی فازی را که اجرا شده نام ببرد، وگرنه روی محور — و تا وقتی یک تصمیمِ پابرجاست `pinned` خوانده می‌شود. **مسیرِ بحرانی**ای که اینجا پررنگ می‌شود، طولانی‌ترین زنجیره‌ی وابستگی است با وزنِ زمانِ نشست و راستی‌آزماییِ *اندازه‌گیری‌شده*ی هر فاز، هرگز با نواری که هنوز باز است — نه برآوردِ صفحه‌ی طرح، که به آنچه مانده جواب می‌دهد نه آنچه رخ داد.

فازی که دو بار سوار شده باشد **مقایسه‌ی تلاش‌ها** را پیشنهاد می‌دهد: چه چیزی میانِ دو سوارشدن عوض شد — نتیجه، مدل، مدت، خرج، پله‌ی نردبان، و هر دستورِ §Verification که نتیجه‌اش جابه‌جا شد. هر تلاش *یک* سوارشدن است، و خرجش از خطوطِ `phase.session` خودش جمع می‌شود، پس هرگز کلِ تجمعیِ فاز نیست. رقمی که هرگز ثبت نشده باشد *not recorded* خوانده می‌شود، هرگز <span dir="ltr">`$0.00`</span>.

| از کجا می‌آید | ژورنالِ اجرا — هیچ‌چیز از چک‌پوینت خوانده نمی‌شود |
| --- | --- |
| Endpoint | `GET /api/run/<slug>/timeline` · <span dir="ltr">`GET /api/run/<slug>/attempts/<phase>`</span> |
| پرچمِ دیدنش | هیچ — خواندن همیشه مجاز است |
| اگر ژورنال کوتاه شده باشد | سرآیند همین را می‌گوید، و لِین‌هایی که بریده شده‌اند partial علامت می‌خورند |

## کیبورد

سه کلید، نه هشت. فهرستِ ۲.x هفت پرشِ تک‌حرفی بود که باید از کارتی حفظشان می‌کردید که باید یادتان می‌ماند سراغش بروید. پالت همه‌ی آن‌ها را با یک ترکیبِ کلید جایگزین کرد که محتوای خودش را نشانتان می‌دهد — هر مقصد، هر طرح، هر اجرا، هر فعل — و خودِ آن ترکیب را روی خودش، در سرصفحه، در هر صفحه چاپ می‌کند.

| کلید | کاری که می‌کند |
|---|---|
| <span dir="ltr">`⌘ K`</span> | پالتِ فرمان — جست‌وجو و هر فعل |
| <span dir="ltr">`/`</span> | همان، بدونِ کلیدِ تغییردهنده |
| `Esc` | یک دیالوگ، یک sheet یا پالت را می‌بندد |

هر چه حرف‌های قدیمی به آن می‌رسیدند در پالت با نام هست: `ready` را تایپ کنید برای آنچه بعدی است، `stats` یا `insights` برای عددها، `guide` برای همین صفحه.

## نقشه‌ی مسیر

نمای **Map** در تبِ Phases طرح را به‌شکلِ یک مسیر می‌کشد: یک ایستگاه برای هر فاز، یک خط برای هر وابستگی. قفل‌شده باز می‌شود، مثلِ تصویری که صفحه از کنارش اسکرول می‌شود؛ **Pan & zoom** (جابه‌جایی و بزرگ‌نمایی) را بزنید تا بتوانید بکشید و pinch کنید، و دکمه‌های **−**، **+** و **Fit** در هر دو حالت کار می‌کنند (دوبار کلیک روی نقشه هم آن را fit می‌کند). طرحی که آن‌قدر بزرگ است که کامل نشان داده نشود، هرگز ایستگاه‌هایش را کوچک‌تر از حدِ خواندنی نمی‌کشد. به‌جایش:

- **Fit rows** هر ردیفِ طرح را در عرضِ قاب جا می‌دهد، بعد روی موج‌هایش پن می‌کنید.
- نوارِ **minimap** زیرِ قاب کلِ طرح و جایی را که هستید نشان می‌دهد؛ رویش بزنید تا به آن‌جا بروید.
- **Find a station** با شماره یا عنوان جست‌وجو می‌کند — Enter به تطبیقِ بعدی می‌پرد.
- ایستگاه‌ها یک توقفگاهِ Tab هستند: روی نقشه فوکوس کنید، بعد **کلیدهای جهت‌نما** از ایستگاهی به ایستگاهِ بعدی می‌روند.

رنگِ یک ایستگاه همان وضعیتِ آن است (هشت حالتِ زیر). فازِ **Stuck** (گیرکرده) با رنگِ waiting و یک نمادِ هشدار کشیده می‌شود؛ فقط یک فراخوان — کاری که یک آدم باید انجام دهد — حلقه‌ی کهربایی دارد.

## هشت حالت

هر نشان در کنسول یکی از هشت **حالتِ UI** است، هر کدام با رنگ، آیکون و واژه‌ی ساده‌ی خودش — و رنگ هرگز تنها حامل نیست: واژه و آیکون همیشه هستند. کهربایی فقط مالِ یک حالت است: **Needs you** (نیاز به شما) — و از ۶.۰ هرگز به‌تنهایی از روی یک واژه‌ی وضعیت خوانده نمی‌شود. از یک موردِ باز در صندوقِ شما می‌آید، یا از واژه‌ای که فقط یک آدم می‌تواند جابه‌جایش کند: یک تأییدِ نهایی، یک ورود به حساب، یک تصمیمِ معوق، یک تداخلِ فرود. هر چیزِ دیگر همان را که هست رنگ می‌کند، و چیزهای تسویه‌شده ساکت می‌شوند. واژگانِ زیربنایی (وضعیتِ یک اجرا، یک رکوردِ فاز، تابلو، یک موقعیت) هرکدام روی این هشت نگاشت می‌شوند؛ جدول‌های پایین‌تر هر واژه را زیرِ حالتی که به آن خوانده می‌شود فهرست می‌کنند.

| حالت | نشان | یعنی چه | واژه‌های زیربنایی |
|---|---|---|---|
| `needs-you` | **Needs you** | تا وقتی یک آدم کاری نکند متوقف است — یک تأیید، یک گیت، یک ورود، یک تصمیم، یک خواسته. تنها کهربایی. | فاز `awaiting-verification` (**Awaiting sign-off**) · یک سرورِ MCP یا حسابی که باید واردش شد · یک تصمیمِ معوق · یک تداخلِ فرود · هر چیزی که یک موردِ بازِ صندوق دارد |
| `failed` | **Failed** | تلاش شکست خورد — یک راستی‌آزماییِ قرمز، یا نشستی که چیزی تولید نکرد که تابلو بپذیرد. | فاز `failed` · QA `fail` |
| `running` | **Running** | یک نشست همین حالا کار می‌کند، یا اجرا در راهِ توقف است. تنها حالتی که ممکن است ضربان بزند. | اجرای `running` `halting` `pausing` `stopping` · فاز `running` · تابلو `in-progress` (**In progress**) · موقعیتِ یک ماشین |
| `verifying` | **Verifying** | نشست تمام شد؛ کنسول خودش §Verification طرح را اجرا می‌کند. هم‌خانواده‌ی Running، روی نقشه یا نوار خط‌چین کشیده می‌شود. | فاز `verifying` |
| `waiting` | **Waiting** | خوابیده روی چیزی که خودبه‌خود یا با یک فشار تسویه می‌شود — یک وابستگی، یک پنجره‌ی مصرف، یک ساعتِ بیرونی، مکثی که خواستید، یک haltی که خواسته‌اش در صندوق منتظر است. | اجرای `waiting` `paused` `frozen` `halted` `parked` `interrupted` · فاز `waiting` `gated` `parked` `interrupted` · تابلو `waiting` `gated` `blocked` `stuck` (**Stuck**، با یک نمادِ هشدار) · موقعیتی که منتظرِ زمان یا کسِ دیگری است |
| `queued` | **Queued** | در صف — نوبتِ بعدی، یا پشتِ چیزی که همان مخزن‌ها را در دست دارد. فازِ تابلو که `ready` است **Next up** خوانده می‌شود. | اجرای `queued` · فاز `queued` `pending` · تابلو `ready` · QA `pending` |
| `skipped` | **Skipped** | اپراتور آن را از فهرستِ این اجرا برداشته. نه تمام‌شده، نه شکست‌خورده. واژه‌ای هم که کنسول نمی‌شناسد همین‌طور خوانده می‌شود: **Unknown**، هرگز با رنگی قرضی. | فاز `skipped` · QA `waived` · یک واژه‌ی ناشناخته |
| `done` | **Done** | تمام‌شده و روی تابلو ثبت‌شده. | اجرای `finished` (**Finished**) · فاز `done` · تابلو `done` · QA `pass` · موقعیتی که تابلو از قبل تسویه‌اش کرده |

چیزی که چند واژگان هم‌زمان توصیفش می‌کنند، به‌عنوانِ **بدترین** آن‌ها خوانده می‌شود، به ترتیبِ بالا — جز اینکه وقتی تابلو `done` می‌گوید بر همه‌چیز می‌چربد: رکوردِ اجرایی که تابلو از آن جلو زده تاریخ است، نه یک حالت.

## واژگانِ زیربنایی

عمداً کنار هم هستند، و تودرتو می‌شوند. یک **طرح** یک وضعیت دارد (آیا هنوز کسی اصلاً دنبالش هست). یک **اجرا** یک وضعیت دارد (اتوپایلوت همین حالا با آن چه می‌کند). هر **فاز در آن اجرا** یک رکورد دارد (اینجا چه بر سرش آمد). **تابلو** می‌گوید چه چیزی درباره‌ی یک فاز روی دیسک درست است. و یک **ادعا** می‌گوید آیا کسی از قبل دارد رویش کار می‌کند.

هر نشان در اپ همین را هنگامِ hover می‌گوید؛ جدول‌های زیر همان متن را یک‌جا دارند، و نشانی که هر واژه می‌پوشد همان نشانِ حالتِ UI آن است.

## وضعیتِ طرح

تنها وضعیتی که *ذخیره* می‌شود نه اینکه محاسبه شود — «آیا هنوز کسی اهمیت می‌دهد؟» را نمی‌شود از روی فایل‌ها خواند. سه‌تای آخر **پایانی**اند، که اپ آن‌ها را **closed** می‌نامد.

| واژه | یعنی چه | چه کنید |
|---|---|---|
| `active` | کارِ زنده. طرح توجه می‌خواهد: فازهای آماده، بوت‌پرامپت‌ها، هشدارها، اعلان‌ها. | هر چه تابلو می‌گوید، همان سوار می‌شود. |
| `approved` | تأیید شده، شروع نشده. | وقتی یک لِین آزاد شد شروعش کنید. |
| `proposal` | پیش‌نویس شده، تأیید نشده. | درباره‌اش تصمیم بگیرید. |
| `backlog` | عمداً پارک شده، با قصدِ بازگشت. | هنوز هیچ — عمداً منتظر است. |
| `complete` | همه‌ی فازها فرود آمده‌اند و کار تمام شده. | هیچ — دیگر چیزی نمی‌خواهد. |
| `abandoned` | رها شده. تمام نخواهد شد، و این یک تصمیم است، نه یک شکست. | هیچ. اگر برگشت دوباره بازش کنید. |
| `superseded` | با طرحی دیگر جایگزین شده. دلیل، جانشین را نام می‌برد. | طرحی را که جایش آمده دنبال کنید. |

طرحِ بسته **ساکت می‌شود بی‌آنکه برود**: نه فازِ آماده، نه بوت‌پرامپت، نه اعلان، و از همه‌ی جمع‌های سبد بیرون می‌رود. تابلویش هنوز رندر می‌شود، جست‌وجو هنوز پیدایش می‌کند، و آسیبِ ساختاریِ واقعی هنوز گزارش می‌شود. از <span dir="ltr">**⋯ ▸ Close plan**</span> ببندید یا دوباره باز کنید — بازکردنِ دوباره همیشه ممکن است، پس بستن تصمیمی ارزان و برگشت‌پذیر است.

## وضعیتِ اجرا

| واژه | خوانده می‌شود | یعنی چه | چه کنید |
|---|---|---|---|
| `running` | Running | اتوپایلوت می‌راند: نشست‌ها خودشان راه می‌افتند، راستی‌آزمایی می‌کنند و هندآف می‌دهند. | هیچ — تب‌های فاز را تماشا کنید. Pause، Freeze و Stop همگی قابل‌اعمال‌اند. |
| `pausing` | Waiting | یک مکث مسلح شده: هر چه در حال اجراست تمام می‌شود، و هیچ‌چیزِ تازه‌ای سوار نمی‌شود. | منتظرِ مرز بمانید، یا برای ادامه Cancel pause بزنید. |
| `paused` | Waiting | به درخواستِ شما میانِ فازها متوقف شده؛ هیچ‌چیز اجرا نمی‌شود. | وقتی آماده بودید Continue را بزنید — دقیقاً از همان جایی که ماند ادامه می‌دهد. |
| `waiting` | Waiting | روی یک ساعت خوابیده: بازشدنِ دوباره‌ی پنجره‌ی مصرفِ یک حساب، یک انتظارِ بیرونی که یک نشست اعلام کرد، یا — تا وقتی یک کارتِ راستی‌آزمایی یا مجوز برقرار است — یک آدم، با ساعتِ اجرا روی نزدیک‌ترین انقضای کارت. کارتی که ساعتش بی‌پاسخ تمام شود فازش را به‌شکلِ `awaiting-person` پارک می‌کند. | هیچ، مگر اینکه منتظرِ شما باشد: آن‌وقت به کارت جواب بدهید. |
| `frozen` | Waiting | هر نشست همان‌جا که هست متوقف شده (وسطِ توکن)، گرم و بی‌آنکه چیزی از دست بدهد. فریز روی *یک* نشست از چندتا به‌جایش روی تبِ همان نشست ثبت می‌شود، و اجرا `running` می‌ماند. | نشستِ فریزشده را Continue کنید تا فوراً ادامه یابد، یا Stop کنید. |
| `parked` | Needs you | هر فازِ باقی‌مانده اول به یک آدم نیاز دارد — یک گیت، یک تأیید، یک تصمیم. | «Why this is stopped» را بخوانید: هر مانع با چاره‌اش نام برده شده. |
| `queued` | Queued | در صف، پشتِ طرحی دیگر که همان مخزن‌ها را در دست دارد؛ وقتی scope آزاد شد خودش شروع می‌شود. | هیچ — نگه‌دارنده روی chipِ queued نام برده شده. |
| `halting` | Needs you | یک halt ثبت شد؛ نشست‌های زنده پیش از توقفِ کاملِ اجرا دارند تمام می‌شوند. | کارتِ halt را بخوانید. اجرا وقتی آخرین نشست تسویه شد halted خوانده می‌شود. |
| `halted` | Needs you | روی چیزی متوقف شد که نباید خودکار از آن عبور کرد — معمولاً یک راستی‌آزماییِ قرمز. | روی کارتِ halt «Finish in its own session» یا «Fix with a new agent»، یا خودتان علت را درست کنید و فاز را Retry کنید. |
| `stopping` | Waiting | توقف درخواست شد؛ نشست‌ها دارند جمع می‌شوند. | یک لحظه صبر کنید. |
| `finished` | Done | چیزی برای اجرا روی این طرح نمانده. | هیچ. |
| `interrupted` | Needs you | هیچ‌چیز آن را نمی‌راند و هیچ‌چیز دلیلش را ثبت نکرده — یک کنسول یا نشست وسطِ کار مرد. | Resume with AI، یا Continue را بزنید — کارِ موجود روی دیسک حفظ می‌شود. |

## رکوردِ فاز

ستونِ «This run»: آنچه *در این اجرا* بر سرِ یک فاز آمد، در برابرِ آنچه روی دیسک درباره‌اش درست است.

| واژه | خوانده می‌شود | یعنی چه | چه کنید |
|---|---|---|---|
| `pending` | Queued | این اجرا هنوز فاز را شروع نکرده. | هیچ — حلقه وقتی وابستگی‌هایش انجام شد به آن می‌رسد. |
| `gated` | Needs you | پشتِ گیتِ طرح نگه داشته شده — شرطی انسانی یا خودکار که اجرا خودش نمی‌تواند رفعش کند (گیت‌های ai هرگز پارک نمی‌کنند: نشستشان برای رفعشان سوار می‌شود). | گام‌های گیت را انجام دهید و روی کارتِ Gate صفحه‌ی فاز Approve کنید (می‌تواند اجرا را در همان عمل ادامه دهد)، یا برای بررسیِ دوباره Retry کنید. |
| `running` | Running | یک نشست همین حالا روی این فاز کار می‌کند. | تبش را تماشا کنید؛ Ask در میانه‌ی کار به نشست می‌رسد. |
| `verifying` | Verifying | نشست تمام شد؛ کنسول خودش دستورهای راستی‌آزماییِ طرح را اجرا می‌کند. | هیچ — سبز آن را done علامت می‌زند، قرمز با شواهد halt می‌کند. |
| `awaiting-verification` | Needs you | بررسی‌های ماشینی پاس شدند؛ گام‌هایی مانده که فقط یک آدم می‌تواند تأیید کند. | به کارتِ راستی‌آزمایی جواب بدهید — دقیقاً فهرست می‌کند چه چیزی به چشمِ شما نیاز دارد. |
| `done` | Done | تمام‌شده و در این اجرا مستقلاً راستی‌آزمایی‌شده. | هیچ. |
| `failed` | Failed | تلاش شکست خورد — یک راستی‌آزماییِ قرمز، یا نشستی که چیزی تولید نکرد. | Why? شواهد را نشان می‌دهد؛ «Fix with a new agent» آن را تعمیر می‌کند، یا Retry اجرا را از همین‌جا دوباره شروع می‌کند. |
| `interrupted` | Needs you | نشست یا کنسول وسطِ فاز مرد — یا اپراتور همین یک نشست را از تبش متوقف کرد؛ درختِ کاری همان‌جاست که ایستاد. | Resume with AI یا Retry — شناسه‌ی نشست نگه داشته می‌شود، و کارِ کامیت‌نشده حفظ می‌شود، هرگز کورکورانه تکرار نمی‌شود. |
| `skipped` | Skipped | اپراتور آن را از فهرستِ این اجرا برداشته. | اگر هنوز باید انجام شود، بعداً Retry کنید. |
| `parked` | Needs you | پیش از آنکه حلقه دوباره به آن دست بزند به یک آدم نیاز دارد — یادداشت دقیقاً می‌گوید چرا. | یادداشت (گیت، قفلِ کسِ دیگر، تصمیم) را بخوانید، طبقِ آن عمل کنید، بعد Retry کنید. |
| `waiting` | Waiting | روی یک ساعتِ بیرونی که نشست اعلام کرد پارک شده — یک buildِ CI، یک auto-mergeِ PR، یک پنجره‌ی deploy. | هیچ — وقتی پنجره سپری شد رانر نشستِ خودِ فاز را ادامه می‌دهد. |
| `queued` | Queued | منتظرِ مخزن‌هایی است که فاز یا طرحی دیگر نگه داشته؛ وقتی آزاد شدند خودش شروع می‌شود. | هیچ — chipِ queued می‌گوید منتظرِ چیست. |

رکوردِ `failed` زیرِ فازی که **تابلو** آن را done می‌خواند یعنی: تلاشِ این اجرا متوقف شد، و کار بیرون از آن تمام و راستی‌آزمایی شد. ردیف می‌گوید «nothing to fix — done elsewhere».

## چرا یک فاز یا یک اجرا متوقف شد

هر halt یک **نوع** (kind) دارد، و نوع می‌گوید موضوعش چیست. نوعِ سطحِ فاز فقط همان یک فاز را تسویه می‌کند، و فازهایی که از قبل در صف یا در جریان‌اند جایشان را نگه می‌دارند. نوعِ سطحِ اجرا اجرا را متوقف می‌کند.

| نوع | سطح | چه رخ داد |
|---|---|---|
| `verify-failed` | فاز | §Verification اجرا شد و قرمز برگشت. |
| `no-handoff` | فاز | نشست بدونِ نوشتنِ هندآفش تمام شد. |
| `phase-blocked` | فاز | نشست اعلام کرد که مسدود شده است. |
| `waiting-external-timeout` | فاز | یک انتظارِ بیرونیِ اعلام‌شده ادامه نیافت. |
| `needs-human` | فاز | خواسته‌ای که فقط یک آدم می‌تواند تسویه‌اش کند. |
| `awaiting-person` | فاز | از یک آدم پرسیده شد — یک کارتِ راستی‌آزمایی یا مجوز — و ساعتش بی‌پاسخ تمام شد. |
| `phase-crashed` | فاز | فاز داخلِ رانر شکست خورد. |
| `verification-preflight` | فاز | §Verification فاز چیزی به رانر نداد که بتواند اجرا کند. |
| `verify-timeout` | فاز | یک دستورِ §Verification دو بار از حدِ زمانی‌اش گذشت — بار دوم با دو برابرِ حد. این شکست نیست: <span dir="ltr">`Verify timeout:`</span> فاز را بالا ببرید یا دنبال یک hang بگردید، بعد Re-check کنید. |
| `mcp-preflight` | فاز | یک سرورِ MCP که فاز لازم دارد وصل نمی‌شد. |
| `recovery-failed` | فاز | یک بازیابی کرش کرد، یا گفت چرا نتوانست تمام شود. |
| `orphaned-session` | فاز | نشستی زنده از یک کنسولِ قبلی پیدا شد که هنوز کار می‌کرد. |
| `worktree-merge` | فاز | کامیت‌های یک لِین در شاخه‌ی اجرا merge نمی‌شدند؛ هر کامیت روی شاخه‌ی لِینش باقی است. |
| `landing-conflict` | فاز | همان برخورد، که `Conflicts: park` طرح پارکش کرد (یا پس از آنکه یک نشستِ rebase دوباره تداخل کرد): فاز انجام شده، اجرا به راهش ادامه داد، و خواسته هر دو لِین و فایل‌ها را نام می‌برد. |
| `budget` | اجرا | بودجه‌ی اجرا تمام شد. |
| `plan-unreadable` · `plan-lint` | اجرا | طرح خوانده نشد، یا دیگر lint را پاس نکرد. |
| `failure-streak` | اجرا | فازهای زیادی پشتِ سرِ هم شکست خوردند. فقط فشارِ یک آدم دوباره راهش می‌اندازد. |
| `models-exhausted` | اجرا | همه‌ی مدل‌ها تمام شده‌اند یا به ظرفیت رسیده‌اند. |
| `run-preflight` | اجرا | شروع رد شد: preflightِ احراز هویت یا پیکربندی شکست خورد. |
| `runner-crashed` | اجرا | خودِ حلقه‌ی راندن exception پرتاب کرد. |
| `plan-deadlocked` | اجرا | یک رأیِ QA هر فازِ باقی‌مانده را نگه داشته؛ هیچ‌چیز آماده نیست و هیچ‌چیز در جریان نیست. |
| `nothing-ready` | اجرا | فازهایی مانده‌اند، هرکدام پشتِ یک گیت، یک خواسته، یک Retry یا قفلِ طرحی دیگر. |

## وضعیتِ تابلو

ستونِ «Status» — آنچه روی دیسک درباره‌ی یک فاز درست است، همان‌طور که `phase-graph.sh` حساب می‌کند. نشان واژه‌ی حالتِ UI را نشان می‌دهد (`ready` به‌شکلِ **Next up** خوانده می‌شود).

| حالت | خوانده می‌شود | یعنی چه | چه کنید |
|---|---|---|---|
| `done` | Done | هندآف کامل است؛ کار تمام و راستی‌آزمایی شده. | هیچ. |
| `ready` | Next up | همه‌ی وابستگی‌ها برآورده شده‌اند؛ این فاز همین حالا می‌تواند شروع شود. | شروعش کنید (یا اتوپایلوت می‌کند)، یا بوت‌پرامپتش را از صفحه‌ی فاز کپی کنید. |
| `in-progress` | Running | یک نشست همین حالا روی این فاز است. | لِینش را تماشا کنید. وقتی هندآف می‌نشیند تابلو به‌روز می‌شود. |
| `waiting` | Waiting | فازی قبلی که به آن وابسته است هنوز done نیست. | اینجا هیچ؛ چیزی را که منتظرش است تمام کنید. |
| `stuck` / `blocked` | Stuck · Blocked | هندآفش blocked علامت خورده — بخشِ Outstanding دقیقاً می‌گوید چرا. با رنگِ waiting و یک نمادِ هشدار کشیده می‌شود؛ فقط وقتی یک خواسته چیزی از شما بخواهد کهربایی می‌شود. | گزیده را در صفحه‌ی فاز بخوانید، یا از Ways forward در صفحه‌ی اجرا استفاده کنید. |
| `gated` | Gated | طرح این فاز را گیت کرده — روی یک آدم (`manual`)، بررسیِ خودِ یک نشست (`ai`)، یا یک شرطِ خودکار. | کارتِ Gate صفحه‌ی فاز گام‌ها و دکمه‌ی Approve را نشان می‌دهد؛ گیت‌های ai وقتی نشستشان سوار می‌شود خودشان رفع می‌شوند. |

## ادعا

یک ادعا یعنی یک نشست بگوید «دارم روی این فاز کار می‌کنم». در یک فایل زندگی می‌کند — `docs/handoffs/<slug>/.locks/phase-NN.lock` — که `phase-lock.sh claim` می‌نویسدش، و یک **اجاره** دارد (به‌طور پیش‌فرض ۲ ساعت؛ نشستی که کنسول می‌راند ۹۰ دقیقه ادعا می‌کند) که نگه‌دارنده تا وقتی کار می‌کند تمدیدش می‌کند. هر جدولِ فاز آن را نشان می‌دهد، چون تنها واقعیتی است که تعیین می‌کند دکمه‌های کنارش کاری می‌کنند یا نه.

| حالت | chip | یعنی چه | چه کنید |
|---|---|---|---|
| `live` | **held by …** | نشستی دیگر این فاز را ادعا کرده و اجاره‌اش تمام نشده. شروعِ نشستِ دوم اینجا رد می‌شود — هم از سوی این کنسول و هم از سوی سرور. | بگذارید تمام کند. اگر آن نشست رفته، روی ردیفِ فاز **Release the claim** را بزنید و تأیید کنید. |
| `stale` | **stale claim** | اجاره منقضی شد: هر که آن را گرفت تمدید را متوقف کرد، پس هیچ‌چیز روی این فاز کار نمی‌کند. | هیچ، مگر اینکه تابلوی مرتب بخواهید — اجرا را **مسدود نمی‌کند**. **Release it** فایل را پاک می‌کند. |

ادعای منقضی که کار را مسدود کند همان شکستی است که این تمایز برای جلوگیری از آن وجود دارد: نشستی که بدونِ آزاد کردن بمیرد، وگرنه فازش را تا پایانِ کاملِ اجاره نگه می‌داشت و بعد هم همچنان نگه می‌داشت، چون هیچ‌چیز ادعای مرده را تمدید نمی‌کند.
